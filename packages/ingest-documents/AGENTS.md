# 文档输入包规则

## 用途

`ingest-documents` 负责把 PDF、PNG、JPG、JPEG 和 WebP 变成带页码、坐标、识别方式和置信度的原始文字块，并在翻译前筛选 NPC/怪物 stat block。它不直接实现 Foundry Actor/Item 生成规则。

## 修改范围

- PDF 必须优先使用文字层和坐标重建阅读顺序；扫描页或图片才进入 OCR。每个可追溯文字块必须保留来源文件、页码、坐标、提取方法、来源语言与置信度；不得用重排后的 Markdown 覆盖这些证据。
- 候选筛选必须是确定性的、本地的，并在任何翻译或 AI Intake 调用之前完成。
- 原始 Markdown、候选清单和提取报告必须先写入独立 run 目录。换行规范化只能服务于后续解析；原始块的行序、页界和可回溯坐标不能丢失。
- 单语来源保持原语言；已有中英并列内容保持其已有的双语语义。翻译是显式、可审计的后续步骤，不得为了下游接受而强制翻译或把译文冒充来源。
- OCR、翻译和 Intake 都通过适配器/注入接口接入；单元测试默认使用 fake，不依赖网络。
- 不把文档原文件复制到 Vault，也不在本包中维护 Foundry JSON 字段映射。

## 验证

- 覆盖 PDF 页级文字顺序、并排候选、中文/英文/混排筛选、机械字段保护和服务失败状态。
- 修改后运行 `bun run typecheck:packages` 以及受影响的文档输入和 workflow focused tests。
- 提取正文、阅读顺序、候选语义或下游内容／消费行为改变时，真实 PDF/图片验收比较原页面、原始 Markdown、翻译 Markdown（若有）、标准 Markdown 和最终 Actor JSON；抽样确认语言、坐标、置信度与换行／阅读顺序仍能回溯。
- 仅报告或元数据显示改变，且有明确证据证明原始 Markdown、阅读顺序、候选语义及下游内容／消费行为未变时，核对原页与受影响的页码、坐标、语言、置信度等可追溯信息，不为该显示修改重新跑完整 Actor 链。证据不足或上述任何内容改变，继续完整来源链验收。代码测试不能替代受影响层级的语义对照。
