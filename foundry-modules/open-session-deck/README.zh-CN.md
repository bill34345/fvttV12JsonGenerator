# Open Session Deck / 开放式跑团副屏

Open Session Deck 是一个仅供 GM 使用的 Foundry VTT 队伍与遭遇操作台。它可以保留在 Foundry 主窗口内，也可以弹到第二块显示器。副屏由 GM 已登录的浏览器会话直接渲染，不加载第二个 Foundry 客户端、Canvas、登录页或模块 socket。

## 精确支持范围

- Foundry VTT `14.364` / dnd5e `5.3.3`（已完成运行时验收）
- Foundry VTT `14.368` / dnd5e `5.3.3`（既有Mirror兼容候选，实际接受见专项记录）
- Foundry VTT `14.368` / dnd5e `6.0.2`（历史静态迁移候选，尚待世界内验收）
- Foundry VTT `14.368` / dnd5e `6.0.5`（原生力竭面板切片已验，其余命令和完整GM／玩家矩阵未验）
- Foundry VTT `14.368` / dnd5e `6.0.6`（GM-only限定链已接受：TempHP自然busy/disabled、stale目标消失、玩家入口拒绝；其余GM命令、通用stale分支和完整矩阵仍未覆盖）

其他版本、交叉组合和系统会 fail-closed。Daggerheart 计划在后续版本接入，本版不声明支持。

6.0.5 与 6.0.6 的适配路径从 dnd5e 的 `dnd5eexhaustion0` Active Effect（由 `staticID` 补齐为 16 字符的 ID）读取力竭等级，并通过原生 `toggleStatusEffect` API 调整。2026-10-01 同一自有 Actor 的6.0.5面板与原生读回通过3→4→3、普通GM重载及精确清理；6.0.6进一步接受GM TempHP自然busy/disabled、stale目标消失，以及玩家入口和权限拒绝。状态编辑仅向GM开放，玩家入口拒绝已验；通用stale分支、其余GM命令和完整矩阵仍未覆盖。角色验收环境的额外消息已准确删除并确认原生缺席，作者和唯一whisper均为本轮TempPlayer，别名Dice So Nice!，Atlas归因假设已否证并符合已实装DSN6.3.1欢迎源；native terminal 的 Task 宏、原92宏行 hash、原7 User `_id` 读回、safeMLD/尺寸/viewport/UI、Core 与 Inspector 限定恢复均已闭合，但不等于旧A或完整User/所有Setting恢复。其余命令和完整GM／玩家矩阵未由本轮接受，见[限定恢复记录](../../docs/reviews/2026-10-01-next-605-custom-module-restoration.md)。

## 功能

副屏先加载模块自带的静态HTML空壳，再由当前已登录GM会话渲染同一份状态；图片和样式仍沿用主页面的相对路径基准。空壳本身没有脚本或世界连接，不会启动第二个Foundry客户端；未能完成加载时显示错误提示。

- 主 Foundry 面板与同会话浏览器副屏共享状态
- 战役记录夹界面：皮革标题、织物装订和连续纸页；紧凑名单下方使用横跨队伍与遭遇两栏的统一操作台
- 双栏模式可拖动中间分隔线调整队伍／遭遇宽度；姓名与状态始终单行显示并提供完整提示
- 由一个世界级 Actor 文件夹定义队伍，可选择包含子文件夹；临时同行 NPC 只需移入队伍文件夹
- 直接查看和编辑当前/基础最大/最大修正/有效最大/临时 HP、AC 修正、激励、力竭、状态、专注与死亡豁免
- 队伍与遭遇每行常驻复选框，可选择一个或多个 PC／NPC；适合批量的既有操作显示实际适用数量
- 点击姓名打开轻量详情浮层并保留批量目标；统一底栏替代旧左下角编辑器与 NPC 行内编辑器
- 编辑和交换小数先攻，单独或批量为缺少先攻的 NPC 私密投掷，并由 GM 控制玩家可见性
- 玩家官方 Combat Tracker 在第一轮逐步揭示友方先攻；敌对单位默认隐藏
- 显示当前遭遇、切换上一/下一回合，并在主画布定位 Token
- 直接执行数值、状态与战斗修改，工具栏“撤回”逐步恢复最近操作；结束专注不再弹出浏览器确认框
- 简体中文与英文界面

玩家先攻隐藏属于普通界面呈现，不宣称能对检查客户端文档数据的对抗性玩家保密。模块不提供独立玩家面板、行动自动化、第二张地图、AI 功能或自定义网络协议。

## 查阅帮助

Deck面板或同会话副屏工具栏的“帮助”优先定位已启用统一手册中的Deck条目；合集未安装、停用或帮助接口不可用时，打开Deck自己的只读帮助窗口。Deck可独立使用，不需要启用合集。帮助只阅读说明，不保存偏好或执行游戏操作。

本模块与统一手册都从`docs/manual.json`取得这一条说明；中央手册目录只保留来源指针。当前0.2.0增加可选`api.openHelp()`，仍逐次检查GM。H3帮助与状态的精确接受见[执行总账](../../docs/plans/2026-10-11-fvtt-suite-refactor/EXECUTION_LEDGER.md)，不扩大其他业务命令的旧接受范围。

2026-10-12在14.368/6.0.5进一步限定接受面板/同会话副屏的实际版本配对，以及真实工具栏点击在受控设置拒绝后显示原生错误通知。通知可见性来自三个实时DOM/样式/位置样本，晚读失败及未拍到通知的截图保留原边界。此次没有禁用输入，原因提示的真实UI未执行；D3的新目标HP/力竭代表链及玩家面仍待验。

## 调整两栏宽度

在主屏面板或浏览器副屏中，拖动队伍与遭遇之间的竖向分隔线即可调整宽度。数据刷新时保留当前比例；两个窗口分别调整，不写入世界设置。双击分隔线或聚焦后按 Enter 恢复默认比例；方向键微调，Shift 加方向键加快调整，Home/End 移到允许范围的两端。

默认主面板最多1360×860，两栏约55:45，并在当前浏览器内预留32像素边距。姓名和状态图标保持单行，过长姓名与过多状态以省略号收起并提供完整悬停提示。面板或副屏扣除外框后的可用宽度低于 960 CSS 像素时沿用队伍／遭遇分页，隐藏分隔线；浏览器变宽时，仍然狭窄的面板保持分页。底部操作台使用整个面板或副屏的可用宽度。右下角“当前运行环境”可展开查看实际版本、支持状态和当前场景名称。

状态名称跟随界面语言，中文界面不直接显示内部状态ID；视觉模块的内部探测标记不列作角色状态。队伍与遭遇列表的表头随内容共用列宽，滚动时保持可见；生命标题与当前／上限数值居中对齐。

## 撤回操作

主面板和同会话副屏共用当前GM页面的撤回记录，按最近操作依次撤回，批量修改算一步。记录覆盖生命、临时生命、上限和护甲修正、激励、力竭、状态、专注、死亡豁免，以及先攻、可见性和回合推进产生的原生文档变化。结束专注会恢复原效果ID、持续时间和实际依赖链；回合撤回包含原生资源恢复、到期效果、移动记录及世界时间。

撤回需要已启用的libWrapper和当前主GM页面；已启用的触发器与自定义状态模块还需提供完成等待和回合撤回联动；不满足时原有操作仍可使用，撤回按钮说明原因。记录仅保存在当前页面内存中，重新加载Foundry后清空。只恢复本次改动；同一数据后来被其他操作修改时显示冲突，保留记录。撤回失败会保留尚未完成的部分，可在解决原因后重试。掷骰聊天记录保留，任意第三方脚本、外部服务和声音等副作用不承诺可逆。视图选择、窗口操作、队伍来源与密度设置不进入撤回。

遭遇快捷操作使用独立图标：双向箭头交换先攻，人物齿轮为尚未投骰的NPC私密投先攻；中文悬停提示解释操作。每行显示／隐藏按钮无需先选中，未投骰时先攻列显示原生d20按钮，投骰后切换为可编辑数值。勾选参战者后，在底部“遭遇”组标记或取消战败，按原生规则同步参战者标记与角色覆盖效果并支持撤回；现有私密投骰／隐藏策略保持一致。

名单头像使用28×32左右的显示尺寸，姓名保持16px单行，超出显示“……”，悬停显示完整名称；常用操作按钮仍保留34px目标。头像首次读取后由2D canvas生成64×64 WebP，在当前浏览器以Blob持久缓存，重开时通过文件校验信息确认后复用；同会话两屏共用结果。后台只更新对应图片，不重建输入和弹层。不改原图或Actor路径，不占用共享PIXI原图纹理；首次冷缓存仍需读取原图，无法压缩的来源回退原显示。

名单状态默认只显示单行图标，状态列收窄并为姓名留出更多宽度，主副屏表头与数据共用列宽，悬停单个图标查看中文名称；超过宽度时以“……”收起，悬停省略处查看全部状态及死亡豁免计数。死亡豁免摘要以图标显示，状态选择菜单保留名称；适用角色的死亡豁免控制放在底部“更多数值”组。生命／临时生命、当前行动和标题不因内容长度撑高默认名单行。

队伍姓名下直接显示英雄激励有／无和力竭层数，图标与数值放在现有名单行高内；悬停显示中文说明。底部“生命”组的数值输入与“伤害”“治疗”按钮同组同排，空间不足时整组调整；默认5供伤害／治疗使用，临时生命使用右侧独立数值，点击相连的“＋临时生命”按钮应用。

## 选择生物与统一操作台

队伍与遭遇每行的复选框决定操作对象，勾一只做单体操作，勾多只做批量操作；表头复选框选择对应名单。点击姓名只打开行旁详情浮层，可查看信息、打开角色卡或定位 Token，不改变批量勾选。同一生物在两栏重复显示时仍算一个目标；没有勾选时底栏收起。

底栏分为五组：生命（伤害／治疗和独立临时生命）、状态（明确添加／移除）、资源（英雄激励、力竭、专注）、遭遇（显示／隐藏、战败／恢复）、更多数值。“更多数值”提供“护甲修正”“最大生命修正”“死亡豁免”入口，“最大生命修正”菜单内还可设置当前生命。基础生命上限、最大生命修正和护甲修正的只读值位于点击姓名打开的详情浮层；名单和详情中的生命上限显示有效上限。每项操作按实际适用对象执行并显示数量。英雄激励与死亡豁免只作用于适用的角色；力竭可作用于 PC 和 NPC，处于0级不能再减，已到系统上限不能再加。混合状态的批量对象使用明确给予／移除或开始／结束，不分别翻转各自状态。

生命、状态等 Actor 修改按 Actor UUID 去重，同一链接 Actor 不会因为多次勾选而重复扣血；未链接 NPC Token 的角色数据分别处理。遭遇操作按所选参战者逐个处理，未参战的队伍角色不计入这类操作的适用数量。每次批量修改作为一次撤回。

“已选 X 个生物”一行始终不换行，放不下的对象收进“+N”入口，点开可查看完整列表并逐个取消；数量、“清空”和“撤回”仍可使用。当前行动对象切换时自动清空全部勾选，包括从 Foundry 原生战斗追踪器切换的情况；普通生命或状态刷新保留勾选。主面板和副屏使用相同交互。

## 开发验证

行内“当前生命”按输入的绝对值设置，保留单独的临时生命；“伤害”和“治疗”按钮继续使用原生计算。新撤回已在14.368／6.0.6完成限定实机验收，包括结束专注及跨主副屏撤回；其他版本和完整多GM矩阵未覆盖。

```text
bun run test:open-session-deck
bun run build:open-session-deck
bun run typecheck:foundry-modules
```

构建和安装 hash 只能证明机械结果；真实完成还需要在精确版本的 Foundry 中使用 GM 与玩家客户端验收。
