# ServerNext House Rules 0.1.2 potion acceptance fixture

`server-next-potion-0.1.2-macro.json` is a Foundry 14.368 Macro import document. Its `command` is byte-for-byte the contents of `server-next-potion-0.1.2-macro.js`. Foundry's normal **Import Data** action updates an existing UI-created Macro and preserves that Macro's ID; the JSON does not select or modify any other Macro.

The script runs once as the active GM only on `http://127.0.0.1:30002/game`, world `cor-cotn`, Foundry 14.368 / dnd5e 6.0.2, with active House Rules 0.1.2 and its potion setting enabled. It refuses to run if an Actor with the reserved ID or prefix already exists. It creates Actor `SN-HR-POTION-012-20260924-Actor` with ID `SnHrPt012240924A` and a `flags.world.codexServerNextMigration.fixture` provenance marker, plus one embedded Consumable with the explicit House Rules healing flag and no original Activities. It calls only the public `game.fvttHouseRules.potion.configure` preview, apply, and restore API. The script checks the schema 2 original and post-apply Activity maps, verifies the restored map is empty and the snapshot flag is cleared, then leaves the Actor and Item for a separate UI reload/readback.

The script never repeats automatically and never deletes an Actor, Item, Macro, or chat record. On any failure after Actor creation, the Actor remains for inspection and exact cleanup. It reports only an Actor actually returned by this invocation's `Actor.create`; it never reacquires a pre-existing Actor from the world collection. It emits a concise PASS/FAIL result with that Actor and Item ID plus `actorMarked` as a task-owned ChatMessage when an Actor exists, and a notification in all cases. After UI readback, cleanup should target only the exact returned IDs whose provenance marker is confirmed, plus the task-owned Macro/ChatMessage created for the run.
