# FVTT Custom Conditions

fvtt-custom-conditions provides nineteen custom conditions and Injury on the exact 14.364/5.3.3, Mirror 14.368/5.3.3 and Next 14.368/6.0.5 pairs. Scoped Next evidence now includes the remaining native movement/action/attack/equipment and real parameter-manager/simple HUD interactions, with original sources restored. The candidate additionally provides positive native6 weapon writer capability and canonical system.changes; the native writer and existing-card WMP HP/Slow application plus pre-attack cancellation now have scoped real Next acceptance with exact owned-source restoration. Other versions and crossed pairs remain rejected.

The exact 14.368/6.0.6 pair has scoped acceptance for Addled and parameterized Frozen apply/toggle, actual Manager rows, ordinary client reload and foreign-effect protection. With Injury naturally enabled, native HP20→0→1 adds one stack and native short rest clears it; the public IFS bridge synchronizes the current death episode while retaining resurrection history and old injury data. Exact owned-fixture cleanup restores original world, Settings and User readback. This does not accept all nineteen-condition combinations, weapon attacks, resurrection settlement or multiple GMs. C1/C2 records condition, Injury and weapon-effect ownership, connects only to an active Trigger Engine API1, and removes only its own Injury socket listener on stop; socket stop/restart has unit coverage, not a live stop-API check. Entry points, rule parameters and persistent identities remain unchanged.

On the exact Next pair, the candidate optionally registers its Defenseless target rule in the public `ac5e.statusEffectsTables` interface of Automated Conditions 5e 14.603.2. Frozen and Shocked share that projected status. The existing engine combines advantage and disadvantage; CC does not force a final dice mode. Registration survives delayed API readiness, leaves existing entries intact, and removes only its own entries on stop. Seven scoped native target modes have been revalidated; the acceptance record retains their exact client and target scope. Other AC5e versions and disabled status automation are unverified; the adapter does not change module settings.

Injury state now belongs to `flags.fvtt-custom-conditions.injury`, with the 0–3 stack rules, death-save 19/20 extension, rest handling, manager, and Token status HUD in this module. A valid former `flags.fvtt-injury-fading-spirits.injury` state is copied to the new subtree after schema and readback checks; the original is retained. Unknown schemas, conflicting flags, and multiple prior owned effects stop migration. The optional Fading Spirits module retains resurrection rituals and exposes them from the manager when present. Injury is a runtime layered status, outside the shared nineteen-condition generator contract. Old Injury settings are imported without expanding the default managed-Actor scope. The Injury SVGs restore the user-selected Game-icons.net Bandaged original by lorc from commit `e8604d64`; [CREDITS.md](CREDITS.md) records CC BY 3.0 attribution and verified hashes. Numeric levels are shown by the status UI.

The module registers nineteen custom conditions. Parameterized instances store their formula, damage type, DC, timing, stacking policy, and end rules in `flags.fvtt-custom-conditions.condition`. Generated Item ActiveEffects are templates; applying one creates a new Actor instance so manual operation and generated monster data use the same schema.

Install both modules, then open Custom Conditions from the module settings or Token controls. GM users can apply, edit, disable, and remove conditions without changing code. Bloodied remains native to dnd5e; Drakkenheim Madness and Contamination are outside this release.

Token Action HUD now gives **all nineteen custom conditions** independent `fvtt-custom-conditions.<condition-id>` actions. In CoTN, native dnd5e `bleeding` is displayed as「失血」while this module's `fvtt-custom-conditions.bleeding` is「流血」; native `burning` is「燃烧」while the custom `fvtt-custom-conditions.burning` is「灼烧」. A GM clicking any of the five parameterized actions—Bleeding, Burning, Frozen, Jinxed, or Valor—for one unambiguous Actor opens the manager bound to that Actor with the condition preselected. The click does not apply an incomplete effect; supply the required formula, damage type, or escape DC before submitting. The other fourteen actions apply or toggle this module's flagged instances through its API. Native actions retain their original behavior. Previously flagged custom instances remain readable, and user-supplied effect names remain unchanged; legacy default custom Burning names display with current localization.

The module marks its own nineteen statuses unavailable to Foundry's native Token status HUD, whose ordinary toggle cannot validate custom instances; Token Action HUD clicks are intercepted by this module instead. A constituent status supplied only by a composite Frozen or Shocked instance can appear active, but clicking it will not silently create a separate duplicate; manage the actual source in the manager. Ambiguous targets, non-active-GM users, and multiple instances produce guidance rather than falling back to the system toggle. Existing TAH layouts may store old action IDs, so new IDs do not necessarily inherit a user's previous hide and sort preferences. Do not reset another user's layout to make one action visible.

Condition names and descriptions follow the Foundry interface language (`cn` / `zh-CN` or English fallback). Reload after changing language. Custom instances use distinct bundled SVG icons; native system statuses with the same IDs retain their native presentation and rules. The custom Dazed HUD title has no distinguishing suffix, but its status ID remains separate from another module's Dazed. Composite Frozen and Shocked descriptions spell out their constituent effects. User-supplied instance names are preserved.

The condition icons are byte-for-byte copies of the sourced SVGs. Clumsy uses Skoll's Drop Weapon and Staggered uses Lorc's Foot Trip. Creator credits, source links, license notice, and original-file SHA-256 values are included in [CREDITS.md](CREDITS.md).

When Fading Spirits is active, the manager exposes its resurrection entry through public APIs. Injury flags belong to Custom Conditions; resurrection history remains owned by Fading Spirits. Neither is copied into the nineteen-condition schema. Native player rests clear Injury only after the active GM verifies the persisted message author against the authenticated transport sender and the sender's Actor OWNER permission. Legacy message adapters remain supported when no canonical author is available.

Build and test with `bun run build:custom-conditions`, `bun run test:custom-conditions`, and `bun run typecheck:foundry-modules`.

Bleeding and Burning select the strongest formula globally per Actor and condition, including different origins and Burning damage types. Compare deterministic expected values; ties retain the existing instance. Both default to turn end. Generated parameters come from the source feature, not CR or the attack's immediate damage.

Custom Dazed lets a creature choose one of voluntary movement, an Action, or a Bonus Action on its own turn; using one category prevents the other two for that turn. Shocked inherits this rule through Dazed. Neither status additionally prohibits Reactions. Shocked still requires an Action to pick up, draw, or stow an item, so choosing movement or a Bonus Action prevents that item interaction in the same turn. An attack temporarily reserves its chosen category on this client while its roll completes; an abnormal failure or a later hook veto may conservatively block other categories until the next turn. Concurrent control of the same Actor from multiple clients and two overlapping non-attack activity dialogs are not yet guaranteed to be strictly exclusive. This three-way choice is the user's project-specific rule change, not a claim about the final Drakkenheim text; see [the change record](../../docs/reviews/2026-09-24-dazed-three-choice-rule.md).

Immobilized and Frozen block voluntary dragging and keyboard movement, including non-GM position edits through the Token HUD or configuration. GM coordinate edits and API-driven forced movement remain available for adjudication and do not consume Dazed's movement choice.

Frozen's special critical-hit rule applies to a hit with a **weapon that deals bludgeoning damage**, not every bludgeoning source. Shocked is localized as `震愕` and is not limited to lightning damage. Valor adds its formula roll to an attack roll or saving throw, while Jinxed subtracts; Weakened halves the total weapon-attack or spell damage, rounding down when applied to HP. Staggered limits the creature to one weapon or unarmed attack on its turn. Including unarmed attacks is an explicit project extension beyond the publicly checkable Drakkenheim Beta wording. The final Appendix C text has not been fully checked; see [the wording review](../../docs/reviews/2026-09-23-drakkenheim-condition-wording.md).

## Undo integration

The awaitIdle and combatRewind API capabilities support Deck undo. whenIdle() drains condition, Injury and weapon-effect queues, including automatic Injury projection restoration. Combat rewind reconciles the relevant in-memory deduplication and reloads action state from restored documents while retaining persisted completed checkpoints. Normal rules remain active; projection restoration uses the existing injuryProjection maintenance context.
