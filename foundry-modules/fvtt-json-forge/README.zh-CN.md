## 默认检查：结构与转换、保存保真（2026-10-25）

AI负责理解原文并给出生物及关联召唤物的结构化数据。程序默认检查字段类型、支持的操作组合、唯一引用、来源身份，以及IR到Markdown、Actor JSON和实际保存结果是否发生丢失或改动。程序不再用原文句式、数字正则或覆盖率账本重新判断AI是否理解正确，也不从原文补写或覆盖数据。

本体和关联召唤物复用完整AI结构化结果入口。使用次数、条件、状态和法术授予由AI明确提供；普通特性的完整正文保留供GM阅读，显式条件／替代伤害使用独立GM按钮，不重复消耗主操作。配套配置由AI选择闭集能力与参数，工具检查引用和投影后安全编译，AI不能提交任意脚本或Foundry路径。未声明的机制不会由程序推断成额外宏需求。

AI已明确给出全手动法术条目时，省略的空usageGroups列表只整理为[]，不推断授予或次数，也不删除AI自己的不确定。

AI自己声明的不确定、结构错误、转换或保存差异仍具体显示。来源hash、精确引文位置、目标版本、GM权限及创建归属检查继续生效。需要内容复核时可主动使用“AI审核当前候选”或由GM对照原文；默认程序检查通过只说明结构和数据传递通过。旧来源语义检查仅保留显式离线SourceAudit入口，不在默认生成链运行。历史回复与检查记录不改写，已有Actor也不自动迁移。

## 2024光环与球状的范围类型

按CHM的2024术语，正文明确的光环 Emanation使用dnd5e原生`radius`，球状 Sphere使用`sphere`。中文“30尺光环”“5尺 光环”及术语前后的换行按同一口径处理；“半径20尺……球状区域”仍为`sphere`。两者在地图上都画圆，但光环放置预览会按悬停Token的体型调整范围。不要仅凭能力名称包含Aura、灵光或光环判断类型，“半径”单独出现也不能证明光环。

工具保留初始AI结构化结果。旧式sphere字段的同一条AI规则／范围引文若唯一明确写出相同距离的Emanation或光环，原生表示映射为radius；不改距离、伤害或其他数值，也不从原始来源补写字段。明确“源自……”或“环绕在你的周围……”时分别核对实际起点，其他生物的光环不变成自身范围。混合几何、否定区域存在或距离不符时不自动转换，仍保留核对问题。此映射不自动完成光环跟随、目标选择、回合触发或伤害结算。中文区域回归已通过，当前实机接受边界见[本批状态](../../docs/plans/2026-10-20-forge-ab-current-state.md)。

## 定时伤害、后续检定与来源提示

独立的回合／事件伤害保留完整条件，由GM主动使用伤害按钮。一个能力还包含后续定时伤害或条件豁免时，AI应分别提取这些基本操作；后续操作不会再次消费最初的动作或资源。定时伤害不并入初始豁免，也不自动跟踪吞咽、附身、回合触发或复杂状态。

这些操作与条件由AI明确声明，程序核对它们是否完整投影，不再从原文寻找“遗漏”。语言使用已有的原生键与别名映射；完整方言和其他语言说明照AI字段保留，不通过原文句式判断AI是否正确。

文字型引文误包为单字符串列表时，只在完整句唯一对应同一能力正文时拆包。这是引用格式整理，原始回复不变；空／多项列表等不符合结构的结果仍提示。该整理也用于读取同源保存草稿，不更改已存在的候选或Actor。

## 当前候选交付与自动纠错（2026-10-22）

**自动纠错默认关闭。** 在共享的“Forge · AI 连接”中，只有主动勾选“开启自动纠错（额外 API 费用）”并保存，后续生成才可为每只生物最多追加一次纠错请求。该选择保存在当前浏览器的连接设置中；旧设置缺少此项时保持关闭。纠错与工作台里的“AI审核当前候选”是独立操作，开启其中一项不会自动开启另一项。

**检查结论和候选交付分别保留。** AI 生物生成（含关联召唤物）只要已有可用 Actor 候选，就保留完整原文、模型提供的字段及原检查问题；即使结构／保真检查或主动模型审核为 `needs_review`／`failed`，或已开启的纠错没有成功，也可下载 Actor JSON。生物导入文件还可导出当前包。阅读候选、完整来源及问题提示后，GM 可明确确认创建／导入；这项选择不把检查失败改成 `accepted`，也不冒称模型审核通过。未支持的后果继续完整交由 GM，已有攻击、伤害和次数等基础能力不能因为保留候选而被删除或换成空壳。

GM 确认采用与检查通过分别记录。确认前后都可导出、读回审核文件；采用后的文件仍保留原检查问题及 GM 的本次选择，不把待核对候选改记为检查通过。

上传包中随候选保留的原具体问题，即使没有独立 AI 报告，也会直接显示在“候选中仍需核对的问题”中，保留对应能力、原因、问题代码和位置，供导出或确认导入前核对。

多生物任务会逐只显示已完成、失败和未处理状态。一只失败时，已有完整候选仍可单独查看、复制和下载Actor JSON；完整生物导入文件须等全部成员处理完毕，失败成员不会被静默删掉。取消后保留已完成项；恢复同一任务时，当前来源和候选身份通过核对的角色直接复用，已有IR继续本地处理，只对尚缺结果的成员请求模型。用户可在继续前开启自动纠错，该开关仅影响后续请求，不要求重做已完成角色。修改来源会撤下旧候选和导出入口。

一只或多只角色组成的无宏待审包也可明确请求“AI审核当前候选”。审核使用当前已生成结果和准确来源，保留已有本地问题；不会因无配套控制宏而误报来源被修改。实际模型审核失败时仍保留候选，可按界面提示重试；已完成的角色审核不重复请求。

完整JSON后出现已识别的少量多余闭合符号时，工具会在本地整理后继续校验，不改写原回复，也不增加模型请求。启用现有私有响应诊断时，可记录原回复、哈希和整理依据；不会默认把原回复写进公开审核文件。第二份JSON、尾部说明文字、正文损坏或缺失不会通过这项整理。它不会更改字段、数字或规则，也不改变自动纠错默认关闭的设置。

JSON／YAML 根本不可读取、或无法生成可用 Actor 时仍显示实际错误；旧来源或产物身份、来源 hash、目标版本与 GM 权限检查继续有效。候选下载不创建世界文档，导入不自动启动控制器。Item 入口仍要求严格 `accepted`，此策略不改变其创建契约，也不改变 CLI／Web 正式输出的推广规则。

条件伤害或0生命值后的豁免仍按完整来源分别核对，不能把“待GM处理”写成已自动实现。当前有可用候选时，相关检查问题与完整规则一并保留，供GM查看、下载并明确决定是否导入；没有对应的执行器或控制绑定时，不会因确认导入而获得自动触发能力。

## 安装

### Foundry Setup 安装

```text
https://raw.githubusercontent.com/bill34345/fvttV12JsonGenerator/master/foundry-modules/fvtt-json-forge/src/module.json
```

安装后进入目标世界的 **Manage Modules**，启用 **FVTT JSON Forge**，再刷新世界。

使用本次本地构建的 `foundry-modules/fvtt-json-forge/dist/release/fvtt-json-forge-0.5.1.zip` 和同目录 `SHA256SUMS.txt`，先核对 SHA-256；不假设尚未发布的GitHub Release已经存在。停止 Foundry 后，把 ZIP 解压为：

```text
<Foundry Data>/Data/modules/fvtt-json-forge/module.json
<Foundry Data>/Data/modules/fvtt-json-forge/scripts/index.js
...
```

ZIP 内是 module 根内容，不能再多套一层版本目录。不要覆盖身份不明的同名目录；升级前先确认旧目录确实是本模块。此仓库的运维规则不创建备份，失败时停止并核对目标。

- **AI 整理**：在独立连接设置中完成配置和连接测试，再粘贴/读取原始资料，按“分析资料→生成并审核→确认创建”推进。Actor 仍保留无需 AI 的纯文本审阅子模式。

三种输入方式保留各自草稿，不把复杂来源自动转换成简化蓝图。切换后旧候选失效，需要重新生成或审核；切换模式不写入世界。创建进入提交/回读区间时锁住导航和关闭，结束后显示完成结果并可直接打开卡片。

蓝图库保存在当前浏览器、世界与 GM scope 下。保存/重开仅恢复可编辑来源，不恢复旧 accepted response。派生变体使用新 sourceId，并记录父来源 hash 及字段差异，创建新 Actor 而不覆盖父角色。蓝图仅支持当前有界攻击与豁免组件，最多八个；不承诺完整施法、传奇、巢穴或自动 CR 平衡。

旧公开 `openForgeActor`、`openForgeItem`、`openForgeIntake` 仍可调用，分别进入同一工作台的标准生物、标准物品和 AI 整理视图。标准资料、蓝图仍走来源→workflow→parser/generation→verifier，不能手改最终 JSON 绕过验证。

AI生物生成（含关联召唤物）在有可用候选时，可查看检查问题并下载Actor JSON／导出包，再由GM明确确认创建或导入；语义校验未通过本身不再整只禁出。原始来源、模型字段与检查结论保留，GM确认不改写为AI或程序检查通过。来源或产物身份过期、权限／版本变化以及无法得到可用Actor仍阻止写入。自动执行仍需完整绑定已支持能力或明确GM伴随规则，确认候选不会补造控制器。Item保持严格accepted创建契约；历史review bundle仍只读，须按当前来源产生新候选。

## Provider 与凭据

预览已有生物导入文件不调用 Provider。人类 MD 入口由 AI 提取生物与固定能力配置，工具生成控制入口；AI 不编写宏代码。本地 Intake 默认使用 DS API 的 deepseek-flash（DeepSeek V4.1 Flash），启用可选审核时使用当前生成模型，默认低推理档；非本地连接继续保留用户明确选择。

AI 模式必须先选择 Provider、协议和精确 model ID，并完成当前连接/结构化输出测试。界面提供 OpenAI、Anthropic、Gemini、DeepSeek、xAI、Mistral、OpenRouter、Qwen、Kimi、GLM 与 Custom presets；preset 只代表连接配置，不代表每个 provider/model 都有同等语义验收。

Forge的付费模型审核默认关闭。生成、翻译、续跑、刷新和旧设置都不会自动开启审核；本地来源、数值、参数与正式生成校验继续执行。用户明确点击AI审核按钮后，才由当前生成模型复核当前候选，不重新生成、翻译或修正，也不配置第二审核模型。审核会额外消耗API费用，多生物和译文可能各有请求，不承诺整包单次HTTP。本地有效候选可完全由GM人工核对并确认导入，报告分别记录AI未审核、实际AI结果和GM批准。生成、翻译及主动连接测试本身仍可能消耗API费用。本轮状态见[显式审核记录](../../docs/plans/2026-10-11-forge-explicit-model-review.md)。

自动纠错也默认关闭，在共享连接页单独选择；旧设置或未勾选不发额外纠错请求。开启后每只生物最多一次，纠错失败保留此前可用候选及两次检查问题。普通AI Actor可用“下载 Actor JSON”保存当前候选；生物导入文件可下载各Actor JSON或导出包，再依据问题提示明确确认导入。下载不是验收通过，确认也不会抹除原失败。

当前人类 MD 样例已由 deepseek-flash 完成提取、规则选择与独立审核，生成两 Actor 和固定控制入口。来源与静态审核通过不代表场景运行通过；实际本地验收另行记录。其他组合需单独验证。

固定齐射的恍惚使用 Foundry 原生状态身份，避免状态同步模块把同一效果再补成第二份。已有其他来源的启用状态不由本控制器接管或提前结束；本控制器创建的状态按记录的目标回合到期处理。此兼容修复的实际 Chrome 复验尚未完成。

Actor 蓝图保留来源固定 HP 和生命骰公式；场上未链接 NPC Token 是否重掷 HP 遵从 dnd5e 世界设置，固定控制器不覆盖该设置。

API Key 默认只存在当前页面内存。只有显式勾选持久化时才会写入当前浏览器的 local storage；它不会进入世界 Document、Chat、review bundle、Collection/ZIP、日志或 Forge response。浏览器存储不是加密保险箱；推荐保持持久化关闭，并在结束后使用清除 Key 操作。

清除当前或全部 API Key、替换 Key 不会撤销已经通过本地校验且来源、目标和产物身份未变的人工候选；GM 仍可核对确认创建。凭据改变会撤销连接测试和旧候选的付费审核资格，改回原 Key 也不会自动恢复旧审核权限。清除全部 Key 保留当前 Provider、模型与其他非敏感连接配置。修改来源、模式、显示名、模型或目标等身份信息仍使旧候选过期。

## Review、Library 与恢复

- **Review Bundle**：导入后只显示严格解码的历史记录。历史 `accepted` 仍不可直接创建；“以当前来源开启新 attempt”会生成新的 identity、snapshot、calls 和 review。
- **Managed Source Library**：来源与安全 review 保存在当前浏览器、当前 `worldId:userId` scope 的 IndexedDB。它不写世界 settings/flags，不自动 Analyze，也不保存完整 artifact/response。
- **Portable export/import**：Library、Collection、标准 ZIP 和 Queue 都有 strict decoder、identity/hash/size/path/CRC 门禁；导出不含 Key、完整 endpoint、provider raw payload 或世界数据。

## Collection 与 Batch Queue

Forge Intake 可以导入 mixed Actor/Item Collection JSON 或标准 ZIP。每项拥有独立 source、kind/mode、identity、attempt、status 和 review；输入顺序保留，单项失败不会让其他项升级为 accepted。

Runner 固定 concurrency `1`，只在 GM 显式点击“开始／继续批量处理”后运行。刷新或关闭页面时，`running` / `applying` 会标为 `interrupted`，不会自动重发 Provider 请求。队列及 portable review 只保存安全审阅摘要；独立的本机完整候选存储按世界／GM隔离，恢复有效期7天，总额度8 MiB，包含来源、IR、正式产物和真实诊断，不保存API Key、endpoint、原HTTP回复或GM批准。普通AI单条在空白工作区展开“更多工具→批量处理”，点击“恢复上次单条候选”；普通批量重开时自动进行纯本地重验，来源、attempt、目标、当前生成器结果和问题清单均须一致，通过后仍由GM本次确认。重验不请求模型、不增加attempt。损坏、过期、目标或结果变化、额度或存储失败时保留来源与队列，可显式重新准备；AI重新准备可能产生费用且须当前有效连接。到期仅禁止恢复，不自动删除副本；可手动清理腾出额度。“清除本地恢复副本”只清除当前世界／GM的这些副本，不删除来源库、队列或世界文档。历史导出仍只读，不成为可直接创建的完整候选。

批量 Apply 使用当前页面仍持有的完整有效候选。普通 AI Actor 的可用语义待审候选可由 GM 明确采用，队列记为 `reviewed_candidate`，保留原 `needs_review`／`failed`、完整来源及问题；Item 仍要求正式 `accepted`。确认框列出正式检查结论、问题、Document ID 及 source/artifact hash，确认后重新核对当前候选和队列身份；结构／解析错误、来源／产物失配、权限及目标版本变化仍拒绝。Actor 与 Item 继续走各自 adapter 和创建读回。多 Document 操作不是原子事务，部分成功/失败会逐项报告，不会伪装为全成功或回滚已完成的其他 Document。导入历史记录时，摘要分别显示流程状态和正式检查结论，GM 采用或 `committing_and_reading_back` 不等于正式 `accepted`。

2026-10-23限定实机已验证：固定Mage待审任务整页刷新后无自动请求，显式继续产生新attempt；GM正常批量采用创建／读回，11项问题及原needs_review保留，已采用／提交中历史只读摘要正确。该证据来自当前本地Mirror14.368／dnd5e5.3.3，0真实模型调用，不推广任意来源或完整玩法。[本批记录与清理](../../docs/acceptance/2026-10-23-forge-batch-runtime.md)。

## 明确限制

基础数据与完整能力按步骤处理。静态头里明确的标准无条件抗性/免疫写入原生字段；带条件的完整子句及非原生状态名称保留为 GM 手动能力，不因此丢弃整只怪物，也不把逗号列表中的限定抗性变成无条件抗性。缺少来源、明确基础数据冲突和错误执行字段仍阻断。

复杂能力中来源明确、已核实的攻击、伤害、豁免、范围、次数与恢复可保留为原生字段，与完整 GM 规则共用一个 Item。卡片直接显示攻击加值、伤害公式、豁免属性/DC和次数；特殊附着、持续伤害、条件状态等剩余规则由 GM 按完整正文处理，不能因为这些规则复杂就把普通操作全部降成纯文字。核对来源、卡面、正常掷骰入口及效应范围即可确认这些原生操作的生成结果；命中、豁免成败和扣血结算由 Foundry／相关模块负责。本模块自己提供的状态或控制器仍须按其实际功能单独验收。

无宏的角色包审核页会明确显示无需执行宏；只有实际包含宏的包才显示代码与绑定审核提示。

来源明确“每个在自身周围若干尺内的生物”的单次豁免能力，以原生自身中心半径模板表示；半径不再误作远处施放距离。中心须绑定来源生物或明确自身称呼；目标、盟友、指定点等其他中心不猜成自身。听觉、种类排除等目标资格仍保留在完整规则中交 GM 核对。

来源共享前言明确写出的标准传奇动作预算会保留为角色原生计数器，例如两个或三个传奇动作；完整前言只保留一次。该计数不赋予手动能力自动资源消费。带条件或未知预算保留完整 GM 说明，不猜一个无条件最大值。

本地修正中文正文可以省略英文单数／复数所有格和缩写的撇号实体，例如 `fiend&#39;s`、`books&#39; allies`、`can&#39;t`；仅在来源全部撇号实体均为这种正文语法时适用。可识别的中文词间或句末孤立残留须修正后才能批准；成对引号及跨内联标签的引号不自动清理。中文显示可清理来源绑定的 Markdown 引用前缀和一至三星号强调，行内大于号、HTML、链接、数字与骰式仍核对，完整作者原文不改写。旧译文身份和原失败保留，重新批准当前修订后的草稿。

原文中的HTTP(S)来源网址原样保留，不当作漏译英文。翻译请求把完整网址作为受保护内容；草稿、保存读回和批准时仍核对同字段网址的字面值、数量和顺序。删改、增添、重复网址继续拒绝，网址旁边未翻译的英文正文也继续拦截；不按特定怪物或网站放行。Markdown链接及HTML属性仍保留结构，这项检查不新增模型请求。

原文尺寸为 Colossal 时，按已批准的显示政策使用最大原生 gargantuan（超巨型），保留完整原文及尺寸 Item，并明确提示尺寸相关规则由 GM 手动判断；这不宣布两种规则尺寸等同。中文尺寸标签也保留 Colossal 原词。其他未知尺寸不自动映射。来源有 XP 静态行时，中文显示统一为“经验值”，数字保持。正式中文仍须 GM 对照全文，不能只凭本地校验判断所有自由译文正确。

能力图标使用来源正文判断用途，GM 提示里的“移动棋子”等操作说明不参与能力分类。图标只改变 Item/Activity 的图片；近似图和低置信度项仍显示审阅边界，Actor portrait/Token art 单独处理。

### 角色、召唤物与配套宏整包导入

在 **Forge 生物 → 生物与召唤物** 提供生物及其关联对象的资料：

1. 选择`fvtt-json-forge-encounter` v1 JSON，或仅包含`encounter.json`的标准ZIP。此前普通龙兽交付ZIP、Review Bundle和Batch Collection不是这个格式。

3. 核对内容后勾选确认，再点击“一起导入角色与宏”。相同且未改变的文档会复用；同一包身份的不同内容、已有文档改变或ID冲突会阻止覆盖。

本批测试对象、控制／玩家／审计宏和116个测试消息／通知已精确清理，最后审计宏删除后独立读回九类集合：原成员、设置和视图恢复；一个旧战斗的修改时间在原生恢复路径中变化，已保留并记录，未伪造stats。原服务常驻且禁止备份。样本、原始失败与范围证据见[特殊机制接受记录](../../docs/reviews/2026-10-06-forge-special-mechanics-routing.md)，不推广为生产或全部规则组合接受。

明确的GM辅助/外部规则只在新整包路径中进入显式审核，且必须各自关联一份有正确Actor绑定的宏。严格accepted的Actor／Item创建接口保持独立；普通AI Actor另按本页候选采用规则处理。失败来源、未知诊断或缺失覆盖不能借宏包伪称正式accepted。

### 生物生成任务恢复与规则审核

生物生成任务在当前浏览器按世界和 GM 保存来源、显示名称、卡片语言及可复用草稿。请求失败、取消或刷新后，重新打开“Forge 生物 → 生物与召唤物”查看恢复提示；由 GM 显式继续。恢复不会自动联网、导入或启用控制器，API Key 仍默认只在当前页面内存中，刷新后继续调用 AI 才需重新输入。浏览器存储不可用或被清除时不能保证恢复；审核记录下载仍用于保留来源与诊断。

有 IR 草稿时使用“继续任务”，有已生成候选时使用“重新预览保存的候选”。尚未生成的输入也会保存。需要丢弃时点击“清除本地生物生成任务”，只清当前世界与 GM 的这份记录；不会清来源库、队列或连接设置。两个窗口同时操作时，旧窗口不能覆盖新进度；出现冲突提示后关闭旧窗口、重新打开当前任务，不反复保存旧页。

审核记录和已准备的生物导入文件可显式查看、复制完整 JSON。浏览器没有开始下载时，可在只读文本区核对内容并保存为对应 JSON 文件；剪贴板不可用时仍可选择文本手动复制。续翻进度变化时，已展开的报告同步更新，旧下载链接撤销；需要下载时重新生成当前记录。生物导入文件 JSON 是现有正式导入格式；复制只保存工具结果，不手改最终 Actor 数据。换源、重新生成或清除会撤销旧文本；查看和复制不请求 AI、不创建文档或执行宏。

直接上传的生物导入文件也保存翻译进度。刷新重开后先点击“重新预览保存的候选”，正式核对包、目标版本和状态目录，再按完整请求身份复用有效字段；继续翻译只请求未完成或失败字段。已经全部通过本地校验的未批准草稿，恢复并重验后可无 Key 交由 GM 人工核对批准。恢复不继承 GM 勾选或付费审核权限。

继续翻译时，同源未批准草稿会先通过原始校验，再本地整理已支持的正文撇号和排版残留；只消除经重新校验确认已解决的本地提示，不为这些显示问题重新请求模型。PDF 单次换行移到行首的孤立撇号，仅在来源语法及连续中文边界明确时处理。来源、数字或其他含义问题继续按原规则处理；标题及已批准包不自动改写。整理后更新译文身份，仍须重新人工核对批准。

续跑复用同一来源的 IR 提案，重新本地校验，不自动调用模型审核，也不继承历史 accepted 状态或GM确认。来源、目标版本或组合状态目录变化时，按界面提示重新生成；不要修改报告、指纹或最终 JSON 来强行续接。关闭窗口会取消当前请求并保留已收到的有效草稿；尚未收到完整结果的阶段仍需重做。界面显示当前生物、实际阶段及重试范围，不承诺取消后供应商已经停止计算。

### 定位问题与浏览审核项

问题面板把当前来源或译文问题对应到生物、能力或包级显示字段，列出原文、候选译文及原因，并提供继续任务、继续翻译或打开共享AI连接的入口。只有引用能唯一对应当前来源时才可定位；未知字段或归属明确提示待核，不按相似名字猜测。翻译失败时保留原语言包，已批准的同源生物译文继续复用，只修失败字段并重新核对完整候选。

审核导航汇总生物、自动规则、GM裁定与阻塞项，可按生物和处理范围筛选并定位。来源完整的GM裁定与真正阻塞问题分别显示；光照、受伤结束等完整限制仍需阅读。中文名称只复用同一生物已经批准的精确译文，并保留英文与来源引文，生物筛选名称与正式预览一致。过滤和折叠只改变显示，不改变包内容、复核结果或GM确认资格。修改来源、资料名称或卡片语言会立即撤下旧问题、预览、报告与下载入口；编辑完成后按当前任务重新生成或预览。

本轮实现与实际验收状态见[第二轮执行记录](../../docs/plans/2026-10-10-forge-phase2-review-flow.md)。CLI工具保留自身明确配置，本节单模型政策适用于Forge浏览器工作台。

直接生成中文时若翻译或含义审核失败，已通过审核的原语言候选保留并明确标注；可继续翻译，但不能把原语言包当作中文完成。恢复后的包仍须重新正式预览并由 GM 确认导入，首次启用仍是另一个明确动作。

继续翻译只修正与同一来源绑定且未通过的段落，完整候选重新进行本地数值、术语与绑定校验；模型审核仍须另行点击。确定性错误保留到记录，不手改候选或最终Actor数据凑通过。中文草稿供GM核对，实际确认后生成明确GM批准记录；已有模型批准与GM批准分别保留，不伪填模型身份。原句与逐项证据始终保留原文。

审核页按能力对照原文、解析参数和自动／GM 处理范围。命中状态列出施加、期限、再次豁免、时机、可选性及成功解除的来源证据；GM 规则保留完整原文和额外限定。旧包或仅上传 ZIP 缺少逐项证据时明确显示缺失，不能把参数摘要当作来源证明。完整来源、JSON 与控制配置仍可展开核对。

来源明确由目标选择智力或感知，包括 `Intelligence or Wisdom Saving Throw: (Target’s Choice) DC …` 的反向顺序时，多操作契约在同一个原生Save保留两种属性和来源DC。GM按完整原文判断触发与后果，由目标实际选择属性；不挑一个属性代替，也不自动连锁或套永久状态。同时要求两种豁免时保留两个独立Save，后续按钮不再扣主能力次数。旧手动包不自动迁移，不完整旧IR须按原文重新提取；缺文、截断、错误引用、不同DC及其他矛盾继续阻断。来源格式与实际生成效果以本轮执行记录的分层证据为准。

引文与原始位置仍须精确对应；同一完整规则引用仅差边界空白，以及原文数字-foot/feet的连字符断行合并，可视为排版等价。不会删除任意连字符或忽略规则差异；只有来源证明的属性关系才进入对应Save。已保存输入的回归通过不代表全新生成必然成功；自动修复响应失败时可显示安全的解析阶段、结构字段路径和类型，不显示模型原值或凭据，保留诊断和原文后停止核对。

本阶段实现和限定实测记录见[恢复与审核执行记录](../../docs/plans/2026-10-10-forge-encounter-recovery.md)。

## 通用命中状态与再次豁免

本地候选使用同一条参数规则处理 dnd5e5.3.3 的全部14种普通原生状况：目盲 Blinded、魅惑 Charmed、耳聋 Deafened、恐慌 Frightened、受擒 Grappled、失能 Incapacitated、隐形 Invisible、麻痹 Paralyzed、石化 Petrified、中毒 Poisoned、倒地 Prone、束缚 Restrained、震慑 Stunned、昏迷 Unconscious。攻击确认命中后施加原文状态，持续指定分钟或轮数，目标每回合结束时再次豁免，成功只解除该来源效果。状态、属性、DC、时长以及“可以/必须豁免”从完整来源核对，不按怪物名称猜测；状态名称、识别及预览来自同一目录。

来源可以使用含义明确的中英文同义表达、不同语序和中文/英文数字，不要求整句套固定模板。AI先整理成上述已支持规则，工具再核对原文引用、状态和数值，GM核对施加对象、时机、可以/必须、成功解除及完整原文中的限制；付费AI审核仅按需按钮触发。含糊的指代、缺失的参数、否定或额外环境/解除分支不会因为“意思接近”而自动套用，应保留原文交GM处理。既有已审包继续读取，新包记录逐项原文依据与真实审核来源。此增量的历史实测见[同义句验收记录](../../docs/plans/2026-10-10-forge-lifecycle-language.md)，当前审核默认行为以显式审核记录为准。

全部14种状况的正式来源编译、投影、执行器及主控制器已获聚焦回归；具体实机样例与候选脚本身份以[执行记录](../../docs/plans/2026-10-09-forge-generic-status-lifecycle.md)为准，不将目录覆盖算作逐项实机接受。既有 Mirror14.368/dnd5e5.3.3 双样例已通过真实浏览器 AI/中文审核、导入回读、Midi14.0.11 命中/未命中、跳过/取消/失败/成功、重载及恐慌两轮到期。分钟到期由世界时间测试覆盖，验收没有推进含既有效果的世界时钟。

1. 在“生物与召唤物”读取完整原文，生成并审核。原文应明确命中后效果、持续时间、每回合末的豁免属性/DC与成功解除；缺失参数时先核来源，不能凭空补值。
2. 预览应出现“命中状态与再次豁免”，并用中文列出状态、期限和豁免参数。核对后导入，再明确启动战斗控制；仅导入不会执行规则。
3. 由当前活动 GM 使用场景中唯一的来源 Token，先标记一个目标，再正常点击原生攻击。模块核对该次消息和 AC 快照，只有命中才施加状态；未命中、取消、免疫不施加。没有明确目标时仍正常攻击，提示 GM 手动处理状态。
4. 目标回合结束后，根据来源选择是否进行再次豁免。可选豁免能跳过；确认后打开原生掷骰窗口，关闭或豁免失败时保持状态，成功时只清理本来源。不同来源独立计时；同一来源再次命中会刷新该来源期限。
5. 分钟读取 Foundry 世界时间，不是现实钟表。轮数在原战斗内按起始轮/回合位置到期；原战斗结束或删除后按保存的世界时间期限处理。停用控制器会停止自动处理，已有状态需 GM 处理或重新启用控制器。

Forge 的原生状态显示效果名称带有 `Forge`，便于在角色卡“效果”页识别。外部法术已有同名状态时，保留它的效果与期限，Forge独立保存自己的显示效果和来源声明；外部状态到期不会提前清除本来源。自动豁免和到期按来源解除；GM手工移除Forge显示效果会清除对应的Forge声明，原生HUD可能先处理外部状态。

系统附带的状况按原生工厂保留。例如昏迷、震慑、石化、麻痹的失能来自主效果；昏迷产生的倒地是系统独立后果，解除昏迷不会自动站起。Forge 的定时倒地使用独立文档身份，不能占用或误删该系统后果。力竭的层数、HUD伪状态和未配置的自定义状态需要各自准确的定义/参数，不把它们当作相似的开关状况。来源对象、视线、挣脱动作等额外机制也须符合已实现能力，否则完整保留GM步骤。

## 配置新状态并连接怪物能力

启用配套 Custom Conditions 后，生物与召唤物页显示“可连接的自定义状态”。点击“配置自定义状态”，新建一项，填写“中文 English”显示名称、说明和怪物原文中的准确中英文名称。选择已有机制并填写参数：可以组合19种已有自定义规则、14种普通原生状态，以及固定尺数的移动减速；无需写JSON、宏或效果字段。保存后回到Forge点击“刷新状态目录”。

例如配置“霜蚀 Frostbite”，原文名称分别填“霜蚀”和“Frostbite”，机制选移动速度降低10尺与笨拙。再读取怪物MD/TXT，原文写明命中后陷入Frostbite、持续1分钟、目标回合末可进行DC10体质豁免、成功解除。点击“AI 生成生物与召唤物”，核对预览中的状态名称、组合机制、时长和豁免参数，再确认导入、启动战斗控制，并正常标记目标和攻击。

状态目录保存在当前世界。Forge按稳定ID与受审定义快照连接能力；名称/别名重复或与内置状态冲突时拒绝保存。未注册名称、缺少来源参数和未支持的额外限定仍显示审阅/GM边界。定义被编辑或删除后，已有生效实例继续按原快照计时、再次豁免和解除；新施加需要重新生成并审核，不能把旧能力自动换成新含义。不同来源分别保存，解除仅清对应实例。手工在角色效果页停用或删除组合主效果，会同步处理其子效果并停止该来源的自动生命周期。

新名称、已支持机制的组合及参数变化无需每状态修改Mod代码；完全新的执行机制仍需补一次可复用实现。目录扩展、单测和精确版本实机分别记录，见[本轮进度](../../docs/plans/2026-10-10-forge-configured-conditions.md)。未知系统/模块版本、层数机制和任意脚本不因这项功能获得支持。

启用DAE14.0.12时，系统可能为状态增加额外的原生显示项；不能按效果行数判断有几个独立来源。候选会在原生独立后果确实发生时保留它，普通定时倒地仍按自身期限/豁免解除。目标只免疫倒地时，不因此撤销昏迷。需要这种联动适配但DAE版本或效果来源无法确认时，提示GM核对，保留外部效果。具体源码、回归和实机层级见[兼容记录](../../docs/reviews/2026-10-09-forge-midi-status-hit-bridge.md)。

此规则需要兼容的 Trigger Engine。当前自动命中路径限定活动 GM 的原生单目标攻击；玩家客户端攻击、多个标记目标、额外环境限定、受伤提前结束、多属性择一豁免等不在这条规则内，保留完整 GM 操作说明。普通原生攻击/伤害继续由 dnd5e 处理，AI只选择数据配置，工具生成固定入口宏。原生状态由 dnd5e 提供，本条无需新增全局自定义状态。

启用 Midi-QOL 时，候选接入精确 `14.0.11` 的已确认命中事件，并核对持久聊天卡，避免漏掉同卡攻击或重复施加。其他版本、未确认命中或其他机制替换了攻击骰时，特殊状态需 GM 核对。该桥接的[接口与接受记录](../../docs/reviews/2026-10-09-forge-midi-status-hit-bridge.md)保留首次真实失败及后续复验边界。

可使用[两只新怪物的完整练习原文](../../tests/fixtures/encounter-status-lifecycle.md)核对同一规则的目盲/恐慌、CON/WIS、DC15/13和分钟/轮变体；这是功能测试资料。

2026-10-13 候选统一跨阶段语义契约：v14 自动生成的内置原生状态标题按状态 ID 与既有目录确定，不再交给模型重新决定；自定义效果标题及 v12 行为保持。中文校验保护完整公式，允许 x/×/* 和空白等价，拒绝操作数、顺序、乘除或重复变化；已登记的范围/伤害数值用途与重甲肯定/否定条件也会核对。未知自由文本仍须 GM 对照原文，不因此扩大自动语义保证，也不请求付费审核。

保存失败输入的契约修复同时核对完整能力的 evidence 与 coverage：短引文不能单独证明规则，完整覆盖、正文和边界一致时才能合成来源事实。父能力明确指定“从以下条目选择可见的60尺内目标”这类规则时，只向来源中连续编号且完整保留的子能力传递范围和视线限制；字段值及父子引文分别核验，任意合法但不相关的引文、缺失子能力、冲突距离和保存记录中的过期结论仍阻断。充能区间、正常／远射程和法术等级区间按用途及数字顺序保护，不作为减法或除法；真实算式仍按完整有序公式检查。能力名称已保留的明确法术等级不要求模型再生成全局施法属性或法术位；来源没有提供的部分保持 GM 核对。上述变更不代表任意 PDF 的全新生成已通过。
