# ServerNext Midi local.9 manual APPLY setup

Import `server-next-local9-isdamaged-harness.json` into a new Foundry **Script Macro** with the normal Macro **Import Data** action, then run it once as the GM at `http://127.0.0.1:30002/game`. The macro itself creates no attack roll or damage card and never presses APPLY. It refuses a second fixture with the same prefix. A private ChatMessage reports `PRECHECK_PASS` and exact Actor, Scene, Token, Item, Activity, and ActiveEffect UUIDs. Do not attack unless it says `PRECHECK_PASS`.

On success, the macro views its own Scene locally, selects the target, controls the attacker, and opens the attacker's sheet. The two 1-square tokens are adjacent on the 5-foot grid. Use the owned Dagger's native **Attack** Activity through the normal UI. Record target HP and the exact effect UUID **after damage roll but before APPLY**, then press the Midi chat-card **APPLY** once and record HP/effect again. The desired local.9 behavior is HP 40 and the same active effect before APPLY, followed by HP loss and effect expiry after APPLY. A green setup readback is only fixture preparation, not gameplay acceptance.

If setup fails after document creation, the error report includes the stage and every allocated ID. Inspect those exact documents; the macro does not automatically clean them. The preflight report records the original viewed/active Scene and exact controlled/target Token UUID lists. Before cleanup, manually restore the original Scene view, controlled tokens, and targets from those lists, checking whether each token still exists. Then remove only the prefix-marked Scene and two Actors through the normal UI after checking for foreign tokens or other additions. The imported Macro and ChatMessages are separate artifacts; remove the exact imported Macro through the normal UI when no longer needed. Do not rerun while the prefix exists.

Source shape checked against the local official dnd5e `release-6.0.2` checkout at `F:\FoundryLab\reference-cache\dnd5e\6.0.2\repo` (`packs/_source/equipment24/weapons/simple-melee/dagger.yml`, `module/data/activity/attack-data.mjs`, `module/data/item/weapon.mjs`, `module/data/actor/templates/attributes.mjs`, `module/data/active-effect/base.mjs`). Foundry 14.368 stores changes in `system.changes`; its compatibility migration does not move top-level `changes` when `system.changes` already exists. The prior fixture provided a top-level change and an empty `system.changes`, causing the real setup run to fail at effect readback before Scene creation. This revision puts the additive 10-foot movement change directly in `system.changes` with the dnd5e 6 speed path and records scalar effect readback on failure. The DAE `isDamaged` flag remains the same as the prior Batch6AL runtime probe. This file is a setup fixture; the target world must still verify the prepared Activity and effect at run time.
