# 人类 Markdown、固定自动化与战斗包

## 当前Forge浏览器操作（2026-10-22）

从Foundry的“Forge · AI 连接”配置模型。**自动纠错默认关闭**，只有主动勾选“开启自动纠错（额外API费用）”并保存，后续生成才为每只生物最多追加一次纠错请求；失败后保留已有可用候选与原问题。额外AI审核是工作台中的独立按钮，不因开启纠错而自动请求，也不强制开启。

普通AI Actor与战斗包在有可用Actor候选时，保留完整原文、模型字段及原检查结论；语义检查为 `needs_review`／`failed` 或纠错失败，不再整只禁止输出。可下载各Actor JSON；战斗包还可导出当前包。GM对照来源和问题后明确确认创建／导入，原失败不改写为 `accepted`，未支持的规则不因确认而自动实现。已有攻击、伤害与次数等基础能力继续保留，不能靠删字段或空壳规则取得输出。

GM确认采用和检查通过分别记录；确认前后都可导出、读回审核文件，采用后的记录仍保留原问题和GM本次选择。

上传包随候选保留了具体问题时，即使没有独立AI报告，预览仍在“候选中仍需核对的问题”列出原原因、问题代码及位置，不只显示概括性提醒。

多生物生成中一只失败时，逐只列表仍保留已有完整候选的查看和下载入口，并明确显示失败、未处理成员。完整战斗包仍要求全部成员完成，不以删成员的方式凑成可导入包。取消或刷新恢复后，当前来源与身份核对通过的已有候选直接复用；只有尚缺的阶段需要处理。继续前可以开启自动纠错，该选择仅影响之后的请求；换源会撤销旧候选。无宏的单／多Actor待审包也支持明确请求额外AI审核，保留原本地问题，已完成的审核不重复请求。

对完整JSON之后已识别的少量多余闭合符号，本地整理不改变正文或规则，不改写原回复，不追加模型请求；启用现有私有响应诊断时可保存原文与整理依据，公开审核文件不会默认包含原回复。截断、第二份JSON、尾部说明或正文语法损坏仍报错；自动纠错默认关闭的设置保持。

无法读取JSON／YAML或无法得到可用Actor时仍显示实际错误。来源hash、产物身份、目标版本、GM权限以及固定控制器的绑定继续核对；下载不写入世界，导入也不自动启动控制器。Item仍使用严格accepted创建契约。

本节适用于Forge浏览器当前本地未发布候选；下方CLI保留自己的明确参数与输出策略，旧实验统计和按日期记录的验收保持当时结果。旧记录里的语义“阻断”不再作为浏览器禁止获取已有候选的现行规则。本轮新的界面与运行接受见[唯一当前状态](../../docs/plans/2026-10-20-forge-ab-current-state.md)，不由历史实机结果推定。

## 已有能力及历史边界

在锁定Midi14.0.11组合中，Forge导入完整来源绑定的“豁免＋伤害”活动时，会保留该活动的手动伤害按钮；使用单活动选项，不更改世界自动伤害或移除按钮设置。骰式、豁免、次数及GM规则保持，伤害按钮只掷原生伤害骰，不再使用能力或扣第二次资源，也不自动扣HP。旧卡不自动迁移；重用卡须通过当前严格读回。
未发布v14/core候选统一保留已有安全原生能力：可安全分离的操作原生执行，其余完整规则交GM；无法安全表达的完整操作明确手动，不因自动化不足阻断整只。来源遗漏、事实冲突、编造和错误原生执行仍列为真实检查问题，不改成已验证正确，也不把已有基础操作降级为空壳；可用候选继续保留。能力施法保留父Item的Recharge池及传奇费用；2024来源明确3/4巢穴账本时使用原生巢穴开关，并附来源绑定的资源控制宏，须开战前启动，刷新后按控制入口恢复，以在自身回合开始恢复而不在回合结束提前恢复。Beguile独立冷却、动态治疗/HP上限和其他复杂后果仍按完整规则由GM裁定。

输入是一份普通 Markdown：写清主生物和召唤物的完整数据、触发时机、目标、豁免、伤害以及来源没有规定的事项。不要求作者写 YAML、JSON、UUID 或 JavaScript。

## 处理分工

2026-10-21续批：共用Encounter provider可在完整结果产生前，对明确模型格式/字段/已证明数值错误使用本生物共享的最多一次纠错；仅重做失败的基础或整表阶段，与后续纠错共用额度。原始回复、失败与请求计数保留，本地不支持来源、绑定歧义、网络和取消不因此新增模型纠错。Forge mod与本目录`run-human-intake.ts`调用此provider；旧plaintext CLI不是这条入口。每日施法的明确法术选择、继承属性与次数可核验后保留完整GM动作及单一父池，不虚构Cast；装备/技能、跨行施法、独立语言选择和可见放置点按来源各自核对。支持中立近战／远程互斥双模式，已有typed归档契约保留，不能自动连打两次。只有来源证明3／巢穴4时才复用现有“在巢穴中”开关，基础值与spent保留，两种资源的恢复不混用。新来源和实机证据仍须分层，见[当前执行记录](../../docs/plans/2026-10-20-forge-ab-current-state.md)。


Forge mod 当前 V2/BW 候选把基础属性与特性分开：基础数据核验后，全部完整特性在一次请求内填写分类 YAML，再由程序按同源编号绑定并进入原有正式生成与审阅。单属性豁免的合法标量写法可机械规范化为数组；原始回复与失败仍保留，程序不把格式兼容当成内容修复。来源歧义、错误攻击分类及不能准确投影的动态规则仍明确阻断或按已验证 GM 边界处理，不增加让用户逐字段抄原句的步骤。下文 CLI 与既有固定包保留自己的流程，不能据此推断已改为 BW。候选实施和冻结首答正式链记录见[当前状态](../../docs/plans/2026-10-20-forge-ab-current-state.md)，本轮限定本地Foundry验收见下文，未新增真实模型调用。

兼容续批已核对旧 CLI 的真实消费者：它会把未知攻击默认成武器攻击，动态治疗则没有原生公式消费者；Forge 不继承这一猜测。现支持完整复合目标、紧邻同主体的目标引入、自身毒气与等价豁免减半表述。实际伤害量治疗关系可证明时沿既有完整 GM 规则保留，攻击/伤害仍可原生执行；不生成虚假 Heal 或生命上限自动化。独立阻断可合并显示。中立近战/远程现在有独立GM通用检定和命中伤害，不回填武器/法术；GM判断优势/劣势、命中与重击，原生Attack钩子不适用。来源唯一证明的自身Bloodied半伤保留完整基准骰式及显式条件调整，GM裁定半伤，伤害后续不重复扣次数。动态恢复引用可用self/自身及当前来源编号或唯一完整原文名，不建立译名词典、不借其他动作。前批Company及2014来源Vampire已通过各自正式链和本地Mirror14.368/dnd5e5.3.3/Midi14.0.11的有界导入、操作与刷新；Vampire结果仅作历史输入证据。当前规则基准为2024，多体型来源与统一GM边界已接通；同一2024 Vampire已通过完整正式来源链及Mirror14.368/dnd5e5.3.3限定实机：Bite、Charm/Beguile施法与单次资源、巢穴3/4、自身回合恢复、刷新和精确恢复均有读回；Charm来源Effect86400秒及移除通过，GM例外仍手动裁定。未发布v14/core候选支持头部明示的多个原生体型选项（如Medium or Small、三项or列表及中文选择），保留完整原文、当前合法体型和GM选择说明；不固定取首项或自动变形。当前值须属于来源集合，选项、可见说明或metadata被删改仍拒绝，正文变形和集群成员尺寸不能借证。前批2014 Vampire的传奇预算3、成本1/1/2与每日次数保留；动态治疗/生命上限、条件半伤与复合目标数量仍由GM核对，不宣称全自动。当前Midi组合须使用有效且非隐藏的目标Token。原完整冻结回复的真实遗漏和错引用继续阻断，未改原回复/评分；本轮没有新真实模型准确率、速度、费用或干预测量。见[本轮统一边界与2024验收](../../docs/acceptance/2026-10-20-forge-unified-boundaries-and-vampire-2024.md)。

完整能力可在同一个Item内提供多个独立原生操作，保留攻击、伤害、豁免、次数和真实施法。GM按完整来源判断后续豁免、条件伤害的触发前提；这些按钮不自动连锁、不重复扣除主能力次数。目标明确选择INT或WIS时保留原生二选一，不能把同时要求两种豁免改成选择。多个明确独立的共享每日法术池分别绑定，池内Cast共用次数、池间互不扣除；不明确的授予仍保留GM规则。

快速切分无法完整承接排版时，模型可选择程序提供的原文行ID和能力归属，程序重建位置与完整覆盖；未完整承接的能力再请求多操作事实。模型不能重写原文、猜位置、过滤失败能力或把明确基础操作整体降成手动说明。每项操作仍须通过同一来源的独立核对；额外执行器未支持的持续、移动、吞咽、灵魂和其他复杂后果明确交GM。候选的离线、真实模型及实机范围见[本轮执行记录](../../docs/plans/2026-10-17-forge-common-contract-restoration.md)，不将契约可表达等同任意来源首次成功。

1. AI Intake 提取每个生物的证据 IR，渲染规范 Markdown；正式 workflow 生成 Actor 并对照来源审核。
2. AI 从固定能力清单选择规则和参数，输出版本 2 的数据配置。AI 不编写宏代码，不提供任意路径、UUID 或脚本。
3. 工具校验来源引文、能力身份、参数及引用，生成固定控制入口。DC、伤害、使用次数和 HP 继续读取正式 Actor 的原生数据。
4. 本地核对配置、来源和完整伴随覆盖，同时保留检查结论与已有Actor候选。Forge浏览器提供候选下载和导出，GM可核对问题后明确确认导入；付费AI审核只在用户另按按钮时调用。CLI保持自身默认审核与输出政策。
5. GM确认后导入Actor与已有且绑定有效的控制入口，再单独启用自动化。没有配套控制的候选不获得自动执行能力。

当前执行器只支持精确 Foundry 14.364 或 14.368 / dnd5e 5.3.3 / core。V12 需要独立实现和验证，不共用当前执行脚本。

Forge 对唯一完整的生物数据块可在本地识别，保留整份来源及前后引用，省略模型发现请求；多生物、不完整或含糊布局仍走原发现流程。本地与正式校验通过、且没有配套执行要求的单 Actor，可直接生成无宏包，省略控制配置请求。说明性或尚未实现的特殊规则仍保留完整文本，由 GM 手动处理；无宏不代表全部机制自动化。

本地识别不区分常见 CR、Speed 标签的大小写。需要模型帮助定位时，程序提供已编号的原文行，模型选择范围，程序取回原文；不要求模型重抄全文或计算字符位置。旧发现结果只允许唯一的空白排版差异映射回原文，改数字、删词和重复歧义仍拒绝。属性表之前的明确背景、战术标题连同全文保留，不放宽属性表之后未知规则标题的检查。来源入口离线回归可运行 `bun run test:forge-discovery`；离线通过不等于全新资料的真实模型、完整中文和导入验收通过。

来源检查核对明确能力标题、能力声明的法术等级与引用定义完整正文，含定义的后续例外段落。漏项仍阻断，不能靠“叙述／忽略”标签放行。中文翻译在原有数值和标记保护上，保护含义明确的再次豁免时点、成功解除、失败差值，以及“仅此次伤害导致 0 HP”的条件；未知表达不自行补规则，仍须 GM 核对。这些本地步骤不新增模型请求，付费审核仍默认关闭。[本轮三来源测量](../../docs/acceptance/2026-10-11-forge-first-pass.md)分别记录首次失败与续跑结果，不保证任意模型一次通过。

明确的“Referenced definitions／引用定义／补充定义”区段中，未完整保留的定义会按来源原文附入角色传记，含后续例外；已有完整能力说明不重复附加。该来源事实整理与CLI Monster Intake共用，不增加模型请求或自动机制，仍走原有IR校验、正式生成和来源验证。没有明确边界或范围被截断时不猜归属，实际缺失继续阻断。生成中文后，GM仍须对照原文核对定义含义；付费AI审核默认关闭，CLI自身审核策略保持。

同一个英文能力名及其括号限定别名共用完整显示标题，不重复嵌套原名；GM载体绑定复用该标题，专注／充能／浴血等限定和原始正文保留。不同身份、歧义或复杂未知格式继续阻断，不通过模糊名称匹配寻找另一能力。

普通／首次失败明确施加的条件允许PDF在同一句内换行；句末、空段、否定／免疫、仅失败差值、第二次失败或未明确成功分支仍须审阅。包级正文显示已声明角色和固定配置字段的可读名称，不改原始command或参数；未知角色引用阻断，旧raw及旧规则标题显示的批准身份保持兼容。

包级说明按固定规则绑定引用对应能力标题，跨角色同名时带上角色名称，结构化规则ID保持；未知或不唯一的引用不能进入新中文草稿。原文DM在受保护的正文翻译传输中规范为GM，不放宽中文、数字或链接校验。已批准旧包按原请求身份读回，旧失败草稿按当前显示请求重新翻译受影响字段。反应／附赠动作的有效原生属性加值也按该活动的明确属性绑定核对，实际伤害或属性漂移仍阻断。后续同三来源测量与限制见[三个阻断修复记录](../../docs/acceptance/2026-10-12-forge-three-blockers.md)；付费审核仍须另按按钮，CLI独立审核策略不变。

v14的原生反应／附赠攻击若具有明确长射程与原生属性伤害，采用武器载体保留射程字段，仍用原激活类型和分区。严格原生读回继续核对长射程，不能把字段丢失当成已通过。此兼容修复不增加攻击触发、自动命中或其他GM裁定机制。

## 已实现的固定能力

| 能力 | 范围 |
| --- | --- |
| 豁免能力结算后召唤 | 成功失败均召唤 1 个已绑定生物，GM 选择目标旁合法空位，独立 Token/HP 并加入先攻；可有失败恍惚及半血后续腐化 |
| 自身回合开始范围能力 | 按原生 save/damage 执行；每回合一次，来源 HP 为零停止，生成瞬间不执行，不按敌友筛选 |
| 腐化分支 | 首次失败加来源定义的共同腐化标记；已有标记再次失败加 1 级力竭，两者互斥 |
| 阈值守护 | 同次伤害类型合计，严格超过阈值才减半取整；碎裂不减，削弱时减熟练加值 |
| 守护碎裂 | 原生能力消耗后碎裂，下一次自身回合开始恢复；次数耗尽后恢复为削弱形态 |
| 自身回合传奇资源恢复 | 只在来源明确规定的自身回合开始恢复已配置资源池 |
| 豁免失败状态与期限（0.5.1候选） | 有来源引文及唯一原生Save Activity：Blinded／来源下回合开始，Slowed／目标下回合结束，Paralyzed／来源下回合结束或实际受伤，失败差值至少5时STR／DEX d20劣势／恢复任意HP；Slowed复用CC Slowed，STR／DEX劣势复用Enfeebled＋Clumsy |
| GM能力可用性控制（0.5.1候选） | 来源Eyestalks限定Bloodied与重击，由GM在面板选择Glacial／Paroxysm光线禁用，Activity使用前真实阻止；仅GM明确恢复，不自动推定恢复规则 |

这是有界能力清单，不承诺任意召唤、任意状态分支都能自动实现。不支持的请求须明确保留为待实现/GM处理，不能靠 AI 现场编程补齐。写法示例也不等于所有示例已通过自动化验收。

候选效果生命周期只管理自己来源的实例／声明；多个来源需分别保留期限，GM删除自有状态不应自动复活。范围豁免由GM选择合法区域及全部目标，一次使用后逐目标结算。实际HP治疗与临时HP获得不同，Paralyzed的受伤解除包括临时HP吸收及0HP时实际正伤害，取消／免疫归零不算受伤。这些边界需要按候选在真实世界验收，当前代码支持声明不代替运行接受。

Eye of the Deep首批覆盖Gaze、Glacial、Paroxysm、Rend和GM眼梗选择。Magic Resistance只对魔法来源，Purge只结束一个作用于Eye的法术／条件且后续是下一次攻击窗口，Mirage另有专注与终止规则；它们仍保留GM步骤，不能宣称已全自动。人类MD AI入口现支持1至6种生物，单只怪物也能携带经过来源审核的GM裁定规则。早期Eye的人工参数样本仍不是AI整链验收；新的真实AI配置及独立审阅须另记实际来源、哈希和接受层级。

GM能力可用性控制现在接受1至20项不同的原生Save Item。目标名称必须由特性直接点名，或属于同一来源中连续编号的眼射线列表；不接受任意同名世界物品。仍由GM确认Bloodied／实际重击、选择禁用和明确恢复。

新增`gm-manual: {}`用于来源完整的GM裁定。普通攻击、豁免和伤害继续保留，特殊状态、阶段、期限、唤醒、禁止治疗、位移、反魔法及死亡附加判断明确交由GM；对应Item不附加声称自动执行的状态模板。控制面板的“GM查看规则”只打开绑定的原生Item，不执行效果或扣资源。每个裁定及条件标记仍须与唯一配套控制入口绑定，单Actor普通导入门禁不因这一整包审核能力改变。

普通英文 `FAILURE:` 后仅有推离的 Save，可在完整精确能力引文与单属性/DC 一致时进入 GM 准备；最终仍须同一能力的 `gm-manual` 完整引文和唯一控制入口绑定。原生 Save 保留，推离固定/掷骰距离及远离来源方向只作为文字规则，不执行 Token 移动。缺文、不同 DC/属性、否定、失败差值、成功分支或额外前提不通过这一有界衔接。

完整规则正文可作为精确引文，标题/编号不是必需机制。配套模型改收完整原文与紧凑原生事实，使用工具提供的能力引用返回选择和必要参数；工具扩展回既有完整配置，再运行原来源编译和准备门禁。旧 v2 提案仍按原契约检查，持久包/固定宏格式不变。只有来源已证明的普通推离是唯一配套需求、其余来源和原生数据均通过时，单 Actor 可由工具编译 GM 配置而不请求配置模型；施法、资源、阶段效果、潜在自动触发或未解决内容不会走该省请求路径。无论配置来源，GM 确认和正式导入仍必需。编译拒绝含安全诊断路径，并提供可选的有界脱敏提案回调用于本地验收；不记录请求头、凭据或服务响应信封。

说明性特性按目标官方系统的执行范围处理。Multiattack、Magic Resistance等官方仅提供规则说明／utility而没有效果的能力，保留完整来源和正常原生操作，不要求新增自动效果或将其列为待实现缺陷。其他复杂裁定默认由GM按原文处理；只有明确承诺的原生／固定执行能力才进入自动化行为验收。分类、活动和次数资源正确仍是来源核对要求。

## Foundry 操作

在模块设置的“Forge · AI 连接”中配置并测试连接，再从角色目录“Forge 生物”工作台打开战斗包，读取原始 MD。普通“生物一：名称”“生物二：名称”标题可直接分段；其他布局由 AI 识别。支持 1 至 6 种生物、最多 24000 字符。

工作台右上角“图解手册”内置单只 Grandmother Sea Hag 示例，提供离线 HTML／PDF、原始 MD 与已审包下载。PDF 先通过[文档输入](../../docs/document-input-workflow.md)提取并核对完整怪物及引用定义，再把 MD/TXT 交给 Forge；Forge 文件入口本身不直接读取 PDF。选择“中文正文 · 中文标题保留英文对照”才执行中文生成，已有中文包的预览不会重新调用 AI。六页图解使用原 PDF 页、实拍界面与红框，并附下一只怪物的流程图；特殊规则仍须按预览中的 GM 裁定说明处理。

FVTT 页面使用当前 Forge 连接设置中的 Provider 和模型，不因本地地址强制替换。API Key 默认只在当前页面内存中共享，关闭设置窗口仍可使用；刷新后需重输，持久化需明确勾选。不会把其他 Provider 的 Key 转送给 DS，也不再提供本机 Luna OAuth 桥接快捷入口。浏览器验收执行角色遵当前项目配置，与 Intake 所调用的模型分开。

Forge的付费模型审核默认关闭。生成、翻译、续跑、刷新和旧设置都不会自动开启审核；本地来源、数值、参数与正式生成校验继续执行。用户明确点击AI审核按钮后，才由当前生成模型复核当前候选，不重新生成、翻译或修正，也不配置第二审核模型。审核会额外消耗API费用，多生物和译文可能各有请求，不承诺整包单次HTTP。本地有效候选可完全由GM人工核对并确认导入，报告分别记录AI未审核、实际AI结果和GM批准。生成、翻译及主动连接测试本身仍可能消耗API费用。本轮状态见[显式审核记录](../../docs/plans/2026-10-11-forge-explicit-model-review.md)。本页CLI保留自身明确配置与默认审核政策。

自动纠错在共享连接页单独选择，默认关闭；旧设置缺项同样关闭。开启后只重做需要修正的阶段，每只生物最多一次额外请求，纠错失败也不清除之前的可用候选。在战斗包预览使用各Actor的JSON下载或导出当前包，完整来源、模型字段及原检查问题继续保留；GM确认不改变程序或模型的真实结论。

新增自定义状态时，先在Custom Conditions的“配置组合状态”表单填写名称、原文别名及已有机制/参数，再到Forge战斗包页刷新状态目录。Forge会把已保存的定义快照交给来源识别，按稳定ID连接“命中→持续时间→目标回合末再次豁免→成功解除”。19种已有自定义机制、14种普通原生状态和固定移动减速可配置组合，无需每状态编写宏或修改Mod代码。当前界面是世界目录的正式入口；CLI不自动读取Foundry世界设置。定义改变后新施加需重新生成审核，已有实例保留原快照；未注册名称、缺失来源参数和未知新机制不猜测自动化。完整步骤见[模块说明](../../foundry-modules/fvtt-json-forge/README.zh-CN.md#配置新状态并连接怪物能力)。

本地候选支持来源明确的“命中施加原生状态 → 持续分钟/轮 → 目标回合末再次豁免 → 成功解除”数据配置。预览显示“命中状态与再次豁免”及中文摘要；活动GM须启用控制器、标记一个目标并正常攻击。dnd5e5.3.3全部14种普通原生状况共用实现，包括束缚、受擒、震慑、魅惑、失能、昏迷等；DC/属性/时长均核原文。力竭层数、HUD伪状态、未知自定义定义或未支持限定保留GM裁定，不替代成相似效果。实例来源分别计时，成功解除和到期只清本来源，系统产生的独立倒地后果也保留。分钟按世界时间，轮数按原战斗锚点；战斗结束后按保存的时间期限处理。完整状态目录、操作及分层证据见[模块说明](../../foundry-modules/fvtt-json-forge/README.zh-CN.md#通用命中状态与再次豁免)。

新候选接受含义明确的中英文同义说法与不同语序：AI先规范化为固定规则，工具核逐项原文证据与参数，再由GM核对完整含义；付费AI审核仅按需按钮触发，不要求整句匹配模板。状态仍须属于原生目录或已注册组合定义；额外条件、不明确指代、缺失参数及未实现机制保留GM裁定。新来源的审核记录保留逐项依据，旧包兼容读取；代码检查和实际不同说法的接受情况分别记录在[执行记录](../../docs/plans/2026-10-10-forge-lifecycle-language.md)。

生成后核对生物数据、固定能力、参数、绑定与 GM 裁决项，再确认导入。生成的薄宏只调用模块的固定执行器。初次明确启用后，配置保存在模块自有 flags 中；刷新世界时重新校验身份与配置后恢复，不执行 flags 中的任意代码。

原生独立后果与主状态分别保留，例如解除昏迷不会自动站起。DAE14.0.12可能增加原生显示项，候选按规则来源处理其关联，不能按效果行数判断独立来源；仅免疫倒地不影响昏迷本身。需要适配而无法确认版本/效果来源时仍由GM核对，不覆盖外部效果。

关闭控制面板不会停用自动化；使用“停用自动化”按钮可持久停用。旧式专用宏属于另一条显式审核路径，仍需手动重新启动，不具有固定配置恢复语义。

## 失败续跑、刷新恢复与规则核对

战斗包界面按当前浏览器／世界／GM 保存任务来源与可复用草稿。生成中断后重新打开同一入口，核对来源、卡片语言和恢复提示，再显式继续；不会因打开窗口自动调用 AI、创建世界文档或启动控制器。Key 默认只在页面内存，刷新后继续调用 AI 才需重新输入；本地恢复记录不保存 Key、服务地址或原始 Provider 响应。清除浏览器数据或存储失败会影响恢复，重要来源与诊断仍应下载保留。

尚未点生成的输入也会保存。有 IR 时点“继续任务”，保存过已生成的包时点“重新预览保存的候选”。“清除本地战斗包任务”只清当前世界／GM 的这份记录；来源库、队列与连接设置保留。多窗口冲突时保留较新的记录，旧窗口应关闭后重开，不覆盖新进度。

来源审核记录和已准备的战斗包可通过显式查看／复制入口读取完整 JSON。下载未开始时，在只读文本区核对后保存对应 JSON；剪贴板不可用也可以手动选择文本。报告内容与原下载一致，战斗包 JSON 可直接使用现有正式预览入口，不必先转 ZIP；查看／复制不联网、不导入或运行宏。换源、重新生成、清除或关闭会撤销旧文本。只保存工具已生成的数据，不手工修补 Actor JSON 来绕过来源审核。

浏览器续跑只复用同源IR提案并重新本地验证，模型审核保持未请求；CLI继续使用自身fresh-validation-and-review政策，不把历史通过记录变成当前许可。来源、目标版本或组合状态目录改变时按提示重新生成；未收到完整输出的阶段不能凭部分流式内容恢复。进度提示区分当前生物、生成／审核／翻译及实际重试，说明哪些工作需要重做。

中文生成失败时，原语言候选与当前草稿保留。直接上传的战斗包也保存翻译进度：刷新重开后先点击“重新预览保存的候选”，正式核对包、目标版本和状态目录，再按完整请求身份复用有效字段；继续翻译只请求未完成或失败字段。已经全部通过本地校验的未批准草稿，恢复并重验后可无 Key 交由 GM 人工核对批准。恢复包仍需正式预览、GM 确认导入和单独启用，不自动恢复勾选或付费审核权限。续翻时已展开报告同步最新进度，旧下载链接撤销；重新下载取得当前记录。

翻译续接只修正同来源下未通过的段落，并对完整候选重新进行本地数值、术语与来源绑定校验，不自动调用模型审核。中文草稿供GM人工核对，实际确认后以明确GM批准记录重走正式workflow；也可主动点击AI审核，只审现有译文。数字／术语错误及原稿保留，不手改最终数据绕过检查。GM批准与模型批准分别记录，来源引文仍按原文展示。

复用同源未批准草稿前，先校验原稿，再本地整理已支持的正文撇号和排版残留；已明确解决的本地提示不再触发重译。来源或数字错误不能借清理放行，独立的含义问题仍保留。PDF 换行后的孤立撇号只在连续中文及来源语法边界明确时整理；标题、真实引号、英文姓名与已批准包保持原规则。修订结果仍是需要重新人工确认的草稿。

数据表前的叙述标题按位置保留；未知机械章节仍拒绝。本地来源失败保留代码和位置，不归为未发生的模型回信错误。中文段落中已检测到的生物／物体／建筑类别矛盾须先在正文修订中纠正，草稿可保存但不能批准，也不为这类已知矛盾付费审核；该检查不代替完整人工译义核对。来源为英文所有格的撇号和中文显示中的字面 Markdown 可在保留真实引号、链接、数字及标记的边界内清理，完整作者原文和原失败稿另行保留。

所有格处理包含复数名词后的撇号。来源全部撇号均属正文语法时，可识别的中文词间及句末孤立残留须先修订再批准；真实引号、跨内联标签的成对引号和英文姓名保留。Markdown 清理限于中文显示的标题、引用前缀及强调标记，行内大于号仍保护；不改完整作者原文。

确认导入前逐条看规则审核卡片：对照原文与归一化参数，核对目标、期限、豁免、可选性和解除；查看自动执行范围，以及光照、受伤结束等仍需 GM 处理的完整限定。仅上传 ZIP 或旧报告没有逐项引文时会注明缺失，参数摘要不能替代来源证明。中英文显示只改变语言，不扩大已实现机制。

操作和实测边界见[本阶段执行记录](../../docs/plans/2026-10-10-forge-encounter-recovery.md)。CLI 的 `--resume-draft` 继续独立可用，不能把 CLI 恢复记录称作浏览器操作。

## 问题定位与审核导航

问题面板展示当前失败所属的生物、能力或包级字段，保留原文、候选译文和原因。按问题提供的动作打开连接设置、继续同源任务或继续翻译；来源引用能唯一定位时才可跳转，不认识的字段ID明确待核。两只生物已批准而包级文本未通过时，先处理包字段，不必重做已批准的同源译文。

审核导航按生物、自动规则、GM裁定和阻塞项组织内容，可筛选并定位相关卡片。完整GM裁定不等同于生成失败；仍需核对限定和操作范围。中文标题只复用同生物已批准译文，原英文与引文保留，生物筛选名称与正式预览一致。筛选不改变报告、包hash或导入资格。修改来源、资料名称或卡片语言会立即撤下旧问题、预览、报告与下载入口；编辑完成后按当前任务重新生成或预览。刷新后的候选仍需正式重预览和GM确认。第二轮状态见[执行记录](../../docs/plans/2026-10-10-forge-phase2-review-flow.md)。

## 本地命令行

默认使用 DS Flash。凭据由父进程的 `DEEPSEEK_API_KEY` 或本机已配置的 `FVTT_LOCAL_DS_KEY_FILE` 提供；后者只指向外部已有秘密文件，程序在内存读取，不复制到仓库、报告或世界。

```powershell
bun run tools/forge-encounter/run-human-intake.ts docs/examples/晶血龙兽与月石晶体-人类写法.md ./crystalbleed-ds-run
```

输出目录必须是新的目录。只有整包达到 `ready_for_gm_review` 才写入各 Actor 的 MD/JSON 和 `encounter.forge-encounter.zip`；未通过只保留审核诊断，退出码为 1。每个 DS 阶段最多 5 分钟，不使用持续等待策略或自动退回 Luna。

可用 `--resume-draft <review.json>` 读取同一来源的 IR 提案，重新验证和审阅；不会继承历史通过状态。`--review-feedback <feedback.json>` 只传递绑定来源与父报告 hash 的具体修正意见，由 AI 修正 IR，不手工编辑最终 JSON。`--configured-provider` 仅用于明确选择其他已配置 HTTPS 服务的场景。

已有 `build-example.ts` 只打包预先整理的来源与专用脚本，不能替代本页的人类 MD → 真实 DS → 固定能力配置验收。

预先整理的晶血样本采用受审核的专用宏路径，导入后仍需 GM 单独启动，刷新后重新启动。样本运行时 2.1.2 读取正式 Actor 中的恍惚效果和自定义条件标记；启用 Custom Conditions 时应用该模块的独立恍惚状态，遵守恍惚免疫并在目标下一个回合结束时到期。未启用时保留来源命名与期限，行动限制由 GM 裁定。样本宏与固定能力配置分别验收；候选修复和静态回归不能代替真实导入与状态结算证据。

## 验收边界

静态测试、来源审核、整包导入与真实回合行为分别记录。运行 server-mirror 前核对实例身份；Chrome执行角色、权限与回传按当前项目约定，完成后返回报告，不持续监听或轮询。

## 中文卡片与术语核对

战斗包的“卡片语言”默认保留来源语言；选择中文正文会在来源生成及本地规则核验后增加翻译，默认不请求模型含义审核。已有原语言包也可先预览再主动翻译。中文草稿需GM实际核对确认，才能以GM批准记录正式生成中文包；AI审核是独立可选按钮，只审当前候选，不重译。使用当前AI连接；普通预览与原语言生成不额外调用翻译服务。CLI翻译仍按自己的默认审核政策运行。

当前本地候选的 Forge v14 战斗包中文草稿采用 `zh-CN-facts-v1`：已支持的机械规则由生成 Actor 时实际使用的同一份归一化事实生成固定中文。模型只翻译名称、叙事及明确待 GM 核对的剩余正文。审核页显示完整来源、完整合成中文和只读固定块；GM 仍须检查未支持的限制及手动处理范围。不能原生执行的结果继续标为 GM 辅助，不把条件或替代伤害并入无条件伤害。

完整覆盖单元与能力正文、相邻边界和精确引文一致时，这份完整规则同时传给事实恢复、紧凑配置请求和编译器；短parent引文不能单独证明全部规则。HTML标签只作为显示包装处理，缺文、错能力、伪造coverage和冲突仍拒绝。普通失败伤害／成功减半只在完整来源无额外前提时归一化；“本次伤害降至0生命值后才豁免”的攻击保留原生攻击，后续豁免及失败效果交GM，不在普通命中时自动施加。条件／替代伤害保留原文和结构化事实，不能作为无条件原生伤害。

完整保留的条件伤害或0生命值后续豁免仍可能阻断在GM待审，本轮没有新增战斗包放行。诊断改成GM边界不等于可以导入；现有配套能力未能完整承接时继续保留原件与未完成阶段。

保存草稿、批准及读取中文包都按当前来源重新生成事实和呈现计划，并核对事实、模板与译文绑定。文件携带的计划不取得信任；旧策略按原身份读取，旧批准不能转用到新策略。CLI/Web 和 v12 的默认策略保持。手工正文修正只适用于剩余文本槽，不能改只读规则块或 Actor 机械字段；修改来源后必须重新生成。付费 AI 审核继续默认关闭。

本候选须先通过历史失败输入的离线整链，再冻结做六例跨 PDF 单次验收。每例首次失败保留，冻结批次内不修补、不重复生成、不换样本。六例真实生成、中文核对、导入和刷新尚未全部完成前，不能称为跨 PDF 验收通过；这也不构成任意 PDF 成功保证。

后续生成的生物、特性、动作、附赠动作、反应、传奇动作等名称显示为“中文名 English Name”，中英文以空格分隔，例如“麻痹射线 Paralyzing Ray”。已有括号格式的受审中文包继续按原格式读取；名称格式变更须形成新的审核绑定，不能复用旧格式的批准。当前Forge v14的传记、能力和活动描述在同一栏先显示中文，再附对应完整作者原文；程序添加的GM提示与护甲、尺寸备注单独显示，不进入作者原文栏，作者自身写下的中文及同名备注保留。审核预览显示可读文本。来源变化须重新核对批准；旧策略及CLI各自保留原有显示规则，GM步骤用中文。数字、骰式、状态身份、开始／结束、来源／目标与自动化边界不因翻译改变。控制器会重新绑定双语能力名；不能通过翻译增加自动效果。

基础规则词优先参照用户指定的[5E不全书《玩家手册2024》术语速查](https://5echm.kagangtuya.top/topics/%E7%8E%A9%E5%AE%B6%E6%89%8B%E5%86%8C2024/%E6%9C%AF%E8%AF%AD%E6%B1%87%E7%BC%96/%E6%9C%AF%E8%AF%AD%E9%80%9F%E6%9F%A5.htm)，例如 Bloodied 为“浴血”、Grappled 为“受擒”。这是用户指定的中文译法参考，不是发行方官方中文译本，也不将来源机制换成2024规则。项目自定义条件 Enfeebled／Clumsy／Slowed 使用“衰弱／笨拙／减速”。Dazed“恍惚”、Dominated“受支配”的第三方完整定义若尚未核实，继续显示明确GM裁定边界，不自动等同于原生或项目自定义状态。

CLI可对新资料增加 `--language zh-CN`。已有来源包的中文生成入口如下，两个输出目录都必须尚不存在：

```powershell
bun run tools/forge-encounter/translate-package.ts ./source.forge-encounter.json ./chinese-run
bun run tools/forge-encounter/translate-package.ts ./source.forge-encounter.json ./chinese-retry --resume-review ./chinese-run/translation-review.json
```

译文必须通过受保护数字／HTML、中文完整性与术语校验；Forge浏览器由GM实际核对批准，付费模型含义审核仅按按钮调用，CLI保持默认模型审阅。失败不产出可导入的中文包；保存候选译文和诊断，不用英文回退冒充完成。续接只复用同来源与对应文本的候选，优先修正实际缺失或失败条目；译文或术语／名称上下文变化都需重新校验并由GM核对；CLI仍执行自身模型审阅。已有批准只在完整来源、语言、策略、术语内容和译文绑定一致时复用。

包级说明同时对照同包正式来源中的完整能力描述与分区。摘要省略“至多”等限定时，以完整原始规则为准；不能为迎合简写摘要而删掉真实限制。此来源上下文也参与审核身份核对。

正式中文Actor仍通过共享workflow重新生成；不要用旧的目录JSON原地翻译替代这条链。中文包保留原英文来源、原控制配置与受审译文，导入端离线重建中文卡片和固定绑定，再由GM确认导入／明确启用。语言和译文改变包身份，不覆盖此前英文角色。首次只接受固定控制配置的包；任意脚本、不能唯一匹配的能力或超过控制器256字符的双语绑定在准备阶段拒绝。新功能的实际样本及运行接受层级见[首期记录](../../docs/reviews/2026-10-07-forge-translation-terminology.md)。

来源未指定的召唤持续时间、数量上限、召唤者死亡处理等保持 GM 裁决。原生攻击目标、战术选择、未选中的其他能力仍由 GM 正常操作。


## 人类 MD 模板与当前能力范围

可从[人类填写模板](../../docs/examples/召唤生物-人类写法模板.md)开始，按普通 Markdown 写明每种生物的完整数据、能力触发条件、结果和召唤关系。晶血龙兽是验收样例，不是名称匹配的专用分支；AI 根据本次来源提取 Actor 和能力绑定。填写模板不代表任意机制都能自动执行。

当前固定能力支持：豁免结算后无论结果在目标相邻空位召唤一只；自身回合开始对范围内其他生物结算；首次腐化标记/重复失败加力竭；超过阈值减半、碎裂后恢复与耗尽后减熟练加值；来源明确的自身回合传奇资源恢复；表中四种匹配组合的豁免失败效果与期限；GM确认的眼梗禁用／明确恢复。数量、结果、放置、状态、期限或触发方式超出这些形态时，需要扩展能力库或明确保留 GM 操作，不能由 AI 改写为近似规则。AI 不生成执行代码。

使用顺序：在 FVTT 启用本模块，在模块设置配置 Provider/API Key，再从角色目录的 Forge 生物工作台打开战斗包读取 MD，生成并审核，再导入；导入之后单独启用固定控制器。已有包的预览和导入无需再次请求 AI。Actor 蓝图保留来源 HP，未链接 Token 的随机 HP 遵从世界设置。

截至 2026-09-15，本地 14.364/5.3.3 已验证包导入、齐射两分支召唤、晶体回合效果、守护阈值实际伤害与次数耗尽后的削弱。重复腐化只有部分运行证据；用户决定待独立状态设计后再明确，不视为严格单次增量验收通过。原生 Dazed 修复通过离线回归，尚无专门 Chrome 复验；FVTT 页面从 API Key 到完整 AI 生成的全链也未重新实测。CLI 真实 DS 审核与浏览器已生成包验收分开记录。此合并不等于生产部署或所有 MD/能力组合通过验收。

Forge v14 的能力与活动图标采用本地模糊选择，依据完整机制、形态、主题、名称和正文；弱线索使用功能类别图，Activity 可继承父 Item 内容图，不自动输出空图、占位图或目录类型默认图。includeBase 决定是否包含父 Item 基础伤害，不混入兄弟活动。展开结果中的 Icon 报告核对理由、备选与近似程度；素材不可用会失败。此策略仅在 Forge 浏览器会话启用，不改变 CLI/Web 默认图标模式。

中文显示的已知契约：v14 内置状态标题按状态 ID 固定；已知语言名称、大小写及中文别名按锁定 5.3.3 目录映射，未知短语保持。完整公式的乘号 x/×/* 可等价，乘除、顺序、操作数、遗漏或重复变化拒绝；已支持的范围/伤害数值用途和重甲条件肯定/否定在保护器与读回、批准校验中保持。其余自由文本仍按完整原文由 GM 核对，不启用额外付费审核。
