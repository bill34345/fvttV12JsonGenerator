# 运维工具公共规则

## 这层目录是做什么的

`tools/` 保存操作本地运行环境、离线世界副本或经授权外部系统的工具。它不是普通 Actor/Item 转换层，默认权限和验收必须更严格。

## 公共安全规则

- 每个命令必须明确目标、最大影响、owner 和所需授权；生产只读可按下述机械门禁自主执行，但“工具能运行”永远不是执行外部写入的授权。
- 默认 fail-closed：路径、身份、配置、锁或授权缺失时，在建立连接或写入前停止；不以创建备份作为门槛。
- production read、local mutation、offline-world mutation 和 production mutation 必须明确区分。
- 生产修改不能为了方便隐藏在“统一 CLI”或普通测试命令中。
- 凭据来自环境或用户明确指定的本地文件；命令、日志、错误和报告必须脱敏。
- 破坏性操作遵守根级精确目标、失败停止和再次确认门禁；不得创建备份或用副本伪装回滚点。

## 验证与完成标准

- `bun run typecheck:tools`
- 运行目标工具自己的权限、路径、dry-run 和拒绝路径测试。
- 语义验收必须说明实际读取或写入了什么目标；本地 fixture 不能证明生产行为。
- 生产只读记录目标核对、命令门禁和读取范围；生产写入、真实数据迁移和删除另行记录当次授权、核对与剩余风险。

## 用户明确授权的无备份运维规则（2026-08-13）

- 用户明确要求本地和线上任何任务都不创建备份，也不因在线人数而阻止已授权的生产操作。执行时仍须记录精确目标、前后文件清单、SHA-256、进程、端口和日志。
- 该规则不扩大授权：不覆盖未授权目标、Foundry/dnd5e 升级或运行中的 LevelDB 直接编辑；`51020` 仍为只读目标。
- 不得以临时副本、隐藏目录或回滚目录变相创建备份；若操作失败，停止并报告，等待新的明确修复授权。
