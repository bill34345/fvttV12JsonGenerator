# Battlefield effect workflow

每次完成一个效果：辨认参考和规则、制作素材、检查实际画面、接入正式画笔、验证本地行为。只读取当前效果需要的资料。

## 开始与范围

1. 阅读模块 `AGENTS.md`、`docs/CONTINUATION.md` 和当前 `src/catalog.ts`；路径均相对 `foundry-modules/fvtt-battlefield-painter/`。实时核对工作区和 Lab，不把交接快照当作当前状态。
2. 用户指定效果时只做该效果；没有指定时先核对公开目录与现有覆盖，按复用程度、证据完整度和玩法价值提出一个合理目标。常规可逆选择可说明后继续，只有歧义会实质改变玩法、范围或权限时询问。
3. 本项目用户于2026-09-09要求后续逐项开发由代理自审，省去每轮人工美术确认。可以自行选择、迭代和接受候选，沿授权范围继续本地接入；不得把“代理验收”写成“用户已确认”，用户后续反馈可推翻结果。
4. 交接记录是短期状态，根/局部 AGENTS 管权限和工作区，当前 Skill 管操作方法。遵循已存在的发布、生产和运行时长边界；自审不扩大这些权限。不要恢复已取消的画质模式。

## 核对参考，再确定本项目行为

- 公开资料检索遵循项目 AnySearch 路由；有匹配的本地研究时只刷新所需部分。
- 确认效果名称、阶段数和视觉身份，避免把编辑器选中高亮当材质，或把 Force Barrier、Magic Platform 当 Frost。
- 将“资料直接说明”“画面可见”“本项目实现选择”“未知”分开。不能从宣传图推断其 shader、隐藏参数、自动伤害或通行规则。
- 沿用可访问的公开资料；没有付费资源时使用自制原创素材和可核实的行为，不要求用户反复提供其已说明没有的付费包。
- 新效果的阶段和玩法按自身证据决定，不一律套两阶段、两倍移动或发光。超出当前两阶段契约时先评估接口、历史与旧数据兼容，不能悄悄截断原始阶段。

## 制作和自审

按 [验收方法](references/acceptance.md) 完成下列步骤，不在步骤之间例行等待用户。

1. **效果小规格**：记录目标、阶段差异、移动/阻挡/光照、参考来源、可验证的未知项。
2. **素材候选**：从已确认三组中选相近的风格基准；优先让原生 Tile 与灯光完成效果，只有原生方式无法满足具体行为时再引入其他渲染机制。使用当前可用工具，不绑定历史失效入口。
3. **素材检查**：用 `scripts/inspect_asset.py` 检查字节、尺寸和透明通道；查看实际图像与地图叠图，机械结果不代替视觉结论。
4. **静态自审**：按效果性质检查单格、连片、拐角、孔洞与相邻笔画。失败就针对原因修正，不能靠遮住坏边缘或把整层调淡通过验收。
5. **动态自审（需要时）**：在静态形态成立后加动态，查看真实连续画面、亮暗和循环；静态效果无需制造动画。
6. **正式接入与实机**：使用模块正式画笔测试受影响的格型、阶段、擦除、历史、移动/阻挡、Token显示和所有权清除。所需机械命令依模块 AGENTS；只运行与当前修改有关的门禁。
7. **交付**：给出完成项、图片/视频、PASS/FAIL/NOT_EXECUTED及具体限制，更新来源记录和短交接状态。一次交付一个效果，不自动继续耗尽整个目录。

## 速度与失败处理

- 优先复用 catalog profile、scene-plan、原生 Tile/Light/Region/Wall、稳定格位外观及现有测试夹具；避免为一个效果再建一套框架。
- 每轮修正一个明确问题。若同一失败连续出现两次，先改变方法或缩小问题，不重复同样的提示词或参数搜索；已有明确修正依据时继续，否则报告具体缺口。
- 只抽取相近基准和当前最终证据，不重读所有历史报告，不重复已经通过且未受新改动影响的检查。
- 默认由当前代理执行与复核；是否委派遵循项目策略，不为了“自审”例行增加代理。
- 此流程已经做格式、样本脚本和情景走查；首个新增效果仍需按实际结果验证流程效率，不能把流程文件存在称为无人监督效果已证明可靠。
