## 已核实的代码行为

本机精确对象：`F:/FoundryLab/foundry-v14/data/server-mirror/Data/modules/foundry-mcp-bridge/dist/`。

- `main.js:61-78`、`422`：GM 页面的 Foundry ready hook 在 Bridge enabled 时发起连接；非 GM 直接返回。
- `constants.js:24`、`socket-bridge.js:418-437`：底层重连默认最多 5 次；耗尽后该重试路径停止。主模块另有心跳恢复，不能由这个上限断言所有恢复都停止。
- `main.js:286-319`：心跳恢复失败的 catch 分支会把 `autoReconnectEnabled` 设为 false；`settings.js:289-295` 表明它是持久世界设置。这是可能影响恢复的已核实行为，尚无本轮游戏内设置或历史 trace 证明它造成了上述任一具体失败。
- `socket-bridge.js:119-126`：干净关闭不在该回调内安排重连；是否随后由心跳恢复取决于主模块状态。
- GM 页面关闭后，页面内连接与恢复逻辑均无法继续运行；单独修改重试次数不能消除这个运行前提。

## 待判断的本地化与流程建议

以下均为 **Proposed / 尚未实施和运行验收**；不改变项目模块健康矩阵中的既有状态。

1. **先补 ServerNext 的真实连接闭合。** 在当前任务需要 Next 时，确认目标服务身份及共享占用，使用项目现有登录方式进入任务拥有的 GM 页，读回 Bridge 设置，再由正式 foundry-next 工具读取世界和一项既有数据。成功前明确报告未就绪。
2. **把客户端准备纳入本地开发环境准备。** 对实际需要的实例准备各自的专用 GM 页面，保留页面与独立登录地址。避免依赖用户偶尔手动进入世界来维持连接。复用已有服务及任务拥有的页面；共享页面按现有规则协调。
3. **在需要 MCP 的操作前执行一条真实读取。** 返回应核对实例、世界和系统版本；状态区分 Foundry 未启动、GM/Bridge 未连接、身份不匹配和已读取成功。连接失败时阻止依赖 MCP 的操作，不把进程与工具列表显示为就绪。浏览器验收与其他独立路径保留各自证据。
4. **修正恢复策略。** 评估有限快速重试后改为有退避的低频恢复，不因临时失败持久关闭用户的自动重连偏好；显式禁用、身份不匹配与权限拒绝仍应停止相应动作。页面关闭后由客户端准备步骤恢复，不能靠页面内计时器解决。
5. **补齐最少的连接日志。** 按实例保存连接、断开、恢复、最后一次真实读取成功及失败原因；协议成功与业务成功分开。日志不包含凭据、完整世界数据或真实生产目标。先记录自然调用结果，不默认新增定时监控或开机任务。

建议顺序为 1 → 2/3 → 5；第 4 项在获得一条可复现的恢复失败链后实施。目标是使用本地开发环境时减少手工准备，并使失败可以辨认；不是把全部实例无条件常驻。

## 最小反证检查与后续复查

本轮只做状态调查及方案记录。以下是后续实施需要回答的问题，不是已执行的 PASS：

- 先开 GM 页后开 MCP，与先开 MCP 后开 GM 页，均能最终通过正式世界读取。
- 短暂中断本任务拥有的连接后能恢复，自动重连偏好不被意外改写；不停止共享 Foundry 服务做故障注入。
- GM 页关闭时明确报告未连接；重新按客户端准备流程进入后读回正确实例。
- Mirror 与 Next 同时使用仍各自返回正确目标；身份错误继续拒绝，不能切换另一实例完成请求。
- Next 的单独成功不能替代 Mirror，浏览器 Connected 不能替代正式工具实际读取。

新版本候选先比较 GM 客户端依赖、重连上限、持久设置副作用、实例隔离与现有本地补丁，再决定升级或移除补丁；旧 PASS 不推广到新版本。
