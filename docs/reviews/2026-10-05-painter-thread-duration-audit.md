## 主要发现与反证

1. **辅助工具在真实接口处反复返工。** 早期模块集合解构错误、合同哈希字符转抄错、恢复脚本对嵌套设置／目标接口的假设错、移动结果循环引用序列化成字符串，均有对应失败和修复记录。这些不能自动判成画笔业务故障。完整 CI 也遇到预算不足；既有修复保留，不再为本次调查重跑全仓。
2. **授权范围广，但完成出口没有及时分批。** 升级、原版比较和音效重做都获得授权，不能把工作量全部归为擅自扩张。问题在于将这些目标与大范围显示、跨角色输入及收尾串成一条长链；已有 runbook 的“代表覆盖／先往返／冻结出口”没有完整落实。
3. **最后的输入问题是真实障碍，但原因未完全证实。** 自动输入有按下到首次移动约 975 ms 的记录，与 Core 500 ms 长按路径存在可解释关联；当前连接未提供拟使用的快拖入口。真人正常拖动完成，证明该功能案例可用，不证明连接器已修好或长按就是确定根因。请求人工操作前没有讲清对照理由，是沟通缺陷，不是人类操作的强制规则。
4. **收尾先销毁入口、后补完整读回，导致额外一轮。** 最终经过“删除前审计 → 清理 → 补删除后集合审计”三次派发。删原审计宏后才发现 Item 目录显示 166 而实际集合为 180，又创建自删除审计宏补核。补核有必要，但应在清理前计划好完整集合与唯一审计入口自身的读回顺序。
5. **完成措辞与项目完成层级易混淆。** 最终“本轮完成”限定范围是诚实的；旧标题仍带 14.365、接续文件保留多段历史“当前”状态，增加检索负担。现有入口已明确最新段优先，没有依据重启旧合同。不能把尚未提交或主观音色未确认解释成所有技术验收仍待做。

本轮独立反证未发现需要再修改公共工具源码的材料性缺陷。目标 worktree 的旧 HEAD 不等于没有使用新工具；实际绝对路径调用证明已采用。把所有耗时归为模型慢、回调完全失灵、权限要求人工或产品持续出错，均缺少证据。
