# 跑团副屏统一操作台

## 用户确认的范围

用户选择所附的底部五组操作稿，并要求：“默认情况下先攻替换到下一个生物的时候自动取消所有批量选择”，“主要就是超过一行的时候不要换行”。选择条使用可取消标签和 `+N` 完整列表；这属于实现选择，并非用户指定必须使用 Ant Design。

此前已确认：底栏横跨队伍与遭遇，双方每行常驻复选框；勾选决定单体／批量目标，点击名称只查看行旁详情，保留勾选；队伍 PC/NPC 与所有遭遇生物均可使用适用操作；一批操作对应一次撤回，主面板与副屏使用同样交互。

## 实现与身份

生命、状态、资源、遭遇、更多数值五组共用操作规划器。角色写入按 Actor UUID 去重，遭遇写入保留每个 Combatant。未链接 Token 使用自己的 synthetic Actor；同一角色在两栏重复展示时同步选择。独立查看对象不改变操作目标。

选择状态观察当前 Combat、轮次及当前 Combatant，而非只监听本模块“下一回合”按钮。普通生命、状态刷新保留选择与输入。选择条按实际元素宽度收纳标签，数量、清空与撤回保留在同一行。

## 本地真实联动问题

目标为本地 Next，Foundry 14.368／dnd5e 6.0.6。证据不推广到其他版本或生产。

- 稀疏 ActorDelta 会实时继承基础 Actor。先修改模板生命再修改未链接 Token，会令它们在已经变化的生命值上再次计算伤害。Actor 写入改为先 synthetic、后基础 Actor；战败也会写角色状态，因此采用同样先后关系但保留全部 Combatant 命令。
- 同批修改基础 Actor 和 Token 时，撤回的继承检查应比较本批完成后的基础值；基础 Actor 未参与本批时仍检查原继承值。部分恢复后重建剩余检查，保留真正的外改冲突阻断。
- Monk’s Combat Details 14.03 的 `updateCombatant` hook 会在死亡状态与战败标记不一致时调用原生状态 API。先改标记再创建效果会竞争创建固定效果 ID。先完成原生状态／覆盖图标，再更新标记，可以让该 hook 看到匹配状态而跳过重复创建；未修改第三方设置或原型。
- 基础 Actor 新增效果会在未链接 Token 上产生继承视图。撤回只在基础效果确属本批创建、完整来源一致、Delta 没有自身效果条目时认领该投影。未知独立效果仍阻断不可靠的撤回。

接口依据来自已安装的精确 Core、dnd5e 和 Monk’s Combat Details 源码，并有针对这些触发条件的回归。没有将社区经验或其他版本的结果当成本地证明。

## 验证记录

本轮行为和失败原件保留在本任务 `.local/status-alignment-20261028/r27-unified-operations/`。最终范围以该目录的收据和根 `design-qa.md` 为准。工作进行期间不能将代码或局部检查通过写成全部实机完成。

已观察：原生追踪器切换行动后两块面板均清空；七个目标保持单行并收纳至 `+N`，完整列表可取消；修复后的混合角色批量伤害及整次撤回、原生力竭、状态和显示／隐藏通过代表性实机检查。战败7目标全部标记并一次撤回、仅选基础Actor的继承效果撤回均已通过；临时Actor/Scene/Combat/Folder/宏已清理，原场景、战斗与队伍来源已恢复。主副屏最终视觉和帮助读回完成，172项模块测试、模块类型检查、38项手册一致性及本地安装字节核对通过。

## 待判断本地化与后续候选

R28修正补记：用户指出左下角与选定稿不符，撤回R27对该区域的视觉通过判断。临时生命恢复连续按钮/数字框，生命组调整为底栏约四分之一，并按主副屏容器放大底栏字号与控件。20项模板检查、同尺寸截图与独立视觉复核通过；断线后核对构建/安装文件未丢失，并恢复外部Chrome交付页面。R27功能、撤回与清理证据保持有效，当前视觉结论及已知非阻断差异见`design-qa.md`的R28记录。

本轮不引入或本地化外部模块，没有新增候选。Monk’s Combat Details 仅作为现有启用环境的接口约束检查。未来升级这些依赖时应复查其战败 hook、固定状态效果 ID 和 ActorDelta 继承语义，重跑受到变化影响的最小代表用例。


## 底部操作区样式精修

用户随后明确“我只针对下面这一块”。R30仅对底栏执行字体、装饰图标、实心下拉箭头、数字框步进区、五组留白和纸面处理。三个装饰图标提取自用户选定原稿，透明PNG仅用于标题；输入、按钮与文本仍为真实控件。步进按钮只改待填值，命令/输入绑定75项保持，既有批量与撤回证据复用。主副屏实际查看、同尺寸局部对照及待填数值上下调均通过，详见根design-qa.md的R30记录。
