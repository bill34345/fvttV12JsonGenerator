### MIDI 进程所有权查询

本机旧实现局部及覆盖率基线均通过，未复现远端挂起。[一手报告 Open Design #9087](https://github.com/nexu-io/open-design/issues/9087) 记录 Windows Win32_Process 全枚举 54.6 秒，也指出 CommandLine LIKE 仍可能慢；查询过滤不是已证实的通用根治。按 [PowerShell 5.1 官方接口](https://learn.microsoft.com/en-us/powershell/module/cimcmdlets/get-ciminstance?view=powershell-5.1) 改为提供方字面量数据根过滤和三属性投影，同时给 WMI 操作 5 秒、包含 PowerShell 启动的子进程 10 秒预算。超时终止并等候退出，仍明确失败关闭安装，不能因 allowFailure 当成无占用。原测试 15 秒上限保持。

真实进程检查保留并强化为正反斜杠两个 PID，覆盖引号和 WQL 通配符字面量，近似路径不误判，结果实际触发安装拒绝；新增真实挂起进程的超时与 PID 回收检查。局部覆盖率 10 pass，整个 MIDI 模块 97 pass、14 文件、422 次断言；foundry-modules 类型检查通过。本机查询策略对比没有足够证据说明显著提速，远端稳定性待新 CI 验证。

## 第四轮远端：大保存报告的哈希成本

`b16f52c3` 的 [GitHub CI 41055085492](https://github.com/bill34345/fvttV12JsonGenerator/actions/runs/41055085492) 已完成，job 15 分 7 秒；覆盖率清单 8248 pass、83 skip、1 fail、1 error，8332 用例、576 文件、611.94 秒。MIDI 真实进程检测 1103.39ms、超长清单身份回归 589.91ms，均通过。唯一失败为已有大于 32 MiB 的保存报告 CLI 导出用例：外层 30000ms 超时后回收子进程，随后出现 close 无状态错误。没有把状态观察连接的 EOF 当作 CI 失败；原始日志通过 GitHub 连接器取得并冻结。

本机阶段诊断确认报告读取与扫描约 150ms、第一次父报告哈希约 8949ms、恢复生成约 6181ms（含第二次独立报告哈希），写出与收尾各小于 100ms。临时诊断输出已撤回，未把 stderr 诊断导致的局部红色结果冒称本机复现了原始超时。独立 32 MiB JSON 基准：敏感信息扫描约 50ms、纯 JS SHA-256 6.56 秒；同内容的原生 SHA-256 约 15.12ms，摘要完全相同。瓶颈是实际哈希成本，不是已证实的磁盘卡顿。

依据 [Bun 官方 CryptoHasher 接口](https://bun.com/docs/runtime/hashing#bun-cryptohasher) 并在固定 1.3.14 实际执行，最终只将 Bun CLI 入口计算父报告指纹的一次 SHA-256 改为原生实现；恢复核心继续对同一完整报告做原来的纯 JS 独立核验。内容、UTF-8 编码、十六进制摘要、两个身份核验及原 Actor／来源快照均保持，未增加依赖或修改共享哈希接口。独立审查确认 hashSource 原来没有附加规范化，最终替换保持同一完整 JSON 字符串的摘要。

中间共享哈希优化原型虽通过 6 项摘要／VM 检查、large case 1179.58ms，但真实 Forge 构建拒绝了浏览器包内的 Bun 依赖，完整本地检查因此出现两个构建失败并停止，不能记为通过。条件导出原型又触发固定 Bun 的 Windows pretty-path 崩溃，也未采用。全部 contracts 源码、包配置及新增原型文件已撤回，与 b16f52c3 基线一致；这些原始失败日志保留，以上原型结果不用于最终版本接受。

最终大报告用例新增实际输入大小及原保存文件逐字节不变断言。runResume 子进程预算改为 25 秒，为原有 30 秒外层留出失败回收时间；没有提高外层时限、跳过用例或降低覆盖率。公开安全入口下 12 项检查通过：五项真实 CLI、Forge 实际 browser build 与 release、原 Gateway 哈希向量，large case 9358.03ms。工具类型、架构、手册检查通过。复用未变共享代码在 b16f52c3 的完整本地通过结果，最终窄增量仍须取得远端完整门禁结果；不把停止的原型整合冒称完整退出 0。手册相关条目只需核对内部 CLI 哈希优化，参数、转换结果、来源绑定与版本说明均保持。
