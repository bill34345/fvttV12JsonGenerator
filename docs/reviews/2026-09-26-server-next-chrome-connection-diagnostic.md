# ServerNext 浏览器入口故障与恢复方案（2026-09-26）

> **专项证据，不是当前进度表。**本页保留标题日期的来源和检查经过；其中“当前”“未执行”等只属于当时。新对话以[唯一迁移交接报告](../plan/server-next-migration-handoff-20260927.md)为准，仅在核对应证据时读本页。

## 人话结论

这次卡住的是 Codex 独立任务没拿到控制 Chrome 的工具，**不是游戏服务器坏了，也不是两个动作栏或血猎手已被证明有故障**。两个动作栏的正式文件已装并核对，原世界可进入；世界里的开启和血猎手新人物检查仍未执行。

## 已核事实

- 当前桌面应用为 `26.924.20706`，内置检查返回 `up_to_date`；因此不能断言“刚出现了可安装更新”或“某次更新一定造成故障”。
- 本机 `chrome@openai-bundled`、`browser@openai-bundled` 均显示 installed/enabled；Chrome 进程存在，Chrome 的原生连接登记和文件存在。`browser_use`、`browser_use_external` 均为 true。
- 全局配置中的 `js_repl = false` 对应当前 CLI 的 `js_repl removed false`。已有[同类原始故障记录](https://github.com/openai/codex/issues/37036)证实，这一行也可能在 Chrome 正常工作的环境中存在，不能据它擅自修改全局配置或宣称根因。
- 新建的独立任务实际 Full Access，核到 ServerNext 仍为原世界、目标版本和PID24104；但其本轮可用工具里没有 Chrome 操作入口。它没有进入游戏，也没有创建人物。父任务当时同样未得到 Chrome 工具。

## 外部调研与判断

- [OpenAI 官方浏览器扩展说明](https://learn.chatgpt.com/docs/chrome-extension)要求在**新对话**里用 `@Chrome` 选定浏览器。其故障步骤也明确写到，新对话可清除该对话的连接状态；随后才考虑重启浏览器或应用、检查扩展和站点权限。
- [OpenAI/Codex 的 Windows 使用者报告](https://github.com/openai/codex/issues/37313)记录过同一应用内工具在一段对话可见、另一段对话不可调用。另一个[Windows 原始报告](https://github.com/openai/codex/issues/37072)记录插件和扩展已装却没有提供浏览器工具。它们证明类似症状并非本机独有，**不证明本机与其根因相同**。
- [OpenAI/Codex 的项目任务故障记录](https://github.com/openai/codex/issues/37036)在当时用全新不绑定项目的任务恢复了 Chrome，并提醒 `js_repl = false` 不是原因。该记录来自另一系统版本，故只能作为本机一次受控诊断思路。
- 当前最小假设：首次新任务创建时没有随**初始消息**选定 Chrome；后来的跨任务转发文字提及 `@Chrome` 没能给该任务补上浏览器能力。也可能是当前任务工具清单组装故障。尚无证据可判定是新版本缺陷、站点权限或扩展损坏。

## 恢复与停止条件

1. 不改 Chrome、Codex 全局配置或游戏数据，保留当前可进入的 ServerNext。
2. 按官方“新对话起始即选浏览器”的方法，仅再做一次**全新独立、项目外、只读预检**：初始消息包含 `@Chrome`，先核实际 Full Access 与 Chrome 工具是否可调用，再只读列出浏览器标签和确认目标地址。项目外任务只读使用精确工作区和数据目录，不另建代码工作树。
3. 如果该任务真实取得 Chrome 且服务身份一致，再进行两个动作栏的正常界面开启与重载读回，以及血猎手新人物关键行为；如果仍无工具，停止重复建任务，并按官方故障步骤转向本机连接状态/应用重启或反馈。没有实际界面证据前继续标 `NOT_EXECUTED`。

## 本地化与复查

这里没有新的 Foundry 模块本地化候选。浏览器恢复不改变五项模块来源与兼容结论；下一次只复查 Chrome 工具是否实际可调用和两个尚未完成的世界内门禁，不重做已通过的文件安装、旧人物更新或其它玩法测试。

## 本轮后续实测（覆盖上面尚未执行的计划）

- 一次全新**项目外**独立任务在首条消息指定Chrome，实际Full Access，但仍完全没有可调用的Chrome工具；未进入世界、未修改人物。因此“只因旧项目对话状态”这一简单假设被否定，不再重复建任务。
- 本机应用安装目录创建时间为2026-09-26 08:52，Chrome插件新版目录创建于08:56；前一天存在旧版插件。版本变化与本轮故障时间吻合，但因没有同一任务跨版本对照，**只能说可能与今天更新有关，不能判定更新必然造成故障**。
- 再核Chrome原生连接：登记准确指向本机manifest，manifest指向`chrome/latest`，该目录实际链接到26.924.20706且目标程序存在。`node_repl`执行文件存在，CLI列出相应服务；`js_repl`在当前CLI为“removed false”。因此不改此配置、不手工改原生连接，也不拿插件文件存在冒充真正的工具可调用。
- 为避免用户手动介入，主任务采用本机已有Chrome和Playwright驱动**全新临时浏览器窗口**，只走ServerNext正常登录页及游戏界面，不借用现有Chrome资料、不直接修改世界数据库。只读预检确认游戏页、Gamemaster和目标世界/系统版本；随后两个HUD在正常界面从关闭变开启，重新开启全新Chrome窗口后两项`active=true`、版本正确、总启用数72→74。[结果](./2026-09-26-server-next-five-open-modules-recheck.md)。这是本轮任务的实际替代执行方法，**并不表示Codex内置Chrome插件已修好**。
- Blood Hunter新人物验收仍待独立完成；若此方法在某步发生身份、登录、页面状态或规则选择不明，应停在该步，不改玩家人物。

- 随后主任务用上述本机Chrome正常界面完成血猎手专用测试人物的2级五选一、烈焰血仪实际扣血、匕首附魔与火焰伤害，重登后附魔保持；精确临时棋子清除。详见[血猎手最终现场结果](./2026-09-26-blood-hunter-new-character-fighting-style.md)。内置`@Chrome`工具仍未在这两个独立任务里出现；本轮是通过本机已安装Chrome的临时自动化窗口完成，不要求用户再手动连接。
