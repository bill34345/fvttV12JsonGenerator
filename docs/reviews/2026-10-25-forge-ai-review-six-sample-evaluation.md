# Forge 六样本 AI 内容复核评估

> 接续状态：此文件记录当时版本。旧流程测试失败清单已从交接材料清理，不是当前待修项。最新开发、测试和AI复核停用决定以[唯一当前状态](../plans/2026-10-20-forge-ab-current-state.md)为准；原始收据仍保留。

结论：本批没有证明额外复核能成为可靠的质量保障。它漏掉 Behir 已确认的两个基础操作，提出三项与实际表示或已接受的 GM 边界冲突的改动，另指出一项有用但后果被夸大的法术拼写／匹配风险。保留显式可选审核，不默认开启；没有自动采用任何意见、修改候选或请求纠错。这是一次负面评估结果，不是流程验证失败，也不能推广为所有模型或所有生物的结论。

## 授权与实际执行

用户在六个输入、上限及第二阶段条件列明后回复：“同意，第二阶段通过后按此上限评估”。[第二阶段](../acceptance/2026-10-25-forge-review-recovery-flow.md)的本地行为和零模型实机恢复／创建检查通过后，按[批准方案](../plans/2026-10-25-forge-ai-review-evaluation-proposal.md)执行。

- 当前 DeepSeek／deepseek-flash，Responses 协议，reasoning=auto，json_object；生产 review prompt 为 `monster-intake-review-v37-consolidated-full-ir`。
- 真实发送层记录 **6 次复核＋1 次连接探针＝7 次 HTTP POST**，全部 HTTP 200。每项一次，失败也计预算；提取、纠错、自动重试均为 0。探针显式关闭模型列表读取，禁止预算外 GET、改端点及重定向。
- 每次调用使用现有公开 browser-runtime provider／review API。原文、IR、正式生成 Markdown 和 Actor projection 都传入，使用的正是产品审核提示，不为这批样本临时改写。预先冻结的问题标签不提供给模型。
- 候选身份先检查；五份 IR 原样使用，Mage 只走此前已验证的法术目录引用正规化，与历史正式续接结果全等。原输入文件不改。
- 本批没有浏览器／Foundry 写入。六份复核后的 IR、artifact 和 candidateHash 与请求前逐一相等。所有原始结果、包括错误意见均保留。

因此，四条 blocking 意见中三条是误报，一条是后果／修法过强的匹配风险提示；没有独立确认的新必改内容错误。预先设定的最低判断——发现 Behir 两项真实遗漏且不提出无依据的实质改动——未达到。不计算一般准确率、召回率或产品成功率；六份有意选取的输入不构成随机样本。

具体判据及路径保存在 `review-evaluation/independent-adjudication.md`。几个容易误判的实现事实是：

- [施法消费者](../../foundry-modules/monster-spell-resolver/src/cast-activity.ts)支持“全部成分豁免”的完整 casting restriction；只看 group.componentWaivers 会错误地把另一有效表示当遗漏。
- [法术身份匹配](../../src/core/spell-resolution/resolver.ts)区分英文精确身份与显式选择；内部引用键不是必须等同于官方英文拼写的显示名。
- 伊斯人既有 `native-eldritch-magic.json` 中 activity `7fb09ca08044d299` 保留 `refId=plantasmal-killer`，但实际绑定官方 `Compendium.dnd-players-handbook.spells.Item.phbsplPhantasmal`，`native-actor.json`含4环缓存。当前代码可提示近名候选后由GM明确选择；本轮没有重新选择或施放。这是“必定不能解析”的直接反证，不意味着错误英文可以自动精确匹配。
- dnd5e 5.3.3 的 target-field 不默认填 creature；save activity 对当前选择目标掷骰。Behir 历史原生同ID活动也没有该 creature 字段。这里核实表示及选择机制，没有重新进行现场游戏测试。

## 这次结果改变了什么

已修好的草稿／修正流程可以保留，它保证失败不毁候选、预算不丢、成功后由GM决定；这与审核模型能否正确找错是两件事。本次结果否定了“额外请求一次同模型，就足以补上内容质量保障”的做法。没有因此降低基础操作要求，也没有把AI意见重新交给正文正则裁判。

下一步建议，**尚未实施或授权新的模型请求**：先整理审核实际输入，让原文每项基础操作与候选可执行操作可对照，并提供程序已确认的投影／Resolver表示事实与GM范围；缺失来源解释仍由AI判断。当前review prompt没有extract/repair的完整法术及操作表示说明，且审核时没有真实法术匹配选择结果；这为部分误报提供了可检查的解释，但尚不能证明加这些信息就能修好遗漏。应先做零模型输入保真检查，再另列一次固定对照的样本、模型和调用上限。保留本批失败作为对照，另留未参与修改的输入；不反复重跑到满意，也不把新提示版本预先算作成功。

既有[外部AI导入工具研究](2026-10-25-forge-ai-import-validation-reassessment.md)已经核过六个固定源码对象及失败案例，未发现可以直接替换并已证明可靠的完整语义审核器。该研究支持结构检查、保留原件、预览和限次处理的机制选择，不替本次负面结果背书；本轮没有重复外部搜索或复制第三方代码。
