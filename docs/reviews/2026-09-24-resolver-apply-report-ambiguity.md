# Spell Resolver 0.1.2：Review Apply 与报告读回分层（2026-09-24）

ServerNext 独立 Chrome 已把[正式接受的 Rat Warlock Actor JSON](../acceptance/2026-07-18-rat-warlock-spell-resolver.md)导入唯一临时 Actor，并在 Resolver Review 看到10条引用各有一个 `dnd-players-handbook/spells` PHB2024 候选。Eldritch Blast 是这轮唯一人工冲突，Keep 不可选；执行器选择 Overwrite 后 Apply 按钮可用，并[只点击一次](<F:/FoundryLab/foundry-v14/evidence/server-next-migration/resolver012-hydration-apply-20260924/run-outcome.json>)。随后“查看解析报告”显示 `MANUAL_CONFLICT_UNDECIDED` 和空数组决策哈希，Actor 卡片可见一个 Eldritch Blast Spell/Action，未读出10个缓存 Spell/Cast，也未做整页刷新；执行器按边界删除了临时 Actor。

**不能仅据报告把 Apply 判为失败。**源码 `src/review-app.ts` 的 Overwrite radio 经 form `change` 进入 `session.decideManual()`，同一个 Apply 回调再读表单并返回 `manualDecisions`，没有另一个“保存决策”按钮。Foundry14.368 的 `DialogV2` 回调收到真实按钮及其 form。`src/hooks.ts::viewReport()` 却重新调用 `createPreflight(..., true)`，未传手工决策，再把此即时预检覆盖到持久报告上；即时部分自然会生成空决策哈希和未决冲突，即使先前 Apply 成功。`src/transaction.ts` 成功提交时会把 `status:'hydrated'` 与 selections/manualDecision 写入 Actor `spellResolution`。现有浏览器证据没有在打开“查看解析报告”**之前**读回该持久状态和10项缓存，故结果应记为 `APPLY_CLICKED_HYDRATION_NOT_CONFIRMED`，而非已证实的修复失败。

下一轮只在新建且可清理的 Actor 上重复一次正常导入/Review/Apply，**先读 Actor 的原生 `spellResolution.status`、嵌入 Spell/Feature Activity 与数量及重载持久化**，再单独查看报告；不得以报告的即时预检哈希代替提交状态。当前模块的 Actor 操作栏已有 `Export Diagnostic Report`，其 `src/hooks.ts::exportDiagnostics()` 导出运行时 status 和删去 undoSnapshot 的持久 `spellResolution`，可通过普通 UI 下载文件作为 Apply 后、View Report 前的分层证据，再配合 Actor 原生 Export Data 核对实际嵌入项。若 Actor 已 hydrated 但报告仍显示未决，单独修报告的“当前预检/已提交结果”呈现；若 Actor 未提交，再按真实 Apply/事务错误定位。两种结果都不能用测试 fixture 替代正式输出，也不能写入或更新所用付费 PHB compendium；只允许读取候选并操作任务 Actor。

报告呈现的独立修复当时形成**尚未安装**的 Resolver 0.1.4 候选，后续安装与真实复测见下：顶层当前状态复用运行时状态及现有 `isAlreadyApplied` 绑定，历史 `lastCommittedOutcome` 只有在 manifest/plan 与完整唯一引用集合匹配时显示，无决策的即时预检单独保留；不兼容运行环境也显示当前原因。325/325模块测试、类型检查、构建与独立只读复审通过，ZIP SHA-256 `1504F9CCD567FAD95A0499B000B99420592ED99C3EB071609DDD27433D9DB2C1`。[与更新前安装0.1.2的8文件预检](<F:/FoundryLab/foundry-v14/evidence/server-next-migration/combined-resolver014-midi-local9-20260924/resolver-preflight.json>)仅 `module.json` 和 `scripts/index.js` 不同。此修复只使报告不混淆历史和当前状态，**不证明上述浏览器 Apply 已提交，也不替代目标运行复测**。

后续[受控两文件更新与服务读回](<F:/FoundryLab/foundry-v14/evidence/server-next-migration/combined-resolver014-midi-local9-20260924/persistent-verified.json>)已将0.1.4装入ServerNext，GM界面也读到active。新一轮[正式Rat Warlock UI证据](<F:/FoundryLab/foundry-v14/evidence/server-next-migration/resolver014-hydration-e2e-20260924/ui-observation-summary.json>)通过正常Actor Import Data导入来源SHA-256 `A8D9A96CD2BD3B6D9FC05DFF2D2B905FE7AE3DB1406969EA3D3733378AC6A2A1`，Review列出10条唯一PHB2024候选；唯一Eldritch Blast冲突选Overwrite并点击Apply一次。Foundry明确通知 `Spell hydration failed: Document lacks resolver spell ownership.; rollback left residual differences.`；整页重载后Actor的Spells只见一个Eldritch Blast而非10个，水合**真实FAIL**。View Report继续显示无决策即时预检；本次FAIL依据是错误通知与重载读回，**不是**空manualDecisionsHash。
