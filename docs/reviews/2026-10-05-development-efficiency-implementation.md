## 工具的实际使用方式

已有检查命令够用时直接运行，不需要额外 JSON 或合同。只有需要文件侧身份绑定和收据时，才选择下列入口：

```powershell
# 明确的新检查；请求格式沿用原有格式
bun run foundry:ops acceptance run --input="<已有请求的绝对路径>"

# 接续同一合同；有结果时仅校验和读回，没有结果也不盲目重放
bun run foundry:ops acceptance run --contract="<返回的合同绝对路径>"
```

两个参数互斥。普通待执行合同仍先经过现有选择、预检、身份及一次领取保护；外部批次／runtime 请求在新 input 的任何预检执行前拒绝，继续使用专属门禁。普通文件检查的通过仍不等于 Foundry 实机、父审或发布接受。`manual`、空输出及不足的证据保持原有未完成边界。

独立审查发现并要求修正：历史合同身份漂移时不能声称“未执行”，有收据但字节损坏时不能声称“没有收据”。最终入口使用 UNKNOWN／RECEIPT_INVALID 的 INSPECT 状态，明确禁止自动重放；不通过读取任意未验证目录来猜测旧执行状态。

## 验证选择与证据

本批改变公共 CLI 和失败状态，故运行相关验收工具组及类型检查；改变指令与手册，故运行规则生成、分层／链接检查和手册一致性。没有产品运行代码变化，也没有 Foundry 行为待判定，因此不启动游戏、不重跑已完成的业务、不运行无关全仓矩阵。

- 新 CLI 的真实进程用例证明：一次新请求只运行一次预检和操作；同一完成合同再次调用，两个标记的计数不增加，原合同、claim、raw、receipt 和 summary 字节不变。
- 已领取却无回执、失败预检、选择不允许执行、外部范围、身份漂移和损坏证据均走拒绝／检查路径，不能自动重放或误报 PASS。
- 未注册的模块可以用原有文件侧检查形式，不需要新增业务 adapter；manual 原始观察保留独立语义审查。
- 独立指令审查覆盖七种情形：说明修订、导出故障、从未采集的关键数据、无公共 adapter、浏览器明确拒绝、阶段父审及共享接口集成。七项均选择了正确下一步，保留了该保留的结果和门禁。这是指令语义核对，不是长期行为提速测量。

首轮测试误用 PATH 上的 Bun 1.3.8，运行时自身 panic；一次相同版本重试开始后中止。随后从已有只读路径选用 CI 固定的 Bun 1.3.14，并只调整本次子进程 PATH，没有更新全局安装。固定版本下相关工具组 106 项通过；后续错误状态修复只运行受影响的 workflow 文件，详细最终回执在本任务外部证据目录。本次已在工具局部规则补明“每批先核项目锁定运行时，环境不变则复用”，不把 panic 当作业务失败，也不隐瞒这次额外开销。

最终代码去掉组合入口对 `requireReady` 的冗余调用，真正的一次领取前门禁仍由 `executeAcceptance → dispatchPrepared` 执行。最终字节的安全定点检查为 25 PASS／0 FAIL、117 个断言；类型检查、架构依赖／循环检查、34 项规则文件与 Ruler 生成幂等检查、30 项手册一致性及 `git diff --check` 均通过。106 项工具组结果属于最后窄修正前的共同基线，受影响的 workflow 用最终 25 项结果替代，没有把旧通过冒充最终整组重跑。
