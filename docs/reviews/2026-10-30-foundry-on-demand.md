实现分为 MCP 源码中的统一入口、FVTT 仓库中的现有 readiness 配置兼容，以及外部安装与配置切换。旧部署后台保持原样。环境工具采用固定目标前缀，不使用跨聊天共享的当前环境变量。

## 检查范围与理由

- MCP 源码测试：目录发现零环境连接/启动、按调用目标连接、两客户隔离、只读拒绝和共享后台退出语义。这些是本次新增行为。
- 本仓库 readiness 测试：旧配置保持兼容；统一入口配置正确解析；双启用、缺失目标和错后台拒绝。配置替换会使原来的 enabled 检查失效，因此必须覆盖。
- 当前 Codex app-server 的两个临时聊天：检查实际宿主握手/工具目录及按目标调用，补 SDK 测试之外的集成证据。
- 所选现有环境的世界只读读回：证明身份与原后台兼容；它与无后台冷启动测试分开报告。
- 更新对应手册说明并运行既有手册检查。首轮没有提交、合并或推送授权；后续发布授权见末节。

运行证据与部署目标保存在本机任务目录；公共记录不保存私有地址、凭据、聊天 ID 或原始世界资料。

## 实现与交付

- 源码以 upstream v0.8.4 的 `f53b9d3a6a0f8415879bf7e51e9496a9ac73e1cc` 为基础，先恢复已部署的 multi1 补丁，再增加统一入口。此前补丁与本次新增源码保存在独立 MCP 开发目录，未改旧冻结源码。
- 单个 `foundry` MCP 入口读取外部环境清单。初始化与列工具只返回内嵌目录；首次调用固定环境前缀工具时才连接或启动该环境的 MCP 后台。Foundry 服务与 GM 页面仍需原有准备步骤。

- 保留原 backend.bundle.cjs 与按环境共享的后台；统一入口退出只关闭自身连接。已运行后台不会因为这次切换而自动关闭。
- 交付 bundle SHA-256：`4c9b8ae49b966c4a67f716446a79f83ed6183543e7fc81935a1302a2d15721f2`。候选验收和安装后读回使用同一字节内容。
- 主目录与本次开发目录只启用 `mcp_servers.foundry`；旧三条配置保留但禁用。Codex 全局配置的 SHA-256 前后一致，因此本次没有改变输入预测。
- 已安装的独立 `codex-readiness.ts` 也已适配统一配置。主目录尚未合并源码，因此此时日常准备应使用该独立入口，不能把主目录旧版 `bun run foundry:mcp` 当成已经更新。

## 使用与剩余边界

新加载的聊天使用统一入口；已载入的聊天可能仍持有旧工具连接。任务方便中断时正常重载或重启 Codex 后再观察，不批量结束后台进程，也不要求归档聊天。首轮未切换的旧任务目录已按下方追加授权完成切换。

本次证明的是取消聊天初始化时对三个 Foundry 环境的主动连接，以及按真实调用选择目标。没有进行四五个桌面聊天长时间并行的 loading 对照，因此不宣称已根治桌面全部等待问题。手册页面的视觉检查和真实生产世界读回也不由其他通过结果替代。

## 追加授权：所有现有与未来 worktree

用户原话：“明白了，那其他现有 worktree 的 MCP 配置也一起切换成统一入口吧，以后新建的 worktree 也默认用这套按需连接的配置。”

本轮实时清单包含主目录与 11 个 worktree，其中 10 个旧 worktree 尚未切换。逐个配置只禁用原三入口并加入同一统一入口，不修改环境清单或其他设置。

新建 worktree 使用本仓库本机 Git post-checkout 脚本初始化配置。核对发现该脚本固定只提取三个旧入口，因此本轮需把统一入口纳入提取清单。验收使用隔离临时 Git 仓库调用实际安装脚本、实际创建 worktree，检查默认只启用 foundry、包含相同环境清单路径及重复 checkout 保持已有无关设置。MCP 实现和 bundle 未改，复用上轮按需连接与真实世界证据，不重复世界验收。

结果：10 份旧 worktree 配置已切换，另 2 份保持原统一配置；当前 12 个目录均只启用 foundry。逐项解析核对通过，原环境参数、生产只读权限、共享清单与 Codex 全局设置保持不变。新建 worktree 的真实 Git hook 检查通过，重复 checkout 不改已有无关 MCP 设置；`.worktreeinclude` 也包含配置文件。隔离测试仓库保留为本机证据，没有改动本项目提交历史或新建用户聊天。

## 初始化脚本源码与安装入口

用户已授权将 MCP 维护到自己的 fork，并补齐 worktree 初始化源码和安装方法后分别提交、合并和推送。发布由主控统一执行，最终提交身份以 Git 历史与本机发布收据为准。

现有本机 helper 已纳入 `tools/foundry-mcp/worktree_init.py`。新增安装器默认仅检查和输出计划；`--apply` 才安装到当前仓库的 `.git/hooks`。解释器取运行安装器的 Python，不在源码中固定机器路径。已有未知 hook、不同 helper 或自定义 hooksPath 会拒绝，安装动作不修改 MCP 配置或启动服务。

新增检查对应安装器这个写入入口：在随机隔离 Git 仓库中实际安装、创建 worktree 和 checkout，验证默认无写入、统一配置继承、无关配置和 `.worktreeinclude` 保留、重复执行幂等、旧 launcher 迁移、未知 hook/冲突配置/自定义 hooksPath 拒绝。MCP bundle 和世界行为不变，复用此前真实环境验证。
