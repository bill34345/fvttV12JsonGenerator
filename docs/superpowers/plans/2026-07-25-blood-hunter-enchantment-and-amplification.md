# 血猎手猩红仪式与血咒 Activity 改造计划

**目标：** 以 Foundry v14 / dnd5e 5.3.3 / MIDI-QOL 14.0.11 / DAE 14.0.12 为锁定环境，把猩红仪式改为具体血仪上的武器附魔，并把每个血咒拆成普通、增幅和增幅失血流程。

**边界：** 所有 JSON 只通过 Foundry Lab 工作流生成；不修改卡勒姆、世界包、生产服务器或线上合集。复杂血咒缺少可靠上下文时显式提示人工处理，不猜测结果。最终实战验收由用户完成。

## 实现

- `猩红仪式`和`鲜血秘法`本体保持 Activity-free；后者只提供共享次数和等级数据。
- 七种具体血仪各生成一个原生 Enchant Activity、一个隐藏失血 Activity 和对应 enchantment effect；附魔为武器攻击增加正确类型的一枚血法骰，并带短休/长休失效标记。
- 每个血咒各生成普通、增幅、隐藏增幅失血三个 Activity；普通和增幅各消耗一次共享次数，只有增幅通过 MIDI Trigger Activity 调用失血。
- 直接可表达的血咒使用 Activity/DAE；需要动态上下文的效果使用 Activity Macro 提示或受控选择。Activity Macro 不足时才使用 Item Macro。
- 把当前规范锁从 MIDI-QOL 14.0.9 更新为 14.0.11；历史验收报告保留 14.0.9 原始事实，并追加当前边界说明。

## 验证

- 先写失败测试，覆盖父特性无 Activity、七种血仪附魔结构、十三种血咒三段结构、共享次数、触发引用、休息期限、稳定 ID、重复 ID 和无关被动特性。
- 使用本地 dnd5e 5.3.3、MIDI-QOL 14.0.11、DAE 14.0.12 源码核对字段。
- 运行专项测试、Foundry Lab、TypeScript、构建、反过拟合和两次确定性生成比较。
- 对七种血仪和十三种血咒逐项做源码语义审查；仅做一个受限的本地冒烟，不扩大为完整 Chrome/战斗验收。

## 失败关闭

- 增幅失血不得被抗性或临时生命值吸收，也不得重复扣血。若 MIDI 14.0.11 无法可靠保证，生成清晰的掷骰/人工扣血提示，不交付错误的自动扣血。
- 破晓血仪的光照、对不死生物额外伤害以及复杂血咒，只自动化本地锁定源码能可靠证明的部分，其余以命名明确的辅助 Activity 或聊天提示保留。
