# Boss 战提醒首个原生试用版规格

日期 2026-11-23。桌上行为已经与用户核对。实现顺序和测试入口是本地开发草案。

## 问题

GM 推进先攻、处理攻击与豁免时，容易错过怪物只在特定时机可用的能力。漏掉的包括传奇动作、传奇抗力、巢穴动作、死亡能力，以及刚陷入浴血时的即时响应。临时从资料库拖进战斗的怪物也应该能参与这套流程。

## 方案

开发独立 Foundry Mod。首个试用版基于 Foundry Core 14.370 / dnd5e 6.1.1，按 D&D 2024 规则和具体能力原文判断时机。机会出现时，只给 GM 弹出可点选的卡，让 GM 当场决定使用或跳过。使用走原生 dnd5e 的动作与豁免流程。GM 可以照常推进回合，聊天只留实际使用的记录。Midi-QOL 作为可选兼容另验。

## 已确认的用户故事

1. 作为 GM，我希望在玩家或 NPC 的回合结束时看到可用的传奇动作和剩余点数，以便当场选择使用。
2. 作为 GM，我希望同一个回合结束最多有一张传奇动作卡，以便在一轮有多次机会时仍能看清当前时机。
3. 作为 GM，我希望同一时机有多个 Boss 可用传奇动作时，各 Boss 分组显示在同一张卡里，以便逐只处理，使用其中一只后仍可选择其他 Boss。
4. 作为 GM，我希望从提示直接点用原生传奇动作，以便系统按该活动扣点。
5. 作为 GM，我希望怪物豁免失败且仍有传奇抗力时看到私密提醒，以便决定是否使用。
6. 作为 GM，我希望点用传奇抗力时，原失败豁免按系统流程改判且扣一次资源，以便后续按真实结果处理。
7. 作为 GM，我希望只有开启怪物的「在巢穴」设置时才启用该怪的巢穴提醒，以便同一只怪在巢穴外也可正常使用。
8. 作为 GM，我希望巢穴动作默认在先攻 20 提醒，以便即使先攻列表里没人掷出 20，也能在正确位置处理。
9. 作为 GM，我希望先攻 20 的所有角色都走完再提醒巢穴动作，以便同值角色的顺序可预测。
10. 作为 GM，我希望具有死亡能力的参战怪物一掉到 0 HP 就弹卡，包括小怪，以便自己决定是否处理该能力。
11. 作为 GM，我希望一次范围伤害让多只怪物归零时合成一张死亡卡，并按各自的 Token 分别处理，以便仍能区分每只怪的位置与范围。
12. 作为 GM，我希望旧怪物只有正文的死亡能力能列为候选并在备团时确认，以便实战用到它时已经有可靠的触发标记。
13. 作为 GM，我希望怪物从半血以上降到半血或以下且拥有即时浴血响应时才弹卡，以便及时看到应该处理的具体能力。
14. 作为 GM，我希望已进入浴血且继续受伤时保持安静。回复到半血以上再跌入时，则按能力的「首次」或使用次数限制判断是否再次提示。
15. 作为 GM，我希望一次伤害直接从半血以上打到 0 HP 时以死亡卡为主，在同一张卡上看见能力原文明示归零时仍有效的浴血响应。
16. 作为 GM，我希望系统自动识别有原生传奇能力的参战 NPC，并允许我关掉某一只怪的提醒，以便临时加怪也能用。
17. 作为 GM，我希望五类提示都以明显、可点选的弹卡出现，以便聊天刷屏时不会错过。
18. 作为 GM，我希望能点用、跳过或照常推进，过了机会的卡自动收起，以便不卡住桌上的节奏。
19. 作为 GM，我希望聊天只留下实际使用的记录，以便复盘时清楚哪些能力真的发生了。
20. 作为 GM，我希望先在原生测试世界体验完整交互，以便验证日常操作，再进入自动战斗结算的兼容试用。

## 已确认的依赖和后续范围

- 「原生提醒先试试」和「做成一个可选兼容才对」确认了试用顺序与 Midi-QOL 的可选地位。自动结算的兼容验收以后要看伤害、效果与实际豁免结果。
- 浴血首版以进入阈值时的即时响应为对象。更广的阶段转换和换招按真实怪物案例另议。回合首尾被动效果和怪物专属反应已发现实际需求，作为后续候选。
- 给玩家看的按类型全屏或场景特效以后另议。本版卡片只给 GM。

## 实现取向与测试接口草案

- 依照仓库独立模块发布规则组织。先用 Foundry/dnd5e 的回合、HP、原生活动和消息行为验证需求。可复用契约须先核对真实能力，模块私有实现各自维护。
- 第一个测试入口选 GM 实际操作到可读回结果的完整链。观察回合推进、两种账号的画面、实际使用的 Activity、资源变化和卡片收起。从实际操作入口能同时核对权限、时机和执行。
- 本仓库 Trigger Engine 的回合测试与开团面板的原生操作、隐私和撤回测试提供可比较的验证口径。早期先读目标环境的真实事件与资源读回，后续用局部测试覆盖状态边界。若使用开团面板的回合撤回，另验撤回后再次前进只出现当前有效提醒。正式试用还需代表性的本地 GM 和玩家运行验证。
- 公开原版演示证实作者把可用传奇动作和余量放在 GM 需要做决定的时机，并从卡片调用原生动作。本机 dnd5e 与 Midi-QOL 源码另有接入证据。具体新模块在 6.1.1 下的触发、权限与扣点仍待运行验证。 [原版交互演示](https://www.reddit.com/r/FoundryVTT/comments/1y2ugqi/dd5e_boss_effect_reminder_legendary_villain_and/) · [本项目的对照证据](../reviews/2026-11-23-paid-module-design-watch.md#原版依赖与自研接入证据)

## 建议的开发顺序

| 次序 | 可独立验收的桌上行为 | 首个对照样本 |
| --- | --- | --- |
| 1 | 一只 Boss 的传奇动作卡从真实回合结束弹出，GM 点原生动作并消耗资源 | 在 Core 14.370 / dnd5e 6.1.1 的原生世界中，GM 推进一个有资格触发的回合。GM 只收到一张，普通玩家没有该卡。使用后余量只扣一次。另一次选择跳过或继续推进，可继续操作。 |
| 2 | 完成传奇动作的多 Boss 合卡，并接原生传奇抗力 | 在 NPC 回合结束加入两只合资格 Boss，卡内各自处理。实际失败的原生豁免测试使用与跳过，核对同一豁免的改判、资源与聊天记录。 |
| 3 | 接巢穴动作 | 同一只怪切换「在巢穴」状态。分别走有人与无人处在先攻 20 的先攻表，验证同值顺序和一轮的实际触发次数。 |
| 4 | 接死亡能力与即时浴血响应 | 覆盖单次多怪归零、跨半血后的治疗再进入、待确认的旧文本候选，以及一次伤害直接归零的合卡。 |
| 5 | 原生试用整合 | 用一场包含五类场景的本地试用核对自动识别、GM 私密、回合正常推进、重复提示、实用记录和实际生效结果。 |

中文术语沿用会话已定用语，产品本地化按仓库双语约定。整合、安装、实机或发布应按项目现有流程核对实际执行层级。上述顺序用于实施与验收，实测范围见下。

## 本地实现和验收

0.1.0 候选已实现原生路径。用仓库要求的 Bun 1.3.14 构建独立 ZIP，校验安装文件和浏览器脚本哈希，冻结锁安装、模块测试、Foundry 模块类型检查、测试隔离、依赖边界与手册检查通过。真实行为使用 30002 Core 14.370 / dnd5e 6.1.1 的独立测试世界，世界只启用 Boss 战提醒。验收源码留在模块测试夹具中，浏览器和状态读回留在外部验收目录 `2026-11-23-boss-reminders-native`。

| 验收行为 | 已读回的结果 |
| --- | --- |
| 传奇动作 | GM 回合推进后看到两只 Boss 合卡。点用 Tail Swipe 走原生确认和聊天，龙的点数 4→3，巫妖的选择仍在。跳过与继续推进可用。 |
| 传奇抗力 | 实际的原生失败豁免弹卡，点用后消息标为已使用传奇抗力，原生剩余次数 3→2。 |
| 先攻 20 | 校正夹具的先攻身份后，先攻 20 回合结束再弹巢穴选项。点用 Quaking Lair 产生原生巢穴动作记录并关闭该段。 |
| 浴血 | 从 40 扣到 20 时弹出 Bloodied Roar，点用后产生原生记录，治疗到 40 再扣到 20 时首次限定保持。 |
| 死亡 | 同一夹具动作中对两只小怪调用原生伤害并读回 HP 0/0，弹卡合并且只列出各自的死亡 Activity。使用其中一只后，另一只仍可选。 |
| 玩家隔离 | 普通玩家与 GM 同时在线时触发新的失败豁免，GM 收到私密抗力弹卡，玩家只看到原生豁免消息。 |
| 旧正文确认 | 在怪物卡的 Boss 战提醒设置打开旧正文能力候选，选择生命值归零，保存并重开后读回。 |

本轮覆盖五类代表操作与玩家视图。死亡合卡样本是单个测试宏对两个目标顺序调用原生伤害。先攻 20 同值、无 20 和换轮边界有单元检查，实机演示用 25→20→18。连结 Token 来源选择和同怪双豁免并发锁分别有回归检查。Midi-QOL 自动结算、长场次和不同版本仍需各自验证。夹具最初的先攻数据按返回顺序关联，实际读回后只修正测试 NPC 数值，并更新夹具按 Actor ID 绑定。验收结束关闭任务玩家页，保留测试世界与 GM 战斗追踪器，便于用户试用。

### 0.1.1 卡片优化

根据[卡片调研](../reviews/2026-11-23-boss-reminder-card-ui.md)重新排布五类提醒。卡头显示时机和跳过入口，分组显示头像和余量，整行动作附原物品图标与适用的消耗。

同一测试世界的桌面 Chrome 截图覆盖全部五类。传奇两怪同卡，1/2 点成本对齐，长动作名完整换行，键盘有焦点轮廓，默认窗口与右侧战斗栏留有间距。选龙的动作后原生聊天记录生成，额度由 4 点变 3 点，巫妖组仍可选。传奇与巢穴同时出现时，跳过巢穴仅移除该卡。两个已验证的死亡来源仍同卡。截图、状态和版本读回留在外部验收目录 `2026-11-23-boss-reminders-card-ui`。

构建目录、ZIP、安装文件和本机 HTTP 资源哈希相符。服务重新加载包清单后，在原 GM 页面读回注册版本 0.1.1，再次弹出传奇动作与巢穴动作，保留该页面供试用。

### 0.1.2 动作摘要

在活动名下显示原生射程、区域、目标和时长标签，点数位置沿用 0.1.1。测试覆盖同时显示区域与目标、有时长或专注的活动，以及裸活动不显示默认标签。30002 的原生弹卡读回射程 10 英尺、单目标和瞬时，另有球形 20 英尺、影响 2 个目标、持续 1 轮，与活动准备数据一致。没有结构化目标和射程的幽魂步保持单行。验收截图在同一目录的 `16-activity-summary-card.png`。

在专用测试世界启用 5e_chn 6.0.6，GM 客户端语言选该包提供的 `cn` 后，上述内容随系统显示为中文。模块无汉化依赖，未加载对应系统语言时，原生标签可能显示英文。中文卡片截图为 `18-activity-summary-card-cn.png`，保留在 GM 页面供查看。

### 本地试用结项

用户看过 0.1.2 中文实机图后确认：「看着蛮好的，我觉得应该没什么大问题了，我们进行一个收尾吧。」本轮以 0.1.2 作为本地试用交付。结项核对 ZIP、安装目录、本机供浏览器加载的文件、手册和留存证据的版本对应，沿用前述各版本的实机验收记录。

首次试用以 Foundry Core 14.370 和原生 dnd5e 6.1.1 为目标。可选 Midi-QOL 兼容、全屏或场景特效留待后续，长场次和其他平台版本尚无验收记录。源码和构建保留在当前专用 worktree，测试世界保留供试用。Git 集成、发布与生产安装需要对应授权。
