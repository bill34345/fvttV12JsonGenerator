# Forge 内读取 PDF

## 范围

先验证浏览器 PDF 提取，再接入 Forge。生物文字默认保留原语言，复用已有 PDF 样本和保真要求，验收涵盖完整生成链及现有入口的回归。

## 实施顺序与接口

1. 精确锁定浏览器 PDF 引擎，保留页、矩阵、原始 TextItems 和派生行。先用旧真实 PDF 在官方 Chrome 运行提取，核对属性表、跨栏尾句及中文页面。PDF.js TextItems 不是 PDF 原始逐字符 glyph，不把新引擎当成旧 pdfplumber 的同字节输出。
2. 在现有 Forge 来源输入中接入 PDF 文件及目标怪物名。自动得到原语言 Markdown 后继续已有生物生成；MD 是可查看、可下载、可恢复的中间结果。多个变体保留为独立成员。
3. 复用现有连接、模型、默认原语言、显式中文、候选保留及 GM 世界创建流程。PDF 读取默认不启用旧独立 AI audit；同书上下文扩页与格式纠错分别计数，不恢复已关闭的 AI 内容复核。
4. 实际 PDF → 浏览器读取 → AI 整理 → 正式 Actor 的来源对照，以及受影响旧入口、取消、恢复、翻译与发布包检查，通过后提交并合并。

本轮范围为文字型 PDF；扫描型／混合扫描不是旧接受证据覆盖的能力。内部实现随 Forge 分发，不新增需要用户运行的 CLI 或独立服务，不删除其他已有入口。

## 检查选择

- 新提取与布局接口：真实 PDF 探针和测真实实现的 focused tests，覆盖表格、分栏、跨页、空文字／未找到目标、取消及原文保留。
- 新 PDF → MD 模型接收：单次默认请求、同书扩页、格式失败与已有 MD 保留；不请求内容复核，不凭程序补规则。
- Forge 新来源状态：现有页面／恢复测试加 PDF 用例，证明默认原语言、多个变体、普通 MD/TXT、候选不被失败覆盖及无请求的恢复。
- 新第三方资源：精确版本及逐字节本地资源检查、browser build 和 deterministic release；保留许可证与完整 worker/CMap/font 资源。
- 用户入口／说明改变：核对手册条目并生成 HTML；合并前后 handbook:check。包类型、Forge 类型、架构及相关 anti-overfit 按实际改动执行。
- 在 Chrome 中完成 PDF 到 Actor 的真实验收。保留模型回复、调用计数和产物。固定回复用于自动化回归。
