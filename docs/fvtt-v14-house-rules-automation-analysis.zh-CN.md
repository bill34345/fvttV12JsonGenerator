# Foundry VTT v14 村规自动化分析（实施版）

> 目标运行时：Foundry VTT `14.364`、dnd5e `5.3.3`。
> 实施总账：[`docs/remediation/2026-08-07-fvtt-v14-house-rules/EXECPLAN.md`](remediation/2026-08-07-fvtt-v14-house-rules/EXECPLAN.md)。
> 本文说明“为什么做、做到哪里”；实际完成状态与证据只认 EXECPLAN。

## 结论

本项目交付两个互不依赖、可单独安装的模块：

| 发布单元 | 内容 | 自动化边界 |
|---|---|---|
| `fvtt-injury-fading-spirits` | 伤势、死亡豁免扩展、消逝的灵魂复活仪式 | 长期状态由活动 GM 单写；死亡、灵魂意愿和环境例外必须由 GM 确认 |
| `fvtt-house-rules` | N1/N20、药水、魔法弹药、隐匿助手、升级生命骰、低属性提醒 | 能确定的计算自动完成；目标、后果和未知第三方公式由 GM 预览确认 |

以下内容不开发：RP 质量判断、临时裁定/查规则、强制位移、英雄激励、VSM、敌人夹角斜走、休息是否失败、环境碰撞和 DM 风格判断。GM 可以比模块更快、更准确地处理这些临场事项。

### 语言与本地化边界

两个模块都通过 Foundry VTT 核心的 `game.i18n` 读取当前世界语言，并声明 `en`、Foundry 中文包使用的 `cn`，以及标准 `zh-CN` 语言别名；模块不自行读取操作系统语言，也不根据 dnd5e 版本猜测语言。Foundry v14 在非英文语言下会自动加载英文翻译作为 fallback。因此：

- 世界核心语言为 `cn`（Foundry 中文包界面显示为“中文”）或 `zh-CN` 时，设置名/提示、首次设置、伤势与消逝的灵魂复活模式、GM 对话框和村规卡片显示中文。
- 世界核心语言为 `en` 时显示英文。
- 切换语言后需重新加载世界；已经打开的 Dialog 不会自动重绘。
- 当前矩阵世界已确认核心语言为 Foundry 中文包的 `cn`，不是模块单独假定的 `zh-CN`；模块 manifest 同时声明 `cn` 别名后即可正确加载中文包。伤势模块还修复了 `IFS.Fading.Result` 与 `IFS.Fading.Result.*` 的 Foundry dotted-key 前缀冲突，否则整份语言文件会被丢弃并回退为原始 key。硬编码的复活模式/伤势裁定文本已迁移到语言包。

## 原生能力与新增能力

| 村规 | Foundry/dnd5e 5.3.3 已有能力 | 本项目新增 |
|---|---|---|
| 暗投 | 原生 `blindroll` | 无；秘密骰值不复制到模块 flags |
| N1/N20 | 原生攻击、重击和自然骰结果 | N1 的 GM 后果卡；N20 在武器攻击或攻击检定法术的完整原生重击骰池中，让第一伤害部分的首颗骰按满值结算 |
| 药水 | Item Activity、动作类型、治疗 Roll | 三种治疗药水 Activity 配置与可恢复快照 |
| 弹药 | 选择、消费、武器/弹药魔法加值叠加 | 单发降级账本与 GM 找回卡 |
| 升级生命骰 | HP Advancement、投骰/平均值 | 赌博锁定与首次 1 只重投一次 |
| 死亡豁免 | 原生失败/成功、自然 20 回 1 HP | 伤势起始失败、保留裸骰 19–20 大成功 |
| 休息 | 原生短休/长休完成流程 | 只把“成功休息”作为伤势清除入口；不判断休息是否失败 |
| Roll Request | 原生玩家检定请求和 `flags.dnd5e.requestResult` | 复活仪式向导复用请求并由 GM 最终确认 |

第三方现状只作为决策背景，不构成依赖：`Custom D&D 5e` 能覆盖部分计数器/生命骰需求，但模块体量和范围过大；`DND5E Scriptlets` 的弹药脚本未验证到 v14；`D&D5e Death Token Effects` 只做视觉提示。两个新模块均保持自包含。

## 自动化分级

- 自动：纯计算、结构明确、可幂等处理的事件，例如伤势 episode、弹药单发降级、生命骰首次 1 重投。
- GM 辅助：会伤害角色、选择目标或产生永久状态的事件，例如 N1 后果、三层伤势、复活仪式。
- 仅提醒：没有统一机械定义的规则，例如属性 4 或以下的表现。
- 不处理：需要理解 RP、环境、剧情和临场意图的事项。

## 模块一：伤势与消逝的灵魂

### 伤势状态机

Actor flags 是权威状态，状态图标只是投影。一次倒地 episode 的边界是：

```text
正 HP -> 0 HP：开启 episode，并按现有伤势设置起始死亡失败
0 HP -> 仍为 0 HP：稳定，不叠伤势
0 HP -> 正 HP：同一 episode 首次恢复叠 1 层并关闭 episode
复活事务 -> 正 HP：抑制叠层
真实治疗增加且到达满 HP / 成功休息：清零
```

层数不按等级封顶。0–2 层再次倒地时，将原生死亡豁免失败设置为层数；3 层及以上先暂停并要求 GM 选择直接死亡、环境例外或暂缓，决定前不得写入三次失败或 Dead。

死亡豁免只看最终保留的裸 d20 面值。19 或 20 都按大成功处理；优势/劣势中被舍弃的骰子和加值不参与这个判断。

### 消逝的灵魂

历史永久保存在死者 Actor flags 中，至少区分：成功回归次数、快速失败永久 DC 惩罚、常规复活锁、最终机会使用状态、当前死亡 episode 的快速复活锁和不含秘密骰值的尝试摘要。成功回归事实会标记为当前死亡 episode 已消费，拒绝同一死亡重复复活；普通仪式、快速复活和奇迹在最终骰或写入前都使用 Actor 上的持久进行中锁，锁的事务 ID 由 Actor UUID、死亡 episode、模式和持久尝试序号组成。为避免 flags 的读写竞态，活动 GM 还先创建一个使用稳定 Foundry `_id` 的 GM whisper 锁消息；服务端唯一 ID 创建失败时不写 Actor，完成或失权时再按 token 清理/交接。

普通仪式最多三名不同参与者。GM 选择参与 Actor、能力/技能、DC 与优势状态；玩家通过 dnd5e 原生 Roll Request 投骰，GM 最终确认贡献成败。最终 DC 为：

```text
10 + 成功回归次数 + 永久 DC 惩罚 - 3 × 成功贡献 + 失败贡献
```

最终无调整 d20 使用原生 Blind GM Roll。原始值只留在原生 blind ChatMessage；模块 flags、公开消息和审计摘要不得复制它。骰子成功且灵魂愿意才回归；灵魂拒绝记为 `declined`，不触发常规失败锁。

快速复活失败增加永久 DC 惩罚，并使本次死亡只能转入长仪式；普通最终检定失败锁定常规复活。9 环/神祇奇迹在未锁定时直接成功，在已锁定时只允许一次最终仪式。

## 模块二：本团村规

### N1/N20

N1 只生成 GM 后果卡，不在 GM 确认前扣血、反击或损坏武器。近战、远程和法术攻击按 dnd5e Activity action type 分类；PC/NPC 使用同一入口。模块自己生成的伤害按世界设置乘 `0.5` 或 `1`，默认 `0.5`，不猜角色等级或 NPC CR。

武器损坏默认每次 `-1` 命中和伤害，可累积并由 GM 修复。反击只投所选敌方近战 Activity 的伤害，不投命中、不消耗反应。未知来源或第三方结构不明时失败关闭。

N20 适用于武器攻击和进行攻击检定的法术，不适用于只有豁免的法术。模块先让 dnd5e 生成并保留完整原生重击骰池，再只把第一伤害部分的首颗骰拆成带 Foundry `minX` 的真实骰：`1d8` 重击为 `1d8min8 + 1d8`，`2d6` 重击为 `1d6min6 + 3d6`。首颗骰的原始骰面仍可见，但计入总伤时最低为满值；其他骰、其他 damage part、附魔、偷袭与法术 rider 保持原生重击处理。来源或骰子结构不唯一时失败关闭。

### 药水

只处理结构化 Potion consumable，并由 GM 显式标记治疗药水。配置器预览三种原生 Activity：附赠动作自饮正常投、动作自饮最大化治疗骰、动作喂他人正常投。其他药水只保留动作。原 Activity 快照可恢复；Compendium 不直接改写。

### 弹药

模块只处理显式 tier。原生消费成功后，把射出的单发写入 Actor 持久账本：`+3→+2`、`+2→+1`、`+1→+0`。剩余物品堆不降级。战斗结束仅生成 GM 找回卡；点击确认后才合并或创建降级弹药。账本不依赖 Combat，重复事件和重复找回必须幂等。

### 隐匿助手

隐匿成功后由玩家/GM 显式进入状态。战斗内追踪本回合移动并只警告超额，不回滚 Token：普通角色半速、隐匿专精减 10 尺、游荡者总等级 7+ 或 GM override 不减速。Dash 按钮或显式标签立即破隐；传送/GM 调整可忽略下一次移动。非战斗只展示建议速度。

### 升级生命骰和低属性

第一级继续使用原生最大生命骰。首次选择投骰后，以 Actor + Class + Level 锁定赌博，禁用平均值；首次结果为 1 时只重投一次，第二次必须接受，并写回原生 Advancement。

属性值不高于世界阈值（默认 4）时，只在选中 Token 的上下文中醒目提醒；GM 面板可调用 `lowAbility.reminder(actor)` 获取结果。模块不自动改 Actor，也不扫描全世界 NPC，不承诺额外的角色卡 hook。

## 共同安全边界

- 只有确定性的活动 GM 写入长期 flags；无活动 GM 时排队或提示。
- 玩家/socket 数据不可信，GM 重新核对 UUID、权限、Item/Activity、ChatMessage 和事件 ID。
- 所有持久事件使用稳定 transaction ID 和有界去重记录；复活 resolve 前还必须重新读取 Actor，确认活动 GM、当前 pending/进行中锁和当前死亡 episode 仍匹配。
- schema 未知、目标不唯一、原生数据无法核验或 MIDI 版本不符时停止自动写入。
- 两模块不导入彼此私有实现；复活抑制只通过第一模块公开 API 或显式 Activity 标签。
- ChatMessage 不是长期事实来源；聊天清理不影响伤势、复活历史或弹药账本。
- 安装和真实回放只允许本地 `F:\FoundryLab\foundry-v14`；生产环境不在本任务授权范围。

## 完成标准

机械层必须通过两个模块自身 test/build/typecheck、manifest/ZIP 一致性、根 `typecheck:foundry-modules`、`agents:check`、`test` 和 `ci:verify`。

语义层分两类环境：干净隔离、模块独立/共同启用、MIDI-QOL 14.0.11 + DAE 14.0.12、单 GM/双 GM/无活动 GM/GM 切换等组合与故障场景使用 `fvtt-v14-module-matrix`；需要现成角色卡、场景、物品、合集以及原生/Tidy 实际操作流的手动验收和玩法语义 E2E，默认使用同一 `server-mirror` 数据目录中的持久世界 `cor-cotn`（“溟渊的呼唤”）。必须人工检查 flags、死亡失败、隐私、库存、Activity 和浏览器控制台；修改持久文档前记录原值，结束后恢复，并清除本轮临时对象。

本地通过不等于生产部署或真实跑团长期验收；最终报告必须分开说明。
