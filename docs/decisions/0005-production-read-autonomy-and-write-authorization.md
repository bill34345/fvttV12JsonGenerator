# ADR-0005：生产只读自主执行与生产写入再授权

- 状态：Accepted
- 日期：2026-08-10
- 决策人：项目用户
- 修订：ADR-0002 中生产授权的读取部分

## 背景

Foundry Ops 已把生产读取与生产写入分成不同权限类别，并为远程读取保留目标身份、显式执行开关和外部配置。逐次询问生产 inventory/acquire 并未增加新的机械保护，却会阻断正常审计；相反，安装、重启、world hydration、迁移和 LevelDB 操作会改变真实服务或数据，需要明确的人类决定。

本地 `F:\FoundryLab\foundry-v14\data\server-mirror` 是共享测试环境，不是生产。它可以承担短时安装与 E2E，但在多参与者同时工作时仍需保护当前使用者和持久世界内容。

## 决策

- 生产 inventory、acquire 及其他只读操作无需逐次对话授权。它们仍必须经过现有 CLI 的目标身份核对、`--apply`、`--allow-production-read` 与外部 `FVTT_OPS_PRODUCTION_*` 配置；缺一项即在连接前失败关闭。
- 生产安装、重启、world hydration、迁移、LevelDB 或任何其他写入必须在第一项写入前再次取得明确授权。生产只读许可不能推导出写入许可。
- 配置后的本地 `server-mirror` 可自主做身份预检、启停、安装和短时测试。操作前核对 PID、端口、路径和运行者；被其他参与者占用时等待或协调，不擅自停止，也不复制另一套完整 Lab。
- 需要持久内容的语义验收默认使用 `cor-cotn`，并记录/恢复既有文档改动；隔离、污染性、迁移或故障注入测试使用 `fvtt-v14-module-matrix` 或随机临时沙箱。
- 被 Git 忽略的本机私有远程 handoff 只保留历史操作证据。未来授权以本 ADR 和 tracked runbook 为准，私有文件不得削弱这些边界。

## 后果

- 只读生产审计可以直接执行并记录目标、读取范围和结果，不再把“等待用户再次许可”作为默认状态。
- 从只读流程转入任何写入流程时必须形成明显停止点；工具分类、日志和最终报告要分开陈述两者。
- 本地 Lab 的机械/运行时证据、生产部署证据和长时真实会话证据仍是互不替代的验收层级。
- ADR-0002 的运维产品边界、外部凭据配置和 backup-first 原则保持有效；只有读取授权方式被本 ADR 修订。
