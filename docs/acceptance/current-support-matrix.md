# Current Support Matrix

**Current as of:** 2026-07-17
**Canonical role:** this file is the current support summary. Dated reports remain immutable evidence snapshots; later amendments clarify their present interpretation without erasing earlier failures or narrower passes.

## Status vocabulary

- **Pass:** the named layer has current mechanical and semantic evidence for the bounded scope stated in that row.
- **Partial:** some named workflows pass, but material behavior in the same layer is unaccepted or failing.
- **Fail:** a required behavior was reproduced as failing.
- **Blocked external:** safe completion needs user authorization, credentials, a valid protected package, or another user-controlled state change.
- A Pass at one layer never upgrades a deeper layer. JSON schema validity does not prove Foundry runtime behavior; sampled copied-world usability does not prove complete module coexistence; local evidence does not prove production deployment.

## Safe resume boundaries

### Local Foundry Item transfers

The Shield import/behavior/export proof is complete. Future unattended transfers must follow the [no-dialog runbook](../runbooks/foundry-json-transfer-without-file-dialog.md): use Foundry's public `importFromJSON()` and `exportToJSON()` methods, transfer JSON text rather than a filesystem path, capture the exact export Blob before native download, restore temporary page instrumentation in `finally`, compare source-relevant semantics, and clean/stop/restore. Do not write LevelDB directly and do not touch production.

### Authenticated GoddessFantasy crawl

The 2026-07-16 authorized run is accepted. Future authenticated reruns still require explicit authorization for the then-current session. Keep secrets out of arguments, tracked files, logs, and reports. Prefer in-place browser-session use or an ignored cookie-header file / `GODDESSFANTASY_COOKIE` environment variable. The CLI credential route remains:

```powershell

```

Do not add `--skip-auth-probe`; the authenticated board probe is part of acceptance. Every rerun must review provenance plus representative `records.json` -> plaintext -> CLI Actor semantics and must not reuse the old authorization for a materially different session or board.

### Historical module-snapshot boundary

The 88-module figure belongs only to the 2026-07-11 production inventory snapshot. The later cleanup record verifies a 79-module local `server-mirror` baseline and separately records selected 2026-07-12 production changes; it does not record a post-cleanup production active count. A future production compatibility audit must begin with a fresh read-only inventory and an explicitly agreed intended set. It must not resurrect the old 88-ID snapshot or require the protected MCDM package unless that fresh inventory and user scope actually include it.
