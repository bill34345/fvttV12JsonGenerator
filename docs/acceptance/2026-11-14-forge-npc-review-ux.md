# Forge NPC 角色卡审核与部署记录

2026-11-14 在本地 Chrome 使用 Foundry Core 14.370 和 dnd5e 6.0.6 的开发构建验收。候选页沿用 Foundry NPC 角色卡的布局。原始问题和设计依据见[调研](../reviews/2026-11-14-forge-candidate-review-ux.md)。

## 首屏差异优先迭代

用户反馈“首屏想看到更多角色和差异”，并明确“没问题的其实不重要，重要的是有问题的”。保留先前的 NPC 角色卡作为查看详情的方式。新首屏按角色列出可定位的差异；不能直接定位的检查提示提供单独入口。展开前，所有角色卡都各占一行。手册同步更新。

| 验收项 | 本地 30001 Chrome 结果 |
| --- | --- |
| 双角色导入文件 | 从正常文件入口预览。无差异的矿坑斥候先出现在文件中，但顶部差异区只有矿坑守卫，直接显示“经验值 · 原文 600 · 导入后 450”。两张角色卡均折叠。 |
| 直接定位 | 在差异链接按回车，矿坑守卫卡和经验值详情自动展开，焦点在差异处；矿坑斥候保持折叠。看到了原文“经验值: 600”、Foundry 按挑战等级计算的原因、按原文结算需手动分配的处理方法。 |
| 真实 PDF 噬智怪 | 重开原保存候选。无可定位数值差异时只显示折叠的角色行和“查看其他检查提示”。链接可打开提示，展开角色后可看到 450 XP。 |
| 导入和更多 | 双角色候选的 JSON 留在折叠的「更多」。确认区约 51 CSS px 高；勾选后启用导入，取消勾选后禁用，未实际创建 Actor。 |

本轮 Chrome 使用开发环境的验收构建。测试覆盖差异列表、键盘跳转和确认区，实际创建、完整窄窗及全部能力差异类型未做验收。本地候选页相关检查 309 项通过。

开发构建同时包含此前的 PDF 配图功能。从主角色卡进入 Token 编辑器，选择第 3 页插图、调整缩放并采用成功。这条验收覆盖开发构建中的配图入口。
