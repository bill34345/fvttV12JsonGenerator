- 用户明确预算：**每份、每条路径各首次一轮，最多一次纠错**。每个实际 HTTP 单独计数。没有额外付费评审或翻译。

- 旧 CLI 没有原生纠错入口：本批一次纠错由任务提交原回复和实际来源差异，回复仍走原读取器及正式生成。这是额外人工辅助，不等同于 Forge 自动纠错。

### 巨蝎

Forge 保留全部六属性、基础数据及三能力；Claw 使用通用 `1d20+5` 辅助检定和 `1d6+3` 钝击，Sting 为 `1d8+3` 穿刺加 `2d10` 毒素。原文没有武器/法术分类，未猜分类。Claw 的“大型或更小、两只钳子之一、逃脱DC13”和两爪一次尾刺的多重攻击全部保留GM，没有捏造初始力量豁免或自动擒抱。

旧 CLI 首答把逃脱DC13写成命中后的力量豁免，还明确写为武器攻击。唯一纠错移除了多余豁免及明确武器分类，但生成器对普通 `attack` 仍默认投影成武器攻击。剩余错误属于程序默认值，不能把“纠错回复不再写mwak”误报成最终 Actor 已正确。两份 Actor 与原回复均保留。

### 狂热邪教徒

Forge 首次能力回复 JSON 无法读取，唯一自动格式纠错后正式链和23项来源检查通过。保留 Medium or Small 两种体型，当前原生体型 medium；感知豁免+4、欺瞒+3、游说+3、宗教+2、通用语、圣徽与皮甲均保留。Pact Blade 是中立辅助攻击+4、5尺、`1d8+2`挥砍加`2d6`暗蚀。

主施法表的 Light、Thaumaturgy、Command每日2次、Hold Person每日1次有真实 manifest，WIS/DC12/攻击+4，没有免材料。**独立 Spiritual Weapon（灵体武器）本次仍是完整GM规则、附赠动作和每日2次计数，没有 native Cast，也不声称召唤或攻击已经自动化。** 后续有必要补连接时应据原文证明继承，不能手动补法术冒充本批产物。

旧 CLI 首答漏了上述豁免、三个技能、语言与装备；双体型原回复没有漏，但旧读取器输出非法原生体型值“中型或小型”。纠错后补回数据，却使用原读取器不认识的顶层“装备”，转换退出1，没有正式 Actor。不能删掉装备或 Small 刷通过。

### 成年黄铜龙

Forge 六项阻断经保存回复的**零网络、只读诊断**准确复现，不把所有阻断都归给模型：

1. 传奇抗性回复保留每天3次、巢穴4次；恢复方式的同义表达被程序的限定字符串格式拒绝，并非丢了次数。
2. 多重攻击的“可替换一次为施法”被通用单法术识别当成独立施法能力，继而要求填写施法表。它原本是完整GM替换规则。
3. **已更正：Rend目标数量1符合2024默认规则。** 官方SRD5.2.1第256页Attack Notation规定一次攻击默认针对一个目标，除非条目另述。先前将其称为“真实无来源事实、AI错误”是错误归因；程序未应用通用默认值，构成误拦。原回复和当时needs_review状态保持，不通过重跑改成成功。
4. 原文及回复都是魅力施法。程序读取整个 Spellcasting 时，把后面 Shapechange 的形态限制带到父施法属性判断，使属性变成未确认。原声明单独读取能正确识别 `using\nCharisma`，证据不支持把换行当根因。
5. Blazing Light 引用 Spellcasting 施放 Scorching Ray，原文没有升环注记；专用引用规则只接受带等级注记的形式，通用识别又要求独立施法属性，造成边界不一致。不能凭猜测补等级，应完整保留GM规则直至引用关系被证明支持。
6. 灼热沙尘的成功结果写“无伤害、速度不减半”，伤害倍率0。程序仅看到“减半”就当成半伤，与0冲突；这是否定句与速度/伤害归属被误读。

自动纠错要求所有并列诊断都在可纠错名单内，第三项 `V2_TARGET_UNPROVEN` 不在名单，整批因此没有自动纠错。正常 UI 无可继续的 IR，也没有单次续纠按钮。本批保持0纠错、无正式包、未导入；没有改用重生成或旁路请求。剩余额度不能冒充已有产品续纠入口。

旧 CLI 首答漏先攻+10、两项豁免、四个技能、火焰免疫、通用语/龙语、巢穴经验及传奇恢复前言；正式转换退出2，没有 Actor。原 warning 位于 Fire Breath 和 Spellcasting 的豁免语义，需要审阅，不能根据无产物推断最终模板宽度或资源数。唯一纠错补回多项内容，但用不认识的“免疫”字段，转换退出1。原始失败保留。
