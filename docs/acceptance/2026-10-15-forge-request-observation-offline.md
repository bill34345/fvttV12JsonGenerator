## 改了什么

- **默认继续等同一个请求。** 普通 Forge Actor 与战斗包生物 provider 的默认调用不再沿用阶段总时限；显式工作台等待策略优先，人工继续/结束保持。普通 Forge Actor/生物 provider 每阶段最多一次请求，网络失败、HTTP 错误或内容无效不隐式重发。调用方明确传入的请求上限和取消信号仍有效；本轮没有删除所有请求的超时能力，也没有改变 CLI、Item、Species 或显式本地桥接包装各自原有的重试策略。
- **接收过程有观察记录。** 普通 JSON 回复逐段接收后才完整解析，能记录响应头、首次/最后收到数据、字节数、开头空白数据段及接收结束时间。空白提示只说明收到连接活动，不认定已经开始推理。沿用现有 Responses 流式协议的终止验证，同时补齐接收计数；没有给 DeepSeek 额外启用新的流式生成协议。
- **中止原因分开。** 明确的等待上限、主动取消、接通失败、回复中断、服务端表示未完成和无效 JSON 分别记录。旧计时器补充明确的超时原因，合并信号保留原原因，避免把内部超时误标为人工取消。
- **卡片与报告可核对。** 工作台活动卡显示接通和接收情况，安全观察信息写入现有元数据报告；不包含密钥、地址、原始回复或推理正文。等候选择仍在打开时，原请求先完成也能正常返回。
- **缺完整答案继续阻断。** 只有收到完整结束并解析成功才能返回内容。空白、半份 JSON、传输中断和服务端长度限制都不能算成功；即使半途文字碰巧是合法 JSON，服务端表示没有完成时仍拒绝。

上次五分钟强制中止来自冻结的单次验收脚本：其外层 `AbortSignal.timeout(300000)` 和五周期后停止的策略仍作为失败原件保留，**旧脚本不能再作为新验收入口**。本轮修复正式入口的默认等待、次数约束和观察记录，没有把旧失败改写成通过，也没有仅把 300 秒改成 600 秒。
