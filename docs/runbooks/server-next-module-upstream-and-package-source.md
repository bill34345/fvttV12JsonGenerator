# ServerNext：上游核查、候选修复与验收方法

唯一当前状态、用户优先级、服务快照及下一步在[迁移当前清单](../plan/server-next-migration-handoff-20260927.md)。本页只规定工作方法，不保存另一份模块进度、PID或错误数。专题review是有日期的来源证据。

## 1. 一次查清官方情况

每项记录精确模块ID、版本、查询时间和原始链接，并依次检查：

1. 最新正式release及固定tag；读取完整正文，不能只看标题/摘要。
2. 正式下载manifest与ZIP内manifest；源码tag的版本字段可能不同，不能替代发行资产。
3. 源码与构建产物的实际目标路径；“静态发现风险”不写成“客户端已复现”。
4. 官方open及closed issue/PR、相关评论和公开维护分支/提交。记录查了哪些，没找到只表示公开查询无命中；不能断言作者私下没有处理或本机没有worktree。
5. Foundry与dnd5e的各自支持依据；模块自己的版本号无需变成6.x。只有Foundry支持、不写system上限、Foundry包页动态显示系统最新版，都不能替代D&D支持证据。
6. 若没有明确支持声明，检查受影响源码并形成可验证候选；不要把“未声明”升级成“已证实不兼容”，也不要在用户允许评估本地适配时无限暂缓。

用户来源与上游版本分开记录。免费包用官方公开资源；付费37项依用户限定只记录，不搜私人下载位置、不下载/更新/改开关。Plutonium CN由用户官方渠道跟进，按当前清单暂停。

## 2. 选择正式包还是本地候选

- 官方正式版已有等价修复并覆盖目标：采用正式包，核依赖/文件/开关/重登与新增错误；不额外全量玩法E2E。
- 官方ZIP缺件或构建身份错误：先复核tag源码与构建流程。需要本地修复时固定上游tag/hash、保留许可、记录最小diff和单独本地版本；不得改一个兼容字段或悄悄修ZIP后仍称官方原包。
- 作者开发分支可参考，不冒充正式发布；公开PR已经解决的差异优先复用，避免重复实现。
- 自有/本地修改只测试受影响入口。已有通过证据仅在相关变化、失败或具体缺口时重验。
- 已持有的本地内容包可以评估自用数据迁移。无公开下载URL不等于技术上不能迁移；内容再分发另行处理，不把本地迁移和公开发布混为一谈。只处理manifest声明的合集，不自动把磁盘旁边未注册文件夹全部激活。
- 内容包用目标系统的正常迁移/文档更新流程，记录原始语义与差异。批量迁移不等于内容都正确；需核Actor/Item数量与ID、攻击活动、伤害、资源、法术、效果和图片/跨包依赖。禁止直接改运行中世界数据库。

## 3. 派Chrome前完成准备

主任务先完成精确候选和依赖、离线检查、可重复初始化及重载恢复工具、相关测试、目标服务身份及本批操作名单。不要将调试工具本身的准备工作堆给执行器。

每个有关联的候选批次复用一个独立Luna/max执行器，完整契约使用固定绝对路径。至少写入：dispatchId、父/子UUID、目标端口/data/world/system、候选文件hash、初始化入口、精确操作与断言、证据路径、保留/清理对象、失败时读回与服务处理。继承已有授权，不重新询问普通可逆步骤。

取消30分钟总时限；不为时间拆成多轮重复登录。单步设置合理超时，无新证据不重复同一个失败。Chrome仍遵守chrome-delegation-dev和实际浏览器能力/安全边界。

## 4. 派发与回传

- 派发首行使用[chrome-delegation:dispatch]；执行器不递归委派。实际权限核查遵循技能。
- 成功派发后只继续必要且不依赖结果的已授权工作；只剩等待就结束父轮。最多一次宿主要求的即时状态检查，不轮询、不读日志监控、不建watcher。
- 执行器压缩恢复后先读当前契约及stage，不从旧批次摘要重新运行。旧批次完成后指针必须标completed且不留“仍待四张图”等活动描述。
- 先保存回执，再用原生send_message_to_thread发送[chrome-delegation:callback]给精确父UUID，核收件人及成功结果，然后final。内部/root消息、单独写报告、final都不等于回传。
- 回执带dispatchId/候选hash、每项PASS/FAIL/NOT_EXECUTED、数据/API/UI证据区分、实际错误、清理及服务状态；失败同样及时回传。不将“正在做”反复回报。
- 父任务收到匹配回执可同轮继续，不使用旧跨轮锁。回调路由改动或真实错投后，先做一次无服务往返验证，不把正常批次变成持续心跳。

## 5. 父任务如何结案

1. 核本批身份、候选和断言，不能仅采信执行器PASS字样。
2. UI要求核真实图像、前景窗口与对应Actor/Item ID；文件名不是证明。API结果不冒充UI证据。
3. 差异只允许已证明的字段；例如系统自动内部ID必须限定到精确叶子，GM创建权限按正常流程记录，不整类忽略flags/permissions/effects。
4. 写入异常先通过正常文档读回确认已写范围，处理失效文档缓存后再决定补写；不把客户端异常当成服务器没写入而整批重放。
5. 新引入错误当批处理；原有雅灵/Pixi等错误按用户顺序另排，不以旧错要求本批先修全世界，也不因旧错掩盖新增错误。
6. 复用已有证明，修复后只重跑相关检查；状态唯一更新当前清单对应行，不新建总报告、不追加第二个当前结论。

## 6. 现场与权限

操作前核实际进程、监听地址、dataPath、world、版本及占用人；PID不是长期配置。Mirror被使用时只读，不重启、不改开关。Next包维护先经正常Setup关闭世界、核锁释放；不强清锁、不复制备份、不直接编辑运行中LevelDB。测试fixture与玩家内容明确分开；保留对象见唯一清单。没有提交/合并/推送或对外发issue的额外授权。
