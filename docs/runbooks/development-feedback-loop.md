# 开发反馈闭环

状态：2026-09-30 获用户授权，作为独立规范增量纳入 master。既有 worktree 需自行吸收该提交；历史审计记录不代表共用工具已实现或提速已测得。

目标：更早得到能区分错误原因的真实反馈，减少重复准备、错误修复和证据转抄。简单、边界清楚的小修改继续用简短说明；完整合同只用于新外部接口、跨模块/版本/客户端、迁移或已经重复失败的工作。

## 1. 开工：目标清楚再改，技术未知先查

先用不超过一屏说清：要改变的行为、保留的行为、验收出口、候选工作树/环境，以及会影响方案的歧义。

- 用户意图、功能归属、完成层级或写入授权存在两个会改变结果的解释：提出具体选项，先问清再做依赖它的操作；可继续只读调查。说明歧义将改变什么，不把问题变成让用户替代理设计实现。
- 路径、版本、API或报错可以从项目/运行记录查到：先调查，不要求用户重复提供。
- 不影响语义和授权的可逆细节：自行决定，必要时简记假设。
- “借鉴开源”不能自动解释成依赖外部模块完成产品功能；“做完”不能自动解释成允许合并/生产发布。已有明确授权继续有效。

## 2. 陌生接口：研究要转成约束

先读精确版本的相关实现/同类真实项目；已有固定来源可复用，不为每个小改重新上网。用户明确要求调查的方向须执行，或以实际检索结果说明为何不适用。

记录只需四项：来源/版本/许可；与本次问题相关的一条接口事实；本项目采用/不采用的差异；能推翻当前假设的最小检查。列链接或“已阅读”不算完成。

对新hook、异步注册、持久化、权限或跨模块状态，先获得一条窄的真实边界记录或精确版本契约检查，再扩展规则和界面。测试的外部替身应依据记录校准，不能用自己想象的调用顺序作为唯一判定标准。

找不到可借鉴实现时：写明检索范围与无匹配结论；从最小状态转移和两个竞争解释开始，用可区分它们的实验获取事实。不得用“没有上游”作为无限试错的理由。

## 3. 失败：先分层，再选择下一动作

| 层级 | 例子 | 下一动作 |
| --- | --- | --- |
| 工具/运输 | 宏语法错、显示空JSON、字段转抄错 | 修工具并做最低往返检查，不重打战斗 |
| 环境/前置 | 玩家不拥有Token、错level/版本/场景 | 验证真实前置，修准确归属的测试准备 |
| 外部协议 | hook顺序、message type、同步/异步注册误判 | 精确源码/事件trace/最小复现，更新契约fixture |
| 产品行为 | 同一次合法伤害后没生成效果、物品字段丢失 | 保留真实失败输入，目标回归先红后绿，再复验受影响链 |
| 判定/证据 | 已有正确事实，classifier要求不存在字段 | 分开行为结论与证据完整性，核原件，修判定器；不伪写PASS |
| 授权 | 当前写目标超出已授范围 | 准备具体结果与目标，向用户问缺失授权 |

同一失败指纹连续两次尝试没有新证据时，停止原路重试。下一步必须带来新信息：缩小复现、换能区分假设的探针、重新读相关版本实现或请求独立反驳。若缺的是产品决策，问用户；若缺的是技术事实，继续调查。这个检查点不是项目总时长上限。

## 4. 先使执行工具可用，再派发

复杂E2E/迁移派发前核对：

1. 合同及源码绝对路径存在，worktree/branch与目标匹配；不要让执行者从master猜路径。
2. 依赖检查的exit code和结构化结果都通过，之后才派发；检查失败不能因同一脚本下一条命令成功而被忽略。
3. 新工具有最小输入→调用→显示/导出→保存→解析的往返证明；纯语法检查只证明语法。
4. 父任务核实其可见的宿主能力并准备好文件；执行器建立后，在它自己的当前上下文核对有效权限、实际工具入口、模型/effort与目标，再做依赖操作。父宿主可用不等于执行器可用，未知项不凭prompt声明代替。
5. callback含准确父线程UUID、dispatchId、contractRevision和receiptId；子代理通道、独立thread通道和浏览器页所有权是不同概念。发送成功、正确父线程实收、父审接受分别留证，不能用一个布尔值代替。

环境基线记录精确dataPath、端口/PID、世界、Core/system、检查时点及当前共用情况。OS owner或旧快照不等于其他任务已释放服务；维护操作沿用已核实授权及协调记录，不新增逐次确认要求。

独立Chrome仍按已授权技能/宿主路径执行。markHandoff表示保留页面，不表示跨thread转移所有权。不要用裸CDP或替代通道绕过工具拒绝。只读来源检索不需要浏览器任务。

派发后只做已有目标必需且独立的工作；没有独立工作就结束父回合，等待结果事件。callback去重；不轮询、监控日志或制造工作维持活跃。有新失败证据可修正合同；旧合同的错误门禁应明确撤回，不能让执行者反复撞它。

## 5. 验收：分层，复用，保持判定独立

以下层级按任务选择，不是每个模块都跑一遍。沿用本项目已明确的迁移口径：官方明确支持且未本地修改的包只做包/依赖/启用/重登新增错误检查；本地修复增加受影响的关键行为验证。用户后来明确改变验收范围时更新当前合同。

- 纯规则：输入/状态转移/幂等和边界。
- 真实契约：固定版本的schema/hook/message及真实依赖的窄桥接。
- 实际运行API：持久化、角色权限、事件时序和最终数据。
- 少量UI：用户入口、窗口/选项、目标选择、拖放、实际应用动作与角色差异。
- 整合：共享依赖/兼容组合/产物/手册，在集成边界执行。

同类型组合优先下沉；只复验变化影响、失败或具体缺口。完整UI不代替低层测试，模拟测试也不代替真实边界。真实Actor/效果操作必须走产品正式入口，直接写期望结果不能充当验证。

行为结果、证据状态、清理结果分开记录。自动分类不适用时保留原始标签，写清独立审查依据；不得因为看到PASS而跳过被测交互或图片内容。截图文件存在不证明截图正确。

## 6. 共用工具与每个模块的边界

复用当前Foundry Ops、WMP harness、构建身份和收据能力。共用部分只做环境/权限前检、run/fixture生命周期、trace关联、结构化导出、状态恢复与精确清理；每个模块提供小型case adapter和独立语义判定。worktree只保存本次身份与状态，不各造一套测试框架。

在第二个真实消费者验证复用之前，不建通用DSL/调度服务/大型测试平台。测试工具本身按代码对待：失败退出、陈旧收据拒绝、显示/文件往返、销毁归属有对应检查。

## 7. 状态和继承

一个任务有一个当前状态源；历史是只读证据。当前状态至少含目标、实际路径/环境、唯一case、已接受证据、当前失败层级、下一动作与授权来源。可从工具生成的ID/版本/哈希不再让模型手填。

新thread先读当前状态并校验身份；旧STOP/已取消门禁必须带superseded状态。产品使用说明不嵌入每次测试进度；文档与运行代码指纹分开设计。相关产物/环境未变是复用证据的充分条件之一；有据可审查的影响分析也可以说明旧结果仍适用，并列明需复验的受影响路径。身份检查防止混用构建，不代替语义影响判断；未知影响不擅自免测。

规范/可复用工具改动尽量作为可独立审查的小增量集成。commit/合并/push仍遵既有明确授权；未合并的worktree规则不宣称全项目生效。全局skill或memory不在本次候选中修改。
