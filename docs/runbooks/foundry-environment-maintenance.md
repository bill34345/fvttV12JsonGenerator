# Foundry 环境维护与源码归属

## 源码归属

| 工作 | 保存位置 |
| --- | --- |
| 自研模块、通用 Foundry Ops、MCP 准备与跨模块联调工具 | 本项目共享 `master`。配置从所选环境读取。 |
| 直接修改第三方 Foundry、dnd5e 或模块源码的补丁及其构建和专用测试 | 同级 `foundry-compat-patches`，按对应上游版本维护。主项目负责选择实例、安装、读回和联调。 |

| 具体实例的路径、安装清单、版本快照、现场验收和生产交接 | 操作者的私用维护分支和资料目录。使用该环境实际核对过的运维入口。 |

## 环境身份

- `development` 是端口 30001 的开发环境。历史数据目录名 `server-mirror` 仍可能出现在开发配置里，实际角色以实例配置为准。
- `server-mirror` 是端口 30004 的线上对照环境。MCP 使用其显式安装路径和只读配置。
- `next` 是端口 30002 的兼容环境。按所选任务和现场版本使用。

操作前核对 PID、端口、实际应用和数据路径，以及现有使用者。旧资料里的 `mirror` 或 `production-mirror` 标签用于追溯。用 [MCP 准备步骤](foundry-mcp-readiness.md)核对当前环境。涉及包安装或升级时，使用为目标实例验过的本机维护入口，并遵守本项目的授权边界。

## 自研 Mod 的版本准入

Core 和 dnd5e 在模块支持的主版本内接受达到最低要求的版本。依赖模块检查最低版本、启用状态及实际使用的 API。单独记录验证过的环境和行为，保留历史证据适用范围。系统版本开发按 [版本跟随流程](dnd5e-version-following.md)执行。
