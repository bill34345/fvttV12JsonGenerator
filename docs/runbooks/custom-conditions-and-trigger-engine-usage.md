# Custom Conditions 与 Trigger Engine 使用说明

十九种通用状态仍对应 Foundry14.364 / dnd5e5.3.3。2026-10-02 候选把独立的分层伤势迁入 Custom Conditions，并为伤势路径加入 ServerNext14.368 / dnd5e6.0.5 精确版本门；这不开放 6.0.5 的十九种通用规则，也不把旧接受推广到新所有者。迁移目标与验收出口见[伤势所有权计划](../plans/2026-10-02-injury-condition-ownership.md)。

基础发布边界见[候选收尾表](../reviews/2026-09-21-custom-conditions-release-readiness.md)；状态文案的来源边界见[规则核对](../reviews/2026-09-23-drakkenheim-condition-wording.md)，全 19 项的 ID、点击路径与 CoTN 页面复验见[入口审计](../reviews/2026-09-24-all-custom-condition-hud-audit.md)。历史全 19 项入口可见通过，不代表逐项施加、结算或本轮新组合已复验。

## 启用与打开

本地候选包位于 `foundry-modules/fvtt-trigger-engine/dist/fvtt-trigger-engine.zip` 和 `foundry-modules/fvtt-custom-conditions/dist/fvtt-custom-conditions.zip`。目前没有公开发布manifest地址；这些是本worktree的本地交付物。安装到其他实例前应核对版本兼容性与目标授权，不能直接覆盖正在使用的模块目录。

安装两个独立模块，在世界的模块管理中启用 Trigger Engine 和 Custom Conditions，按提示重载页面。Custom Conditions依赖Trigger Engine；核心功能不要求Midi-QOL、DAE、Times Up或Effect Macro。

以GM选中或标记目标Token，从模块设置菜单或Token控制栏打开“管理自定义状态”。存在标记目标时优先使用标记目标，否则使用选中的Token。改变目标后点击刷新，确认面板显示的Actor名称再操作。

## 配置新状态并连接 Forge

1. 在“管理自定义状态”点击“配置组合状态”，或在Forge战斗包页点击“配置自定义状态”。新建定义不要求选中Actor。
2. 填写“中文 English”显示名称和说明；英文、中文原文名称分别一行一个，使用怪物资料中的准确称呼。名称不能与原生/内置状态或另一已保存定义冲突。
3. 添加机制：已有十九种自定义规则及其参数、十四种普通原生状态、固定尺数移动减速均可选择和组合。参数表单会显示必填骰式、伤害类型或DC，不要求手写JSON/宏。保存后定义留在当前世界。
4. 回到Forge刷新状态目录、读取怪物MD/TXT。原文须给出命中、目标、状态名称、持续时间、回合末再次豁免属性/DC和成功解除；Forge按这些完整依据选择定义。核对预览中的名称、机制和生命周期后导入并启用控制器。
5. 正常攻击和推进回合。新名称/参数/机制组合可重复使用，无需逐状态修改Mod代码；未实现的新机制仍需补一次通用执行能力。

管理器也可把已保存组合直接施加到目标Actor，并按来源停用/解除。应用时保存定义快照；目录编辑或删除不会改写已有实例。Forge已生效的旧实例仍可重载、到期和再次豁免，新应用遇到定义指纹变化会提示重新生成并审核。手工停用/删除组合主效果会同步处理其子效果，独立原生后果如昏迷产生的倒地按系统规则保留。不同来源的移动减速按原生ADD规则叠加；流血/灼烧仅结算最高值，保留各来源文档。目录是当前世界数据，安装到另一世界时需先配置对应状态，不能把包内快照当成自动创建世界规则的授权。

## 手动状态和参数

名称和悬停规则说明跟随 Foundry 的核心界面语言：`cn` / `zh-CN` 为中文，`en` 或没有对应翻译的语言回退英文。改语言后重载世界。系统与模块没有两套彼此独立的语言选择。十九种自定义实例各使用一张选定的 Game-icons.net 原始 SVG，作者、作品、来源和 CC BY 3.0 许可见模块包内 `CREDITS.md`。笨拙使用 Drop Weapon，踉跄使用 Foot Trip。Token Action HUD 的完整提示使用 dnd5e 规则卡布局：左侧双语标题、右侧状态类别和分段正文；状态图标只留在 HUD 按钮，不放大到提示框内。仅名称和无提示模式仍按 TAH 设置生效。**所有 19 个自定义状态**使用 `fvtt-custom-conditions.<语义 ID>` 的独立状态 ID；dnd5e 原生与其他模组的裸 ID 按钮保留其原有规则。CoTN 中系统原生 `bleeding` 的中文按钮是「失血」，本模块自定义 `fvtt-custom-conditions.bleeding` 是「流血」；原生 `burning` 为「燃烧」，自定义 `fvtt-custom-conditions.burning` 为「灼烧」。自定义 Dazed 标题只显示「恍惚」或 Dazed，不显示辨识用后缀，仍与 MCDM 的裸 `dazed` 分立。不能把原生按钮当作已配置自定义骰式的实例。

伤势由 Custom Conditions 自身管理。在模块设置打开“启用伤势自动化”，按需打开“管理 NPC 伤势”；新世界两项默认关闭，升级沿用旧伤势模块已有意图。在管理器的伤势区域查看或调整 0–3 层，不要求安装复活模块。Token HUD 左键增加、右键减少；状态标签显示层数。伤势采用此前选定的 Game-icons Bandaged 原 SVG，作者、来源和许可见 Custom Conditions 包内的 `CREDITS.md`。

HP 归零开启倒地 episode；第一次恢复正 HP 增加一层，恢复满血或成功短休／长休清除。死亡豁免只认保留的自然 d20 面值：19／20 清零成功与失败并恢复 1 HP，修正值和被丢弃的骰不算。第三层倒地先由 GM 裁定直接死亡、环境例外或稍后处理，不提前写入死亡。

升级时，新伤势写入 `flags.fvtt-custom-conditions.injury`；旧伤势原件及复活历史保留。复活模块后续只写自己的 `fadingSpirits` 状态。未知 schema、重复投影或相互矛盾的数据会停止自动迁移并提示，不能靠重新点按钮绕过。仍写伤势的旧复活模块与新 Custom Conditions 同时启用时，伤势自动化拒绝运行，须使用配套的新版本。

可选的“消逝的灵魂”继续提供独立复活，兼容模块 ID 为 `fvtt-injury-fading-spirits`。启用后，伤势区域提供复活仪式入口；没有它也能管理伤势，没有 Custom Conditions 也能使用其独立复活。成功复活经公开接口抑制相应 HP 恢复计层，实际 HP 由法术或 Activity 处理。两模块的 UI、HP、休息、自然19／20与重载联合行为仍按本轮候选单独接受。

选择状态，在参数JSON框中填写该状态的参数，再施加。切换到另一种状态时应按新状态填写参数，不要沿用上一种状态的无关字段。没有参数的状态使用 `{}`。

| 状态 | 最小参数示例 |
| --- | --- |
| 自定义流血（内部 ID `bleeding`） | `{"formula":"2d6"}` |
| 灼烧（内部 ID `burning`） | `{"formula":"2d6","damageType":"fire"}` |
| Frozen | `{"escapeDC":15}` |
| Jinxed | `{"formula":"1d6"}` |
| Valor | `{"formula":"1d4"}` |

Token Action HUD 中已生效的 Jinxed、Valor 实例显示其骰子面数，例如 `1d6` 显示 `6`、`1d4` 显示 `4`。这是骰式标识，不是掷骰结果；复合骰式显示紧凑式，过长时角标截短，完整式可在状态管理器查看。

冻结与震愕的说明直接展开其所附状态的效果，阅读时不用再翻查「定身／无防备／恍惚」。冻结使速度为 0、不能受益于速度加值，飞行中会坠落；针对目标的攻击检定有优势。其特殊重击条件限于**使用造成钝击伤害的武器**命中冻结目标，不是任意钝击法术或普通徒手打击。天生武器只有被具体规则认定为武器且在 Foundry 中可被活动数据识别时，才能指望自动判定覆盖。本模块的自定义「恍惚」在自己的回合可从**自主移动、执行动作、执行附赠动作**中选择一种；选择后不能再做另外两种。震愕继承这条恍惚规则，另使针对目标的攻击检定有优势，并让目标掉落手中物品，拿取、拔出或收起物品各需 1 个动作。因此震愕目标若已选择移动或附赠动作，本回合不能再拿取／拔出／收起物品。两种状态都不额外禁止反应；「震愕」也不表示只由闪电伤害造成。攻击掷骰进入求值时，会在本客户端临时锁住所选类别；若掷骰异常失败而没有完成 Hook，本回合保守地继续限制，下一回合自动重置。跨客户端同时操作同一 Actor、两个独立非攻击活动弹窗交错完成仍需单独验收。这一三选一是本项目按用户决定采用的自定义规则，见[规则变更记录](../reviews/2026-09-24-dazed-three-choice-rule.md)。

英勇在攻击检定或豁免检定时额外掷实例骰式并**加**到结果；厄运使用相同结构但**减**去骰值。虚弱使武器攻击或法术造成的伤害总值减半，结果向下取整；若聊天卡仍显示含小数的伤害表达式，以目标 HP 实际应用的整数为准。踉跄在自己的回合最多完成一次武器或徒手攻击；这比目前可公开核对的 Drakkenheim Beta「武器攻击」文字范围更广，是本项目的明确选择。正式版 Appendix C 的条件原文尚未逐条公开核对，不把这里的措辞称作正式中文版原文。

在已选 Token 的 Token Action HUD 中，鼠标离开时动作区可能隐藏；打开「效应」组。active GM 对单个明确 Actor 点击自定义流血、灼烧、冻结、厄运或英勇，会打开**绑定该 Actor 且预选所点状态**的管理器，点击本身不施加效果；先填写流血/灼烧的骰式、灼烧伤害类型、冻结解除 DC、厄运/英勇骰式等必填参数，再提交。其余 14 项经 Custom Conditions API 切换带本模块 flag 的实例，不能通过系统默认状态开关来代替。目标不明确、无 active GM 权限或同状态有多个实例时，以提示和管理器核对为准，不退回系统默认切换。仅由冻结/震愕的复合效果提供的子状态会显示生效；点击子状态不会暗中再建一个独立实例，应到管理器处理实际来源。旧版带本模块 flag 的实例仍按原存储读取并点亮自定义 HUD 项，原生流血/燃烧不会点亮本模块项目。

2026-09-23 的 CoTN [现场核查](../reviews/2026-09-23-cotn-burning-hud.md)只看到原生燃烧按钮；2026-09-24 的[灼烧入口验收记录](../reviews/2026-09-24-custom-burning-hud.md)只确认当时「燃烧／灼烧」并列。此后的[全 19 项 CoTN 复验](../reviews/2026-09-24-all-custom-condition-hud-audit.md)已确认 19 个自定义按钮均可见、无重复，且点击自定义「流血」打开绑定 Actor 的空参数表单；其余按钮的逐项点击与结算未在这一轮执行。Token Action HUD 保存的个人布局按 action ID 匹配；本轮现有布局显示正常，但旧布局中的隐藏与排序偏好未证明会自动迁移，若个别入口未出现，应先检查该用户的「状态」组布局，不要清空他人的偏好。

Bleeding默认在自身回合结束时失去生命值，恢复生命值后解除；Burning默认回合结束造成指定类型伤害。来源明确指定回合开始时，可在参数中加入 `"timing":"turnStart"`。结束说明只是说明文字，不会把任意自然语言自动变成触发规则。

Bleeding与Burning在同Actor上各自只保留一项较高值，按骰式期望值比较，平手保留原值。Burning不同伤害类型仍一起比较。它们不是多层相加，也不按每次随机掷骰结果临时决定强弱。

编辑：面板中点击已有实例的编辑，修改参数后保存。停用会保留实例信息但暂停作用；移除则解除实例。来源栏用于记录“这个状态从哪个能力或物品来”，不需要普通使用者手写技术地址。

Frozen实例的“破冰（动作）”按钮会进行力量（运动）检定。默认目标自救；标记被冻结目标并另选一名协助者时，可由协助者检定。GM先判断其是否能接触目标。取消不耗Action，完成失败耗Action但状态保留，成功则解除。

## 怪物生成与模板

来源必须明确给出状态参数，例如Frozen的DC、Jinxed的骰式。使用正式生成器输出Actor JSON，再通过Foundry的Import Data导入。攻击Item中的Condition效果是可施加模板，不应让持有该Item的怪物自己中状态。

模板应用使用模块公开的 `applyFromItem` 流程，将来源参数复制到目标Actor实例。已有自动化可以调用此接口；仅导入Item并不等同于每次命中都已自动完成目标选择和规则裁定。当前管理器用于直接施加/管理状态，不能把API验证描述为已经提供所有“一键命中套用”的UI。

不要手工修补最终生成JSON来补来源没写的DC或骰式。来源缺参数时先补充来源，或由GM在Foundry中手动决定实例参数。

## 通用触发器

从模块设置或Token控制栏打开Trigger Manager。当前编辑器接受JSON定义，支持Actor文档更新、Combat回合开始、Combat回合结束。可以新建、复制、编辑、启停和删除Trigger，并选择已有Macro UUID作为动作。

伤势的生命值事件通过 Custom Conditions 对 Trigger Engine 的公开订阅接收，无须另建一个调用旧伤势私有实现的 Macro。系统休息和死亡豁免由 Custom Conditions 接收原生事件。外部武器事件继续使用独立的 `publishExternal`／`subscribeExternal` 接口；既有武器专精支持仍限定 5.3.3，不因本轮 6.0.5 伤势路径扩大。

Trigger只由active GM执行。宏收到 `triggerContext`，可读取变更前后数据、Actor及回合信息。宏要回写同一Actor时，使用 `triggerContext.updateDocument()` 保留防递归信息。

无需为了更改现有触发条件或状态骰式重新编译模块；但首次编写全新Macro行为仍需要脚本。不要把“可在FVTT中配置”理解为“所有新规则都无需编写任何逻辑”。

## 移动与使用边界

Immobilized/Frozen限制拖拽、键盘，以及非GM通过HUD/配置进行的自主位置修改。GM坐标编辑、API位置操作保留用于强制位移/裁定，不计为Dazed的自主移动选择。键盘输入路径的当前验收缺口见候选收尾表。

飞行坠落落点、地图距离、环境解除由GM判断。原生Bloodied继续使用dnd5e/FVTT；Madness和Contamination不在本期范围。

## 本地测试环境

server-mirror入口为 `http://127.0.0.1:30001/join`。真实组合验收使用 `cor-cotn`「溟渊的呼唤」，保留世界原有启用模组；历史隔离 E2E 使用 `fvtt-v14-module-matrix`，不能替代 CoTN 的组合证据。该服务按用户要求常驻到关机，测试任务只复用；清理仅限自己的临时对象和receiver，不停止Foundry。

结束测试后恢复原场景、暂停状态。CoTN 当前用户要求保留 Trigger Engine 和 Custom Conditions 启用供手动查看，不恢复历史隔离测试中关闭 Custom Conditions 的配置。serverNext30002是独立环境，不自动安装或更新。
